## 1. Postfix → smtp-adapter policy delegation

Postfix's [SMTP access policy delegation](http://www.postfix.org/SMTPD_POLICY_README.html) over TCP (`check_policy_service { inet:${SMTP_ADAPTER_HOST}:10040, timeout=10s, default_action=DEFER_IF_PERMIT 4.3.5 …, policy_context=<context> }`). **IMPLEMENTED in step 2.2** ([design D4, D6, D11](../plan/steps/04-smtp-gateway.md)). Every listener passes its own `policy_context`; an unknown or missing context is `DEFER_IF_PERMIT 4.3.5` (a misconfiguration never opens anything).

| Context             | Listener                                | Checks at `RCPT` (first non-pass wins)                                                                                                                                                                                                                                                                                                                                                                                       |
| ------------------- | --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `inbound`           | `postfix` 25 (also at `END-OF-MESSAGE`) | recipient domain active + `inbound_enabled` (`REJECT 5.7.1 Relay access denied`), per-client-IP and per-tenant recipient rates (`DEFER_IF_PERMIT 4.7.1`), recipient validation (`REJECT 5.1.1` only in authoritative allow-list mode), declared size vs tenant limit (`REJECT 5.3.4`); at end of data the recorded per-instance size limit                                                                                   |
| `submission`        | `postfix-outbound` 587                  | SASL connector active (`REJECT 5.7.1 Relay access denied`), sender domain of the connector's organization and outbound-enabled (`REJECT 5.7.1 Sender address not authorized`), active DKIM key when `SMTP_OUTBOUND_REQUIRE_DKIM` (`REJECT 5.7.1 Sender domain is not ready …`), suppression (`REJECT 5.7.1 Recipient address suppressed`), per-tenant per-minute/day limits (`DEFER_IF_PERMIT 4.7.1`), size (`REJECT 5.3.4`) |
| `relay`             | `postfix-outbound` 25                   | as `submission`, connector from `ccert_fingerprint` (wins) or `client_address`; `require_tls` without TLS → `REJECT 5.7.1 Must issue a STARTTLS command first`                                                                                                                                                                                                                                                               |
| `reinject-inbound`  | `postfix-outbound` 10026                | recipient domain must be an active tenant domain (`REJECT 5.7.1 Relay access denied`)                                                                                                                                                                                                                                                                                                                                        |
| `reinject-outbound` | `postfix-outbound` 10027                | sender domain active + outbound-enabled (`REJECT 5.7.1 Sender address not authorized`), suppression, DKIM readiness `HEXISTS dkim_selectors <domain>` on redis-dkim (missing or error → `DEFER_IF_PERMIT 4.7.0 Signing key not available`)                                                                                                                                                                                   |

Postfix renders a policy `REJECT` as `550 5.7.1 …` / `550 5.1.1 …` (verified by the stack suites); the listener's own final `reject` answers `554 5.7.1 … Access denied`. Any thrown error, Redis or DB failure, or a decision slower than `SMTP_POLICY_DECISION_TIMEOUT_MS` answers `DEFER_IF_PERMIT 4.3.5 Policy service temporarily unavailable`. **The adapter never answers `OK`.** Replies are generic: no tenant names, ids or internal errors.

**Tenant resolution query.** `resolveActiveDomain(db, rawName)` (`packages/database/src/domains/resolve-active-domain.ts`) maps a recipient (or sender) domain to its organization in-session: normalized like the API, read by the unique `verified_name` on the **writer**, `active` domain of an `active` organization only. The adapter caches the domain view in Redis (`sa:dom:*`, 60 s, negative 30 s) and drops entries when it sees `domain.status.changed.v1` in the outbox tail (≤ 5 s; the TTL is the guarantee). Post-queue ingestion uses `resolveDomainOwner` (also `suspended` domains/organizations: mail accepted before a suspension is still stored).

**Wire behaviour** (`policy-protocol.ts`, `policy-server.service.ts`): requests may span TCP chunks and be pipelined; replies are written strictly in request order; a request over **16 KiB** or a line without `=` is a protocol error (tempfail, then close); an action containing CR or LF is refused; idle connections are closed after 60 s. Health: `policy-listener`.

**Postfix side**: `smtpd_policy_service_timeout = 10s`, default action `DEFER_IF_PERMIT 4.3.5 Policy service unavailable`. Unreachable or slow means **4xx, never accept-all**. Tested by `tests/integration/smtp-fail-closed.test.ts` (Redis down; adapter container stopped in CI) and `mail-plane.test.ts` (no adapter).

## 2. Postfix → Rspamd milter

Inbound policy since step 4.1: [ADR-0027](adr/0027-rspamd-milter-policy.md), [S11](../plan/steps/09-rspamd.md#s11-rspamd-at-smtp-time-milter-adr-0027), [deployment](../deployment/rspamd.md). The outbound `rspamd-outbound` DKIM signer is unchanged (ADR-0020).

| Aspect    | Contract                                                                                                                                                                                                                                                                                                                                         |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Transport | Milter protocol 6 to `inet:rspamd:11332` (Rspamd proxy worker in milter mode, `self_scan = yes`, `count = 1`)                                                                                                                                                                                                                                    |
| Macros    | connect `j {daemon_name} {daemon_addr} v _ {client_addr} {client_name}`; MAIL `i {auth_type} {auth_authen} {auth_author} {mail_addr} {mail_host} {mail_mailer} {client_addr} {client_name}`; RCPT `i {rcpt_addr} {rcpt_host} {rcpt_mailer}`; end of data `i`                                                                                     |
| Timeouts  | Postfix connect 10 s, command 10 s, content 30 s; Rspamd proxy timeout 25 s, `task_timeout` 15 s                                                                                                                                                                                                                                                 |
| Actions   | `554 5.7.1` only for GTUBE and score ≥ `RSPAMD_MILTER_REJECT_SCORE` (15); no `add_header`, subject rewrite, greylisting or soft reject. DMARC `p=reject` only with `RSPAMD_MILTER_DMARC_REJECT=true` (default off). Everything else is classified post-queue (§22)                                                                               |
| Headers   | Removes every inbound `X-Spam*`, `X-Spamd-*`, `X-Rspamd-*` and the `Authentication-Results` carrying our authserv-id (`RSPAMD_AUTHSERV_ID` = Postfix `myhostname`; custom routine `eg-strip-forged`), adds exactly one `Authentication-Results` of ours; no score header. Foreign `Authentication-Results` are kept and never trusted downstream |
| Failure   | `milter_default_action = accept`: Rspamd down or slow → the message is accepted without the SMTP-time pass and always scanned post-queue, where a failed engine is `scan_failed`, never clean. The policy service still fails closed                                                                                                             |

Verified through Postfix by `tests/integration/scan-smtp.test.ts` (GTUBE `554 5.7.1`, nothing stored; forged headers removed) and `scan-resilience.test.ts` (Rspamd stopped: `250` accepted).

## 3. Postfix → smtp-adapter LMTP ingestion

**IMPLEMENTED in step 2.2** ([design D7, D8, D13](../plan/steps/04-smtp-gateway.md); MIME parsing and `email_headers`/`email_attachments` rows are step 3.1). LMTP server built on `smtp-server` (`lmtp: true`, XFORWARD, no AUTH/STARTTLS), only for peers inside `SMTP_INTERNAL_CLIENT_NETWORKS`.

| Aspect       | Contract                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Listeners    | `:10050` = `direction inbound` (`postfix` `relay_transport`), `:10051` = `direction outbound` (`postfix-outbound` `content_filter` of 587 and 25), `:10052` = bounce notices. **The port decides the direction**, never content                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Envelope     | Inbound: each recipient's organization = `resolveDomainOwner(recipient domain)`; no owner → that recipient `451 4.3.0`. Outbound: the organization of the envelope sender domain (the policy proved the connector belongs to it). XFORWARD `IDENT` (the queue id) is required                                                                                                                                                                                                                                                                                                                                                                           |
| Ingest key   | Per organization: `v2:` + hex SHA-256 of `{mtaId}\|{queueId}\|{direction}\|{contentSha256}\|{recipientSetSha256}` (`mtaId` = LHLO name; the recipient set = that organization's accepted addresses, lower-cased, de-duplicated, sorted, LF-joined). A retry after a lost `250` carries the same queue file and recipients → same key → `250` without new rows (stack suite 7). A retry of only the recipients that were deferred (one RCPT tempfailed while another of the same organization was stored) has another key and is stored as its own message, never answered `250` and lost. `v1:` keys (no recipient set) predate the step 2.2 review fix |
| Transactions | **One writer transaction per organization**: `message_identities`, `email_messages` (`status received`, header metadata, `eml_object_key`, `eml_sha256`, `mta_queue_id`), `email_recipients`, one `email_events` `received`, one `message_outbox` `mail.message.received.v1` (validated)                                                                                                                                                                                                                                                                                                                                                                |
| Replies      | Per recipient in RCPT order: `250 2.0.0 Ok` after its organization's commit (or duplicate); `451 4.3.0 Temporary failure, please retry` for any S3/DB/timeout failure of that organization. Organizations are independent; never `5xx` for infrastructure faults                                                                                                                                                                                                                                                                                                                                                                                        |
| Refusals     | `554 5.4.6 Routing loop detected` (valid gateway trace for the same organization and direction, §16); outbound `550 5.7.1 From header does not match the authenticated sender domain`. Both become DSNs to an authenticated or traced sender (ADR-0019 exception)                                                                                                                                                                                                                                                                                                                                                                                       |
| Direction    | **Step 2.3 (R1):** per recipient `classifyRecipient` (`@email-gateway/mail-routing`) → `email_recipients.direction`. Inbound listener: always `inbound` (also for a sender in the organization's own domain). Outbound listener: `internal` when `resolveActiveDomain(R)` returns the same organization, else `outbound` (including another tenant's domain on this gateway). `email_messages.direction` = `internal` only when every recipient of that organization is internal; the `mail.message.received.v1` payload carries it. The ingest key, the S3 key and the loop check keep the **listener** direction                                      |
| Bodies       | Streamed once to S3 (multipart above 5 MiB, bounded memory), a server-side `CopyObject` per extra organization, never in MySQL                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

**Bounce notices (`:10052`).** `postfix-outbound` sends postmaster copies of its DSNs (`notify_classes = bounce, delay`) to `bounce-notices@${POSTFIX_BOUNCE_DOMAIN}`. That address is reserved: the policy refuses it (and its subdomains) as a recipient in every context (`550 5.7.1 Relay access denied`), and the handler refuses any LMTP envelope sender other than Postfix's bounce daemon (`<>` or `double-bounce@${POSTFIX_OUTBOUND_MYHOSTNAME}`, `550 5.7.1`). The handler parses `message/delivery-status`, resolves the organization from `X-Postfix-Sender`, and records the notice only if the undelivered message's headers (`text/rfc822-headers` part) carry a valid **outbound** `X-Gateway-Trace` of that organization (§16): only mail the gateway reinjected on 10027 for delivery says anything about the tenant. Failures of the ingestion hop (content filter LMTP 10051: From check, loop, adapter/S3/DB outage) and notices naming another tenant's sender domain are ignored (`250`, counted `ignored`). Per failed/delayed recipient it writes `bounce_events` (dedupe key SHA-256 of queue id, recipient, action, status) and, for hard address failures (`5.1.1`, `5.1.2`, `5.1.3`, `5.1.6`, `5.1.10`, `5.2.1`), upserts `delivery_suppressions` (`hard_bounce`, `source = bounce`, `SUPPRESSION_HARD_BOUNCE_DAYS`; never shortens a `manual`/`complaint` row). DB error → `451`; unparseable or unowned → `250` (counted).

**Step 2.3 (R9):** before the 2.2 rules, the handler matches the notice to a reinjection by `X-Postfix-Queue-ID` (= `delivery_reinjections.queue_id`) or `Original-Envelope-Id` (= the reinjection token, §15) and, when matched, records per recipient a `bounce_notice` delivery signal with the organization **of the reinjection row** (any direction, including inbound 10026 deliveries): `failed` + `5.x.x` → `bounced`, `failed` + `4.x.x` → `expired`, `delayed` → `deferred`. Signal key `dsn|{queueId}|{address}|{action}|{status}|{arrivalDate}`: a redelivered notice is a duplicate (no transition, no event, no outbox row). For matched outbound notices `bounce_events.message_id` / `message_received_at` are filled. Inbound and internal bounces create no suppressions and no reputation events.

**EML key (changed in step 2.2, D8):** the date is the UTC date of the ingestion attempt and `{objectRef}` is the first 32 hex characters of SHA-256(`{mtaId}|{queueId}|{direction}|{organizationId}`), so a same-day retry overwrites its own object instead of orphaning one; the message id does not exist before the transaction that follows the upload. The key is stored in `email_messages.eml_object_key` and carried in `mail.message.received.v1`; **consumers never derive it**. Orphans (upload succeeded, commit never did) are reconciled in step 3.2.

**Part key (step 3.1, M11):** deterministic. The date is the UTC date of the message's `received_at` (never "now"), `{organizationId}` and `{messageId}` come from the writer row, and `{partIndex}` is the node's index in `email_message_parses.structure`, so a retry, a redelivery or a concurrent worker writes the same key with the same bytes. `.text` and `.html` hold the transfer-decoded, UTF-8-converted text and HTML bodies, `.att` the decoded bytes of every other leaf. Filenames and header values never appear in a key or in object metadata; objects are stored with `ContentDisposition: attachment` (`ContentType` `text/plain; charset=utf-8` for `.text`, `application/octet-stream` otherwise). Keys are stored in `email_message_parses.{text,html}_body_object_key` and `email_attachments.object_key` (NULL when a size limit kept the part from being stored).

Rules: `{organizationId}` is a decimal id. Every key starts with `org/{organizationId}/` so per-tenant export, deletion and IAM conditions are prefix operations. The event schema enforces the **format** (`^org/[1-9][0-9]{0,19}/`); consumers must also check that the prefix **equals** the envelope's `organizationId` before reading (PLANNED 3.x). MySQL stores keys (`*_object_key VARCHAR(512)`), sizes and SHA-256 hashes, never content.

## 14. Postfix → smtp-adapter SASL

**IMPLEMENTED in step 2.2** (D10). `postfix-outbound` 587 uses `smtpd_sasl_type = dovecot`, `smtpd_sasl_path = inet:${SMTP_ADAPTER_HOST}:10042`, `smtpd_tls_auth_only = yes`. The adapter implements the server side of the Dovecot auth protocol 1.2: handshake (`VERSION 1 2`, `MECH PLAIN`, `MECH LOGIN`, `SPID`, `CUID`, `COOKIE`, `DONE`), `AUTH` with `secured` required, PLAIN (authzid empty or equal) and LOGIN. Success `OK <id> user=<username>`; wrong or unknown credentials, disabled connector or inactive organization → `FAIL <id> user=…` after `SMTP_AUTH_FAILURE_DELAY_MS` (SMTP `535 5.7.8`). **Temporary failures** (DB/Redis error, more than `SMTP_AUTH_MAX_FAILURES_PER_IP` failures per window) **close the connection without a reply**, which Postfix answers with `454 4.7.0 Temporary authentication failure` — Postfix 3.7 turns any `FAIL` line, including `FAIL … temp`, into a permanent 535 (deviation from D10 found by the stack tests). Secrets are Argon2id PHC hashes (`smtp_connectors.secret_hash`); successful verifications are cached in process memory keyed by an HMAC that includes the connector's `updated_at`.

## 15. Reinjection (delivery-worker → postfix-outbound)

**Listeners IMPLEMENTED in step 2.2; the caller (delivery-worker) IMPLEMENTED in step 2.3** ([design R4, R8](../plan/steps/05-routing.md), ADR-0021 amends ADR-0019 decision 2: the worker is the one internal SMTP client). Only clients in `POSTFIX_REINJECT_NETWORKS` (production: the delivery-worker subnet); never published to the host or the Internet (locally and in CI the test-only `reinject-forwarder` lets a worker on the host reach them).

| Port    | For                                                               | Policy context      | Rules                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ------- | ----------------------------------------------------------------- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `10026` | approved **inbound and internal** mail → the tenant's own servers | `reinject-inbound`  | recipient must be an active tenant domain (never the bounce-notice domain); routed by the `transport`/`tls_policy` maps (next-hop list, §13); `RCPT … NOTIFY=NEVER` for inbound (no backscatter to external senders), `NOTIFY=FAILURE,DELAY` for internal (DSN to the authenticated sender)                                                                                                                                                       |
| `10027` | approved **outbound** mail → the Internet                         | `reinject-outbound` | sender domain must be an active, outbound-enabled tenant domain with a published signing key; DKIM-signed by `rspamd-outbound`; `NOTIFY=FAILURE,DELAY`; **`-o content_filter=smtp:`** (step 2.3, R4): the empty next hop means the recipient domain, so Postfix does its own MX lookup and **never consults `transport_maps`** — a recipient in another tenant's domain is reached through that tenant's public MX, never its destination servers |

Session (step 2.3, verified on Postfix 3.7, [mail-routing.md](../deployment/mail-routing.md#reinjection-session-contract-r8-verified)):

1. `EHLO ${DELIVERY_REINJECT_HELO}` (`delivery.gateway.local`, organization-neutral); `XFORWARD` must be advertised, else a configuration error (retry).
2. `XFORWARD NAME=… ADDR=… HELO=… PROTO=ESMTP` with the message's original client (`[UNAVAILABLE]` when unknown), then **`XFORWARD IDENT=<token> SOURCE=REMOTE`**. **Contract change (ADR-0021): `IDENT` is the reinjection token `dw1-` + the 32 hex digits of `delivery_reinjections.public_id`**, no longer the original queue id; Postfix logs it as `orig_queue_id=` on the `client=` line, which binds its queue id to the reinjection even if the worker crashes before reading the `250` (§19). The forwarded `ADDR` does not change `permit_mynetworks`. Deviation (WP2): Postfix's `Received:` of this hop names the real peer, not the XFORWARD client; with `smtpd_peername_lookup=no` it reads `from delivery.gateway.local (unknown [<worker ip>]) by out.gateway.local`.
3. `MAIL FROM:<original envelope sender> SIZE=<n> RET=HDRS ENVID=<token>` (+ `SMTPUTF8` for non-ASCII addresses). `ENVID` returns as `Original-Envelope-Id:` in DSNs and postmaster copies (second matching key of the bounce handler, §3).
4. `RCPT TO:<a> NOTIFY=<per direction> ORCPT=rfc822;<xtext a>` per recipient. `2xx` accepted; `4xx` → that recipient moves to a new reinjection with the worker backoff (`deferred`, `reinjection_4xx`, or `no_destination` for `Destination not configured`); `5xx` → `failed`, `reinjection_refused`.
5. `DATA`: one `X-Gateway-Trace` (§16) + the stored EML **unchanged** (streamed from S3; LF → CRLF, dot-stuffing). `250 … queued as <QID>` → `queued` (never `delivered`), `outbound_queue_id = QID`. A timeout after the final dot is ambiguous and left to the reconciler.

Postmaster copies of the resulting DSNs reach the bounce handler (§3).

## 16. Gateway trace header

**IMPLEMENTED in step 2.2** (D14; `buildGatewayTrace` / `countGatewayPasses` in `@email-gateway/common`). `X-Gateway-Trace: v=1; g=<GATEWAY_TRACE_ID>; d=<in|out>; t=<unix seconds>; s=<sig>`, `sig` = base64url (no padding) of the first 16 bytes of HMAC-SHA256(`GATEWAY_TRACE_SECRET`, `v1|<g>|<d>|<t>|<organizationId>`). It names neither the tenant nor an internal host. Ingestion counts valid traces for the same gateway, direction and organization; `≥ SMTP_LOOP_MAX_PASSES` → `554 5.4.6` for that organization's recipients. Forged traces and other tenants' or the other direction's traces do not count (stack suite 11).

**Step 2.3:** the delivery-worker prepends exactly one trace on **both** reinjection listeners: `d=in` on 10026 (inbound and internal), `d=out` on 10027. The 10026 trace is what stops a loop between tenants' routes at the second arrival for the same organization (`routing-loops.test.ts`). Before connecting, the worker also evaluates hops (`evaluateHops`): `Received:` count ≥ `ROUTING_MAX_RECEIVED_HEADERS` (25) or valid traces of this organization in **both** directions ≥ `ROUTING_MAX_GATEWAY_PASSES` (4) → `failed`, `loop_detected`, nothing sent.

## 17. DKIM key store (redis-dkim)

**IMPLEMENTED in step 2.2** (D12, ADR-0020). The api's `DkimSigningPublisher` (every `DKIM_SIGNING_SYNC_INTERVAL_SECONDS`, one replica per tick, and on demand with `pnpm --filter @email-gateway/api dkim:sync`) decrypts the active RSA-2048 key of every active, outbound-enabled domain of an active organization (`SecretBox`, AAD `dkim:<domain public id>:<selector>`) and reconciles two hashes in `MULTI/EXEC`: `dkim_selectors` (`<domain>` → `<selector>`) and `dkim_keys` (`<selector>.<domain>` → PKCS#8 PEM). `rspamd-outbound` reads them as `dkim-reader` (`selector_prefix`/`key_prefix`), smtp-adapter probes `dkim_selectors` as `dkim-probe` (never keys). redis-dkim has no persistence; after a restart 10027 defers until the next sync.
