# ADR-0059: Admin portal design system (tokens, theming, components, accessibility, charts)

**Status:** Accepted (2026-11-13, step 7.1 WP6; designed in [docs/plan/steps/20-admin-portal.md](../../plan/steps/20-admin-portal.md) P12–P14, implemented by WP2, used by WP3–WP5). Verified end to end ([verification record](../../plan/steps/20-admin-portal.md#14-verification-record)): every one of the 22 pages, their tabs and the e-mailed routes rendered in Chromium with seeded data and no serious or critical axe violation (WCAG 2.2 A/AA rules of axe-core 4.14) as organization admin, platform admin and mailbox user; desktop 1440×900, tablet 834×1112 and mobile 390×844 layouts (sidebar, rail, focus-trapped drawer with focus return, no horizontal page overflow on any top-level page, tables as cards on mobile); the 12 dashboard widgets equal figures computed independently from the seed. Corrections made by WP6 (§13): grid items inside the page may shrink (`min-width: 0`, base layer), links inside running text are underlined, label-in-name fixes (account menu, multi-select filters). The rules for implementers are in [docs/frontend/design-system.md](../../frontend/design-system.md).

**Context.** Step 7.1 builds 22 pages in three parallel work packages on top of one foundation. Without a shared system each package would invent its own colours, badges, tables and states, and accessibility would be checked page by page. The portal shows security data (verdicts, severities, delivery and quarantine states) where colour carries meaning, attacker-controlled strings everywhere, secrets that are shown once, and lists without totals (cursor pagination, ADR-0051). The brief requires Next.js, React, TypeScript, Tailwind CSS, shadcn/ui and Recharts, WCAG 2.2 AA, a professional enterprise look (dark navy sidebar, light workspace, optional dark mode) and that no invented number is ever shown.

**Decision.**

1. **Tokens are the only source of colour.** CSS custom properties in OKLCH in `src/app/globals.css`, defined for light (`:root`) and dark (`.dark`), mapped into Tailwind 4 with `@theme inline`. Groups: surfaces, lines (`border` decorative; `input` and `ring` ≥ 3:1), actions, feedback, a navy `sidebar` set kept in both themes, the override `banner`, eight semantic **tones** (neutral, info, success, warning, orange, danger, purple, magenta) and a categorical chart palette `--chart-1…8`. Semantic scales (verdict, severity, delivery state, quarantine state, direction, risk bands) map values to tones in one module (`src/components/domain/semantic.ts`); badges always print the label, so colour is never the only cue.
2. **Contrast is tested, not reviewed.** A manifest (`src/lib/design/tokens.ts`) lists every foreground/background pair the components use with its AA threshold (text 4.5:1, non-text 3:1); a unit test converts OKLCH → sRGB (clamped like browsers) → WCAG relative luminance for both themes and fails below the threshold. The measured ratios are published in the design-system document.
3. **Typography and shape:** Inter Variable (UI) and JetBrains Mono Variable (ids, hashes, secrets), self-hosted from npm (`@fontsource-variable/*`, no external requests, CSP `font-src 'self'`); scale 12/13/14/16/18/20/24/30 px, base 14 px, tabular numbers; 4 px spacing grid; radius 6/8/10/14 px; three elevation levels; motion ≤ 200 ms, disabled under `prefers-reduced-motion`.
4. **Components:** shadcn/ui primitives (new-york) themed only through tokens in `src/components/ui/`; composites (`DataTable`, `ConfirmDialog` with typed confirmation, `SecretRevealDialog`, `KpiTile`, `RangePicker`, `PageHeader`, `Breadcrumbs`), the four states (`LoadingState`, `EmptyState`, `ErrorState` with status title, API message, `code`, `requestId` and the operation's required permissions, `UnavailableState` naming the step), and domain components (`VerdictBadge`, `DirectionBadge`, `RiskScore`, `DeliveryStatusBadge`, `QuarantineStateBadge`, `DateTime`, `CopyableId`, `UntrustedText`). Wave-2 packages may not edit them; local variants are recorded as deviations.
5. **Tables follow the API's list model:** `DataTable` over TanStack Table with server-side cursor pagination (cursor stack, Previous/Next, "Page N", no totals, the short-page notice of the scan budget), sort only where the operation declares `sort`, filters and search in the URL, column visibility per table in `localStorage`, row actions, per-page selection for bulk actions, sticky first column on tablets and a stacked card list on phones.
6. **Accessible charts:** Recharts only through wrappers (`TimeSeriesChart`, `BarChart`, `DonutChart`, `Sparkline`) inside `ChartFigure`: `<figure>`/`<figcaption>`, `role="img"` with a computed `aria-label` summary, a "View data as table" toggle with a real captioned table, text legends, keyboard-reachable tooltips, colours from the chart tokens (≥ 3:1 against cards in both themes). Missing buckets are gaps, never invented zeros.
7. **Content safety is part of the system:** no `dangerouslySetInnerHTML` (lint, no exceptions), attacker-controlled strings only through `UntrustedText` (text, truncated, never a link), secrets only in `SecretRevealDialog` (`gcTime: 0`, reset on close), message content never rendered except the sanitized quarantine preview as React text.
8. **Dark mode** with next-themes (class strategy, system default, CSP nonce on its script); both themes define every token.
9. **Every page test runs axe** (`expectNoAxeViolations`: serious and critical fail) through the shared test kit (`src/test/`), and WP6 repeats axe in the end-to-end visits.

**Alternatives considered.** A third-party component suite (MUI, Ant Design): heavier, its own theming and CSS-in-JS conflict with Tailwind and the CSP nonce, and the brief names shadcn/ui. HSL tokens (shadcn's older default): OKLCH gives perceptually even steps across tones and is what Tailwind 4 uses. Contrast checked by hand or by axe only: axe sees rendered pages, not every token pair in both themes, and manual checks drift. Chart libraries with built-in accessibility (Highcharts): licence and bundle size; the wrappers give the required table fallback with Recharts. Per-page badge colours: inconsistent semantics across 22 pages.

**Consequences.** New colours require a token (and a manifest entry if text sits on it); the contrast test fails the build otherwise. Pages are slower to customise but consistent. The design-system document must be updated with any new component. The chart wrappers limit what charts can do; a page that needs another chart type adds a wrapper in a follow-up rather than using Recharts directly.
