# ADR-0066: Immutable archive storage with per-tenant S3 Object Lock (governance or compliance), set at upload, extend-only; honest fallback; AWS vs MinIO

**Status:** Accepted (2026-11-17) for MinIO, verified locally: governance and compliance at upload, extend-only retention, locked-version deletion refused (stack suite case 13, worker integration suite), the empty-bucket Object Lock migration of `minio-init` (WP1 probe; record [docs/plan/steps/23-journaling-archiving.md](../../plan/steps/23-journaling-archiving.md) §13, §14). Proposed by the step 8.1 architect on 2026-11-16 (design A10, A29, A30). Supersedes no ADR decision. Implementation note: `governance → compliance` on existing versions needs `BypassGovernanceRetention`, as on AWS (WP1 deviation 6, WP3 D11). **Not verified:** AWS S3 Object Lock (Terraform written, `terraform validate` not run: no Terraform on the workstation).

**Context.** The brief requires immutable storage where legally and contractually required. Archived objects are already write-once at the application level, but an operator with bucket access, a bug or a compromised credential could still delete versions. S3 Object Lock provides storage-level WORM in two modes: governance (bypassable with a dedicated permission) and compliance (no one can shorten or remove the retention before it ends). Object Lock must be enabled on the bucket (on AWS also on an existing versioned bucket; on MinIO only at bucket creation). The local archive bucket was created without it and is empty.

**Decision.**

1. **Bucket.** The archive bucket has Object Lock enabled and **no default retention**; retention is set per object. Locally the bootstrap recreates the archive bucket with lock when it exists without lock and holds no object version, and refuses (pointing to the runbook) when it holds data. A test-only replica bucket is created the same way.
2. **Per tenant.** `archive_settings.object_lock_mode`: `none` (default) | `governance` | `compliance`. For a locked tenant every archive object (original, journal report, scan snapshots, later rounds) is uploaded **with** its lock mode and `retain-until = retain_until` of the record, so there is no unlocked window; `lock_mode` and `lock_until` are recorded. Export packages are never locked.
3. **Extend-only.** Whenever the lifecycle keeps a locked record past `lock_until` (a longer policy, a legal hold, a review), it first extends every object version's retention, then updates the row. Retention is never shortened.
4. **Mode changes.** `none → governance | compliance` and `governance → compliance` apply to new captures and start a bounded pass that locks active records; `compliance → anything` is refused; `governance → none` affects new captures only.
5. **Legal holds** are enforced in MySQL at disposal and, for locked tenants, by extending the lock; object legal-hold flags are not used.
6. **Honest fallback.** Lock availability is probed (`GetObjectLockConfiguration`) unless disabled by configuration. Without Object Lock, settings asking for a mode are refused and captures of such tenants fail with `object_lock_unavailable` instead of storing unlocked copies; the status route reports it.
7. **AWS vs MinIO.** Both implement the S3 Object Lock API (modes, retain-until, governance bypass header, legal hold). Differences: MinIO enables lock only at bucket creation; AWS S3 Object Lock has third-party regulatory assessments that local MinIO does not stand in for; on AWS, replication to the DR bucket carries lock settings when the destination has lock enabled (10.2); orphan cleanup with governance bypass is granted only to the lifecycle role's IAM policy.

**Alternatives considered.** Bucket default retention (one retention for every tenant and record). Locking after the database commit (a short unlocked window). Object legal-hold flags per hold (an O(records) pass per hold and a second source of truth). Compliance mode for everyone (irreversible for tenants that never asked for it, test objects stuck locally). Silently storing unlocked copies when Object Lock is missing (claims a guarantee that does not hold).

**Consequences.** Compliance-locked data cannot be deleted by anyone, including the platform, before its date; a crash between upload and commit may leave a locked orphan until its lock ends (recorded and retried). Local tests use a shortened test day (`ARCHIVE_TEST_DAY_SECONDS`, local/ci only) to keep locked test objects short-lived. The tenant's choice is a contractual statement the platform enforces; it is not legal advice.
