# ADR-0019: SMTP gateway topology: two Postfix instances, Node behind Postfix extension protocols, durable LMTP ingestion

**Status:** Accepted. Amends [ADR-0006](0006-postfix-mail-path.md) (two documented post-queue DSN cases; outbound submissions are ingested before delivery) and [ADR-0011](0011-observability.md) (services may expose Prometheus `/metrics` scraped directly). Design: [step 2.2](../../plan/steps/04-smtp-gateway.md).

**Context.** Step 2.2 turns the local MX into a production-oriented gateway: tenant domains resolved dynamically, recipient validation, rate limits, durable ingestion, authenticated outbound submission (SASL, source IP, client certificates), per-domain DKIM, bounce processing and loop prevention. ADR-0006 fixed Postfix at the edge and LMTP ingestion but left open how Postfix gets tenant data, how submission is authenticated, how the outbound path is laid out and what the ingestion idempotency key is. The security boundaries say the edge (Postfix) holds no data-store credentials.

**Decision.**

1. **Two Postfix instances**: `postfix` (inbound MX, port 25 behind postscreen) and `postfix-outbound` (submission 587 with STARTTLS + SASL, connector relay 25 for source-IP and client-certificate connectors, internal reinjection listeners 10026 for approved inbound mail to tenant servers and 10027 for approved outbound mail to the Internet). Each listener states its own relay permission; the outbound `main.cf` defaults to `reject`.
2. **Node never speaks SMTP.** smtp-adapter implements only Postfix extension protocols — policy delegation (:10040, with `policy_context` per listener), **socketmap** lookup tables (:10041: `relay_domains`, `transport_maps`, `smtp_tls_policy_maps`, connector client/certificate access maps) and the **Dovecot SASL auth protocol** (:10042) — and LMTP servers built on the `smtp-server` library (:10050 inbound, :10051 outbound, :10052 bounce notices). Postfix holds no database credentials; all tenant rules live in one service with one cache.
3. **Outbound mail is ingested like inbound mail**: submission and connector listeners hand accepted mail to LMTP ingestion with `direction = outbound` (`content_filter`); mail reaches the Internet only through the reinjection listeners after the post-queue pipeline approves it. There is no direct submission-to-Internet path.
4. **Ingestion contract**: per organization of a message, one writer transaction (registry, `email_messages`, `email_recipients`, `email_events`, outbox) after the EML is in S3; `250` per recipient only after commit; `451 4.3.0` on any failure. Idempotency key = MTA id + Postfix queue id (XFORWARD, long queue ids) + direction + content SHA-256. S3 keys are deterministic per queue file and organization (`org/{organizationId}/eml/yyyy/mm/dd/{objectRef}.eml`), so the message id is no longer part of the key.
5. **Two post-queue DSN cases are allowed** (exceptions to ADR-0006's "never bounces"): a routing loop proven by an HMAC-signed, organization-neutral `X-Gateway-Trace` header for the same tenant and direction (`554 5.4.6`), and an outbound message whose `From` header does not match the authenticated sender domain (`550 5.7.1`; the sender is an authenticated tenant user, so this is a real bounce, not backscatter). Postfix's own hop-count and queue-lifetime DSNs are unchanged. Policy outcomes (spam, malware, …) still never bounce.
6. **Metrics**: smtp-adapter exposes Prometheus metrics at `/metrics` (prom-client, `MetricsModule` in `@email-gateway/common`), scraped directly like RabbitMQ.

**Alternatives considered.** MySQL lookup tables and Dovecot SQL passdb in the Postfix containers (DB credentials and duplicated tenant rules at the edge); direct submission-to-Internet with signing (an unscanned bypass); a Node SMTP/milter implementation (forbidden by the brief and unnecessary). Details in the step note §7.

**Consequences.** smtp-adapter becomes a hard dependency of both Postfix instances; its outage turns every lookup, policy check, AUTH and LMTP delivery into a temporary failure (mail waits in senders' queues or Postfix spools, never lost). It must be deployed redundantly next to the Postfix ASGs and monitored (`/health/ready`, metrics). Delivery-worker (steps 3.x/5.x) must follow the reinjection contract (XFORWARD, trace header, `NOTIFY=NEVER` on inbound reinjection).
