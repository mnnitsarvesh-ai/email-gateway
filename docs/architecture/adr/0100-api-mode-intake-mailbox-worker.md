# ADR-0100: API-mode intake: mailbox-worker, change feeds, per-mailbox copies, dedupe, lag and coverage

**Status:** Accepted (2026-11-26, local verification: stack suite `api-mode.test.ts` 11/11 on the containerized mailbox-worker — `copy_scanned.v1` → `email.mailbox` → per-mailbox copy rows with verdict, risk and lag; Graph subscriptions created through the api's validation handshake, a change notification → delta → MIME fetch → `mailbox_api` copy scanned; Gmail history poll → raw fetch; dedupe in both orders with no MIME fetch for the journal-first copy (simulator call log); scripted `429 Retry-After: 2` paused and retried with `throttled_429` and `throttled_until`; inventory and coverage totals; `GET /api-mode/overview` consistent; regression messaging-topology 28/28 (v17); live provider tenants, CI, Kubernetes apply and the 3-node RabbitMQ cluster suite pending). **Context.** Brief scope 3 and 9: optional change feeds, dedupe of journal and API copies by Message-ID plus mailbox, lag from provider delivery to verdict, coverage and health; every provider call budgeted per tenant with `Retry-After` honoured; idempotent asynchronous processing through the outbox and RabbitMQ. The integration-worker has no RabbitMQ and no Redis by design; the ato-worker is ATO-scoped; the provider HTTP client is JSON-only.

**Decision.**

1. A new deployable **mailbox-worker** (HTTP 3087; roles `copies`, `feeds`, `inventory`, `health`; API-2 adds `remediate`). Every outbound event is an outbox row; the worker never publishes directly.
2. Feeds are **off by default** per provider connection (`api_mode_connections.feeds_enabled`). Microsoft: the Inbox **delta query is the source of truth**; Graph change notifications reach a public, unprivileged api callback that only sets `api_mailboxes.sync_requested_at` after a subscription-id lookup and a constant-time client-state hash match (the client state is stored as SHA-256). Google: history polling on INBOX. No backfill: a feed starts at the current cursor.
3. Content is fetched (MIME / Gmail raw, streamed, ≤ `API_MODE_MAX_MESSAGE_BYTES` 50 MiB) only when no copy of the same Message-ID exists for that mailbox, and becomes a registry message with `email_messages.ingest_source = mailbox_api`, scanned in detect mode and **never archived**.
4. The email-worker writes `mail.message.copy_scanned.v1` (exchange `email.security`) for every scanned non-gateway copy; **topology v17** adds the work queue `email.mailbox` (ledger `mailbox-worker.copies`, retry `hold` 5 × 10 s–60 s, reconciled) and the role user `eg-mailbox`. The copies consumer records one `api_message_copies` row per API-mode mailbox (inbound recipients in API-1; internal recipients are counted only) with verdict, risk score, lag and the hybrid inline link, deduplicated through `api_copy_dedupe_keys` (`api-copy/1` hash of organization and Message-ID, unique per mailbox).
5. Per-connection Redis budgets per API family (`mbx:rb:…`) and a shared throttle pause (`mbx:throttle:…`, TTL = `Retry-After` ≤ 600 s) honoured by every worker before any call of that family.
6. Coverage per mailbox (healthy feed, or a journal sighting within `API_MODE_JOURNAL_COVERAGE_DAYS`), connection health (`api-mode-health/1`) with the alert kind `api_mode_unhealthy` (at most once per connection per 24 h), hourly counters (`api_mode_counters`), metrics and Prometheus rules.

**Consequences.** Six tables (one partitioned: `api_message_copies`, 6 months, core), one queue, one role user, one worker; copies are visible only on the API-mode pages (gateway views filter `ingest_source = 'gateway'`); API-2 acts on `api_message_copies`. Provider cursors are opaque and never returned by the api; no message content in MySQL.

**Alternatives considered.** Feeds in the integration-worker or ato-worker (no Redis/RabbitMQ there; ATO's failure domain); rich (encrypted-content) notifications or trusting notification data; subscriptions without delta; a Graph `/messages` subscription across folders; Gmail Pub/Sub push; backfill on feed start; archiving API copies; storing the verdict on `email_messages.final_verdict`; dedupe by raw hash or by Message-ID across the organization. Details: design §6.
