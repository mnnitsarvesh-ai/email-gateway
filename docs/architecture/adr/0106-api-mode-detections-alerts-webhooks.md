# ADR-0106: API-mode detections in alerts and webhooks

**Status:** Accepted (2026-11-27, local verification: stack suite `api-mode-parity.test.ts` 11/11 — `mail.message.copy_detected.v1` relayed by the rebuilt event-relay over the topology v19 binding; `mailbox.dlp.detected` (outbound, `remediation: null`; internal) and `mailbox.threat.detected` (EICAR, `protectionMode: api`, stage `scan`) received and signature-verified at the webhook receiver, every received payload passing the payload guard, the strict catalogue schema and the no-content assertion; no `email.threat.detected` for a copy; the `dlp_detected` and post-delivery `threat_detected` e-mails with the `/api-mode` detections link at notify-relay-sink, one per recipient; the detect-variant policy alert; no event, alert or webhook for a hybrid inline-authority copy; webhook-worker and notification-worker suites of WP5; live provider tenants, CI and Kubernetes apply pending); proposed by the step API-4 architect, 2026-11-27. Design: [docs/plan/steps/38-api-mode-parity-onboarding.md](../../plan/steps/38-api-mode-parity-onboarding.md) §0, §1.2 (items 1, 5), §2 (P-I3, P-I7), A7–A9, §7, §12. Contracts [§39](../contracts.md#39-api-mode-parity-and-onboarding-step-api-4) (event `mail.message.copy_detected.v1`, `mail.policy.notification_requested.v1` + `evaluationMode`, alert kinds `dlp_detected` and `api_mode_detect_only_ended`, topology v19, public webhook types `mailbox.threat.detected` and `mailbox.dlp.detected`); migration `20261127120100_api_mode_parity_onboarding` ([docs/database/README.md](../../database/README.md#step-api-4-migration-20261127120100_api_mode_parity_onboarding)) (counter `copy_detections`). **Context.** PO-D2 asks for `threat_detected` (and DLP/BEC) alerts and webhooks for API-mode detections with the protection mode where contracts allow. ADR-0054: strict v1 types, breaking changes need v2, additions are new types; DLP incidents are not events (decision 8). A copy's sandbox verdict currently yields `email.threat.detected` (an N1 leak).

**Decision.**

1. Internal event `mail.message.copy_detected.v1` from the mailbox-worker per copy message with a detection (topology v19: bound to `email.webhooks`).
2. New public types `mailbox.threat.detected` and `mailbox.dlp.detected` (catalogue v1, version 1, metadata only, protection mode in `data`); `email.threat.detected` v1 unchanged and no longer fed by sandbox verdicts of copies. **Supersedes ADR-0054 decision 8 in part** (DLP detections of API-mode copies are events).
3. Alerts: `threat_detected` also for API-mode detections (post-delivery template); new kind `dlp_detected` (recipients `dlp:read`, tenant settings, opt-out); new kind `api_mode_detect_only_ended`.
4. Policy ALERT actions of copies use `mail.policy.notification_requested.v1` with `evaluationMode: detect`.
5. Hybrid inline-authority copies produce no event.

**Consequences.** Receivers subscribe to the new types explicitly; no breaking change; one more binding.

**Alternatives considered.** Mode field or stage value in v1; a v2 of `email.threat.detected`; reusing `mail.policy.decided.v1` (design §7).
