# ADR-0104: Internal mail and user-reported phishing in API mode

**Status:** Accepted (2026-11-27, local verification: program acceptance stack suite `api-mode-clawback.test.ts` 10/10 — internal EICAR journaled to an api and a hybrid recipient recorded as two `internal` copies and moved, a second journal report deduplicated, an outbound-only message never recorded or delivered; a forward-as-attachment report matched by Message-ID (`pending_triage`, assessment malicious), an inline forward matched by sender + subject, an external reporter rejected without e-mail, acknowledgement and result e-mails at notify-relay-sink without the reported content, a report clawback removing every copy; worker, api and notification-worker suites of WP1–WP6; live provider tenants, CI and Kubernetes apply pending); proposed by the step API-3 architect, 2026-11-27. Superseded in part by [ADR-0105](0105-api-mode-copy-policy-evaluation-and-policy-lane.md) (decision 1) (step API-4, 2026-11-27): outbound journal messages are policy-evaluated when the organization's outbound-detection setting is on (default on); a detection is recorded on the sender's mailbox as a copy with `direction = outbound` that is never remediated (`skip outbound_not_remediable`), never a clawback target and never a coverage sighting; non-detections are still not recorded.

**Context.** Brief scope 7 and 8: east-west mail must be scanned and remediated like inbound mail; users forward suspicious mail to a per-tenant report mailbox (P4: no add-in); reports are scanned, triaged, may trigger clawback and the reporter gets feedback. [ADR-0100](0100-api-mode-intake-mailbox-worker.md) (note 35 D7.4) records inbound journal recipients only.

**Decision.**

1. **Supersedes ADR-0100 in part (D7.4):** internal journal recipients are recorded as copies with `direction = internal` when the organization's internal-mail setting is on (default); outbound-only journal messages are recognised and never recorded; dedupe and N1 are unchanged; the remediation decision gains the skip `internal_mail_disabled`.
2. **Report mailboxes** are API-mode mailboxes flagged `report_mailbox` (≤ 5 per organization); their copies are never remediated and create `api_user_reports`.
3. The mailbox-worker **`reports` role** checks the reporter (organization-side, no loop, no auto-reply, rate limit), extracts the original (forward-as-attachment or inline forward headers) with a bounded pure extractor, links it to a recorded copy or ingests the attached original as a `mailbox_api` registry message without a copy row for a detect-mode scan.
4. **Analysts triage** reports in the portal (states, verdicts, groups); a report never remediates by itself; an analyst may create a clawback ([ADR-0103](0103-api-mode-clawback-search-and-purge.md) rules).
5. **Reporter feedback** (acknowledgement and result) goes through the notification-worker with the strict, content-free event `mail.report.feedback_requested.v1` (topology v18, one binding).

**Consequences.** East-west threats are visible and remediated; reports reuse copies, scanning and clawback; no add-in.

**Alternatives considered.** A new ingest source for report originals; quarantine notification kinds for feedback; automatic report-driven clawback (design §6).
