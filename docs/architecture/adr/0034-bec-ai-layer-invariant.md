# ADR-0034: BEC AI layer: additive, bounded, versioned; Anthropic Claude as the optional LLM provider

**Status:** Accepted; implemented in step 4.4 (implementation notes below; **no real LLM call has been made**). Design: [step 4.4](../../plan/steps/12-phishing-bec.md) B9, B10, B16.

**Context.** The brief requires deterministic rules first, ML or LLM classification only as an additional layer with structured evidence and confidence, and that an LLM never alone authorizes or rejects delivery. No LLM provider exists in the repository.

**Decision.**

1. **Deterministic verdict first** (`bec-map/1`: reason codes, severities, weights, score, identity + intent evidence classes). AI providers (a local logistic-regression model `bec-lr/1` with committed, reproducible weights, and an optional LLM) implement one interface returning labels, confidence 0–1, cited features, source spans by offset, enumerated indicators, model id/version and, for the LLM, the prompt template version and a response hash.
2. **Aggregation invariant** (pure, exhaustively and property-tested): final `clean` only if the deterministic verdict is `clean`; AI never lowers; AI alone raises to at most `suspicious`; AI may turn `suspicious` into `malicious` only when deterministic identity and intent evidence fired and the deterministic score is within a platform band (≤ 15 points) of the malicious threshold; shadow output never changes anything; any AI failure leaves the deterministic verdict.
3. **Modes** `off`/`shadow`/`active` per layer: platform caps (local model `shadow`, LLM `off` by default) and per-tenant opt-in within the cap.
4. **LLM provider:** Anthropic Claude through the official `@anthropic-ai/sdk`, model configurable (default `claude-opus-5-5`), strict JSON-schema structured output without free text, server-side refusal fallback enabled by default, low effort, timeouts, breaker, per-tenant and platform budgets in Redis, gating to borderline messages. **Data minimization:** only a redacted excerpt (≤ 1 500 characters; addresses, URLs, digit runs, phones, profile names and tenant labels replaced) and derived features are sent; never attachments, full bodies, identifiers or secrets. Tests use a fake transport and recorded fixtures; stack runs use a fake provider that is refused in production.
5. **Model versioning** by configuration and a packaged manifest (active and shadow model ids, file hashes checked at start); every result records engine, rules, lexicon, model and prompt versions.

**Alternatives considered.** LLM as the classifier of record (violates the brief); free-text rationales (could echo content into storage); a model registry table (second source of truth for deploy-time artefacts); other vendors (no existing choice; the interface allows adding one).

**Consequences.** BEC verdicts stay reproducible from deterministic inputs; enabling the LLM is an operator and tenant decision with a cost budget and a documented data-handling statement; prompt injection in mail can at most fail to raise a verdict.

**Implementation notes (step 4.4, [§12](../../plan/steps/12-phishing-bec.md#12-deviations-log), [§13](../../plan/steps/12-phishing-bec.md#13-verification-results)).** The invariant (P1–P6) is enforced by `combineVerdict` and tested exhaustively (> 50 000 grid cases) and by 10 000 seeded random cases; the local model `bec-lr/1` is reproduced byte for byte by `model:check` (synthetic training set: its metrics show template reproduction, not real-mail performance). The provider uses `@anthropic-ai/sdk` 1.1.0 (`client.beta.messages.create` with `output_config.format` JSON schema, `effort: 'low'`, beta `server-side-fallback-2026-07-01` and `fallbacks: 'default'`; `BEC_LLM_REFUSAL_FALLBACK=off` uses `client.messages.create`), verified against the installed SDK types and a fake transport only. Refinements: the output format has no `strict` flag (strictness is the schema; numeric and array bounds are enforced by zod after parsing, WP2 deviation 1); SDK telemetry content and debug logging are off (WP2 deviation 3); the LLM is never called for a deterministic `malicious` (gated-out calls are counted `status="gated"`, WP3 deviation 4); `refused`/`invalid_output` count as breaker successes (WP3 deviation 5). Stack and package integration runs use `BEC_LLM_PROVIDER=fake` (refused in production). **Open:** no call to the real Anthropic API was made in this step; enabling it is an operator decision following [the deployment document](../../deployment/bec-detection.md).

**Amendment (review round 1, 2026-11-07): AI-only raises never hold delivery.** Decision 2 lets the AI raise a deterministic `clean`/`unknown` result to `suspicious`; the dev pass-through (B17) held every bec `suspicious`, so an LLM assessment alone kept mail in `scanned`, which contradicts "an LLM never alone authorizes or rejects delivery". Decided: the engine outcome stays the combined verdict (the AI raise is recorded as `bec.ai.flagged` and `bec_scan_results.ai[].effect = raised_to_suspicious`), and **every delivery decision on a bec result uses the deterministic verdict** (`bec_scan_results.deterministic_verdict` of the round). The dev pass-through reads that row (writer, echo-checked, in its ledger transaction) when the bec outcome is `suspicious`/`malicious`: deterministic `suspicious`/`malicious` → held (`reason="bec_verdict"`), a missing row → held (fail-safe), deterministic `clean`/`unknown` → approved and counted `delivery_bec_ai_only_not_held_total`. `scanned.v1` is unchanged (strict schema; adding a field would break consumers during a rolling upgrade). Policy (5.2) inherits the rule ([contracts](../contracts.md)): it may tag or warn on an AI-only raise but must not hold, quarantine or reject because of it. Tests: `becHoldDecision` and the approver unit tests, the delivery-worker `approvals` integration case (deterministic `clean`, final `suspicious` → approved).
