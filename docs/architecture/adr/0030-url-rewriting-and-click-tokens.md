# ADR-0030: URL rewriting in the URL engine into a separate S3 copy, and compact HMAC click tokens

**Status:** Accepted. Refines [ADR-0021](0021-mail-routing-and-delivery-status.md) (the approval's `emlS3Key` may name the rewritten copy; the delivery-worker is unchanged) and [ADR-0022](0022-mime-parsing-and-post-queue-ingestion.md) (the original EML stays immutable). Design: [step 4.3](../../plan/steps/11-url-protection.md) U11, U12. **Amended in step 5.3 by [ADR-0049](0049-policy-copy-body-edits-banners-and-url-rewrite.md):** the policy-engine also signs click tokens with the current key only (URL rewriting after the scan); a release reuses the re-validated round's rewritten copy.

**Decision.**

1. **Where:** the URL engine, at the end of its definite scan, streams the stored EML through a MIME rewriter (mailsplit, parse5 source offsets, no re-serialization) and uploads a rewritten copy to `org/<org>/rewrite/…/<messageId>/r<round>-<uuidv7>.eml` (tagged for lifecycle expiry). The `url_rewrites` row of the round, written in the finalize transaction, names it. The approver (dev pass-through now, policy and quarantine release later) sets `emlS3Key` to that object when the round was rewritten, otherwise to the original. Archive, quarantine and rescans use the original.
2. **What:** `a`/`area` hrefs in inline HTML bodies and http(s) URLs in inline text bodies; never attachments, headers, images, forms, `mailto:`/`tel:`/`cid:`, the click host, tenant-excluded or allow-listed domains, or URLs the scan did not record. Untouched nodes pass through byte-identical; rewritten parts keep their charset (lossless round trip required, else skipped) and transfer encoding (7bit/8bit switches to quoted-printable only when a line would exceed 998 octets).
3. **Signed and encrypted mail:** S/MIME, PGP/MIME, inline PGP and encrypted messages are skipped entirely with a reason code. DKIM-signed mail is rewritten by default (the gateway already authenticated it; downstream must trust the gateway), or skipped per tenant policy; ARC sealing is a follow-up.
4. **Token:** 46 bytes base64url (62 characters): version, key id, organization id, message id, `received_at` (ms), URL sequence, expiry (s), and a 128-bit truncated HMAC-SHA256 over the rest. Two key slots (current, previous) for rotation. The token carries no URL and no tenant name; the original URL is looked up server side and never trusted from the token. Expiry per tenant, at most 90 days.

**Alternatives considered.** A rewrite stage after approval (an extra queue and lifecycle edge for data the engine already has); rewriting during reinjection (token keys and URL tables in the delivery-worker, repeated on retries); SMTP-time rewriting (before scanning and storage); AEAD tokens (longer, nonce management, no benefit); random tokens with a lookup table (a database hit before any validation); URLs inside tokens.

**Consequences.** One extra S3 object per rewritten round; orphans from duplicate attempts expire by lifecycle. Tokens of one rewritten copy are shared by every recipient, so clicks cannot be attributed to a user. Rotating keys more often than the maximum expiry breaks old links.

**Implementation notes (step 4.3, recorded in [§12](../../plan/steps/11-url-protection.md#12-deviations-log)).** The rewriter uses mailsplit's `Splitter`/`Joiner` with its own transform for the selected leaves (mailsplit's `Rewriter` re-encodes every node as quoted-printable, which would break "original transfer encoding kept"; WP2 deviation 2). The approver's echo-checked read of the round's `url_rewrites` row also matches the scan id of the `scanned.v1` event and refuses keys with `.`/`..`/empty segments (falls back to the original); `delivery_approvals_total{source, object}` is counted by the planner from the key prefix, so every approval producer is counted the same way (WP5).
