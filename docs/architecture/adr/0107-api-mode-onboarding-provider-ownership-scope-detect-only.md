# ADR-0107: API-mode onboarding: ownership through a bound provider tenant, mailbox scope and the detect-only start

**Status:** Accepted (2026-11-27, local verification: stack suite `api-mode-parity.test.ts` 11/11 — a pending second domain listed as verified in the provider-fake tenant of the bound Microsoft 365 connection verified through `POST /domains/{id}/ownership/provider-check` (integration-worker check, api scheduler win, `ownership_method = provider_tenant`, audit `domain.verified` with the method, no TXT verification row), an unlisted domain's check `failed` with `absent` and the domain still pending; a `mailboxes` scope evaluated by the health leader; both detect-only expiries (remind: one alert, mode kept; enforce: switched with audit and alert); the onboarding view `waiting` with the `journal_source_missing` hint, then `received`; protection-coverage totals and gaps; api, integration-worker and portal suites of WP4–WP6; live provider tenants, CI and Kubernetes apply pending); proposed by the step API-4 architect, 2026-11-27. **Context.** PO-D1 (decided 2026-11-27, note 35 §17 feedback): the API-mode wizard should hide inapplicable steps, show only the TXT ownership record or verify ownership automatically through the connected provider tenant, and add mailbox-scope and threat-action steps. Step 2.1 D4 and 8.2 I6 keep gateway ownership TXT-only; ADR-0076 (1) binds a tenant on TXT-verified, gateway-`active` linked domains; links need `active`; ADR-0098 (3) defines the API-1 wizard.

**Decision.**

1. **Supersedes step 2.1 D4 / 8.2 I6 in part:** a pending domain may be proven by its verified listing (verified for Email) in a provider tenant **already bound** to the organization, checked by the integration-worker with the read-only mail-flow grant and won by the api's existing first-to-verify-wins transaction (`domains.ownership_method = provider_tenant`).
2. **Supersedes ADR-0076 decision 1 in part:** tenant binding counts only DNS-TXT-proven linked domains, in `verified` or `active` status; links accept `verified` domains.
3. Per-domain mailbox scope (`all`, policy-directory departments, selected mailboxes); out-of-scope mailboxes are recorded but not remediated or fed.
4. Remediation policies may carry a detect-only period with a reminder (default) or an automatic switch to enforce; the wizard defaults to 7 days detect-only with a reminder.
5. **Supersedes ADR-0098 decision 3:** mode-specific wizard step lists (inline unchanged; api hides inapplicable steps; hybrid = inline + API steps) with a server-computed onboarding state and a live first-copy check.

**Consequences.** Second and later domains of a bound tenant onboard without DNS changes; ownership remains globally unique and auditable; tenants can stage protection.

**Alternatives considered.** Unbound-tenant listings; provider-group scopes; auto-enforce by default; a stored wizard pointer (design §7).
