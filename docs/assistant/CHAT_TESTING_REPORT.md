### Fixes made after review (AI-2, 2026-11-21)

- **Outcome-unknown sweep vs a running confirm** (medium): the sweep could fail a confirmation whose precondition re-read (up to 25 reads) was still running, after which the write still ran. Now the confirm claims the write (`execution_started_at`, migration `20261120223558_ai_assistant_confirmation_execution_started`) right before sending it; the sweep measures a started write from that column (timeout + 60 s) and an unstarted one from `decided_at` (26 × timeout + 60 s); a swept row loses the claim (`409`, nothing sent); a write that outlives the sweep replaces `outcome_unknown` with its real outcome (audit `reconciledFrom`). Tests: `confirmation.service.test.ts` (3 new), `confirmation-turns.test.ts` (both phases), `assistant-confirmations` sweeper test (both phases).
- **Replica lag hid changed state** (medium): the precondition GETs now carry `x-eg-assistant-read-primary`, so the routes read the MySQL writer (`runReadsOnWriter`). Tests: `read-primary.test.ts`, `loopback-client.test.ts` (2 new), `prisma-read.service.test.ts` (1 new), the proposer assertions, and the integration test `replica lag …` in `assistant-writes-mail-ops` (REPEATABLE READ snapshot as a lagging replica; fails without the fix).

### Fixes made after review round 1 (AI-1, 2026-11-21)

Details and the check results are in [the design note §13.2](../plan/steps/28-ai-chat-management.md#132-review-round-1-fixes-2026-11-21).

- **Retention:** a conversation used again after its content purge is purged again. Each turn sets a new `purge_after` and clears `content_purged_at`. The job re-checks candidates under a row lock. Lowering `retentionDays` moves existing purge dates earlier. Covered by unit tests and `apps/api/integration/assistant.test.ts`.
- **Loopback:** path parameter values `.`, `..` and `''` are refused (`denied_schema`). The built path must match the tool template, and the client refuses a path that URL resolution would change. Covered by `loopback-client.test.ts` and `tool-executor.service.test.ts`.
- **Untrusted data:** the evidence and explanation of ATO signals and the incident evidence, detail and notes are wrapped as `untrusted_text`. The generator now marks every free-form response value as untrusted, and the registry test fails if one is left uncovered. Registry version `fecb031f3ad52d84` → `30777563d395518a`. Covered by `results.test.ts` and `registry.test.ts`.
