# Rspamd deployment (step 4.1)

How the inbound Rspamd is deployed and configured: its two roles (SMTP-time milter and post-queue scan engine), the milter policy and failure mode, every `RSPAMD_*` key, production feeds, Redis, DNS, training operations, memory and local verification. Design and decision ids (S*n*): [docs/plan/steps/09-rspamd.md](../plan/steps/09-rspamd.md). Decisions: [ADR-0026](../architecture/adr/0026-security-scan-pipeline.md) (scan pipeline) and [ADR-0027](../architecture/adr/0027-rspamd-milter-policy.md) (milter policy). The outbound DKIM signer `rspamd-outbound` is a separate instance, unchanged by this step ([smtp-gateway.md](smtp-gateway.md#dkim-signer-and-redis-dkim-isolation-d12-adr-0020)).

## Topology

```
 Internet ──25──▶ postfix ──milter 11332 (SMTP time, ADR-0027)──▶ rspamd (proxy worker, self_scan)
                     └──LMTP──▶ smtp-adapter ──▶ S3 (EML) + MySQL ──▶ email-worker (MIME, then scan role)
 email-worker scan role ──POST /checkv2 11333 (EML streamed + trusted envelope)──▶ rspamd (normal worker)
 email-worker ──GET /stat 11334 (read password)──────────────────────────────────▶ rspamd (controller)
 api platform training ──/learnspam|/learnham|/fuzzyadd|/fuzzydel 11334 (enable password)──▶ rspamd
 rspamd ──▶ Redis DB RSPAMD_REDIS_DB (Bayes, fuzzy storage, reputation, history, ratelimit)
 rspamd ──▶ DNS resolver (RSPAMD_DNS_SERVERS; locally/CI dns-sink, scan.test zones)
```

| Worker         | Listen            | Count                       | Purpose                                                                                                                           |
| -------------- | ----------------- | --------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `rspamd_proxy` | `*:11332`         | 1                           | Milter of the inbound Postfix, scans in-process (`self_scan`), `timeout = 25s` (below Postfix's `milter_content_timeout = 30s`)   |
| `normal`       | `*:11333`         | `RSPAMD_NORMAL_WORKERS` (1) | `/checkv2` of the post-queue scan (no authentication: internal networks only)                                                     |
| `controller`   | `*:11334`         | 1                           | `/stat` (read password), learning and fuzzy (enable password). Loopback (`secure_ip`) needs no password: the Compose health check |
| `fuzzy`        | `127.0.0.1:11335` | 1                           | Local fuzzy storage, Redis backend, updates only from loopback (the controller), `expire = 90d`, `sync = 5s`                      |

Both roles use **one** Rspamd configuration: SMTP time and post-queue see the same rules and the same scores. Per-tenant thresholds apply only post-queue, in the email-worker's mapping (S7/S8). Production can run the two roles as separate pools of the same image and configuration (the milter pool sized for SMTP concurrency, the scan pool for `scan.spam` throughput); locally one container serves both.

## Milter policy and failure mode (ADR-0027)

- **Reject only on very high confidence.** `actions.conf` (rendered into `override.d`): `reject = RSPAMD_MILTER_REJECT_SCORE` (default 15), `add_header = null`, `rewrite_subject = null`, `greylist = null`, no `soft_reject`. GTUBE is rejected in-session with `554 5.7.1 Gtube pattern`; other rejects use the proxy's `reject_message` (`5.7.1 Message rejected as spam`). The post-queue reply therefore only ever carries `no action` or `reject` (or `soft reject` when Rspamd could not finish, which the client turns into an attempt failure); the email-worker's mapping uses its own thresholds.
- **DMARC `p=reject` at SMTP time** only with `RSPAMD_MILTER_DMARC_REJECT=true` (renders `dmarc.conf` `actions { reject = "reject"; }`). This is platform-wide and also makes the post-queue reply's action `reject` for those messages (mapped to `spam.reject_action`).
- **Headers.** Forged result headers are removed first by **Postfix cleanup**, independently of the milter (ADR-0027 decision 3, review round 2): `main.cf` `header_checks = regexp:/etc/postfix/header_checks`, rendered by the Postfix entrypoint from `POSTFIX_MYHOSTNAME` and `RSPAMD_AUTHSERV_ID` (`IGNORE` for `Authentication-Results` whose authserv-id, after an optional comment, is ours; `/^X-Spam/`; `/^X-Rspamd-/`). This also holds while Rspamd is down and the milter fails open (`scan-smtp.test.ts` stops Rspamd and checks the stored EML). `header_checks` do not apply to milter-added headers, so the milter's own `Authentication-Results` is kept. As a second layer, the custom routine `eg-strip-forged` (rendered `milter_headers.conf`) removes every inbound `X-Spam*`, `X-Spamd-*` and `X-Rspamd-*` header and the `Authentication-Results` headers carrying our authserv-id (`RSPAMD_AUTHSERV_ID`, case-insensitive). The `authentication-results` routine then adds exactly one `Authentication-Results` (SPF, DKIM, DMARC, ARC). No score or spam headers are added. Rspamd takes the authserv-id of the added header from the MTA name Postfix sends (macro `j` = `myhostname`), so `RSPAMD_AUTHSERV_ID` must equal `POSTFIX_MYHOSTNAME` (the Compose default). `skip_local` and `skip_authenticated` are off: forged headers are removed from every client.
- **Failure mode.** `infrastructure/postfix/main.cf`: `milter_default_action = accept`, `milter_connect_timeout = 10s`, `milter_command_timeout = 10s`, `milter_content_timeout = 30s`, `milter_protocol = 6`, macros `j {daemon_name} {daemon_addr} v _ {client_addr} {client_name}` (connect), `i {auth_type} {auth_authen} {auth_author} {mail_addr} {mail_host} {mail_mailer} {client_addr} {client_name}` (MAIL), `i {rcpt_addr} {rcpt_host} {rcpt_mailer}` (RCPT), `i` (end of data). When Rspamd is down or slow, Postfix logs `warning: connect to Milter service inet:rspamd:11332: …` and **accepts**; the message is stored and scanned post-queue, where an unavailable Rspamd yields `timeout`/`error` attempts, retries and finally `scan_failed`, never `clean` (invariant §2.0-1). The policy service (smtp-adapter) still fails closed.

Verified locally (2026-11-05, Rspamd 3.12.1, Postfix 3.7): GTUBE through `postfix:25` → `554 5.7.1 Gtube pattern`; the clean fixture → `250 2.0.0 Ok: queued`; with `rspamd` stopped both the clean and the GTUBE message → `250 2.0.0 Ok: queued` (milter skipped); a message with one forged `Authentication-Results: mx.gateway.local; …` between two foreign ones is stored with ours on top, the forged one removed and both foreign ones kept; with two forged ones every inbound `Authentication-Results` is removed (see deviations).

## Production feeds (configuration, not code)

None of these can be verified locally (no Internet DNS in the test stack); they are rendered from configuration only.

- **Spamhaus DQS** (`RSPAMD_RBL_PROFILE=production`, `RSPAMD_SPAMHAUS_DQS_KEY`): `spamhaus` (zen: `RBL_SPAMHAUS_*`, `RECEIVED_SPAMHAUS_*`) and `DBL` (`DBL_SPAM`, `DBL_PHISH`, `DBL_MALWARE`, `DBL_ABUSE_*`, …) query `<key>.zen.dq.spamhaus.net` / `<key>.dbl.dq.spamhaus.net`; `SPAMHAUS_ZRD` (`RBL_SPAMHAUS_ZRD`, zero-reputation domains) queries `<key>.zrd.dq.spamhaus.net`. Spamhaus refuses queries from public/shared resolvers, so the public mirrors (used without a key) only work behind your own recursive resolver and within the free-use terms.
- **SURBL, URIBL, mailspike, DNSWL, SEM, MSBL** stay as Rspamd ships them in the production profile (`SURBL_MULTI` → `PH_SURBL_MULTI`, `MW_SURBL_MULTI`, …; `URIBL_MULTI` → `URIBL_BLACK`, …; `RBL_MAILSPIKE_*`). Commercial feeds need their own keys; add them as extra `rbls` entries in a deployment-specific `local.d/rbl.conf` (mount) without changing code. The email-worker's symbol catalog already classifies the standard names.
- **OpenPhish / PhishTank** (`RSPAMD_PHISH_FEEDS=true`): `PHISHED_OPENPHISH`, `PHISHED_PHISHTANK` from Rspamd's default feed URLs (OpenPhish premium needs `openphish_premium` and a feed URL in a deployment override).
- **Known-bad URL feed** (`RSPAMD_BAD_URL_MAP_URL`): an HTTPS map with one host per line, exact host match, polled by Rspamd's map watcher (`map_watch_interval = 5min`); the local file stays loaded as well. Symbol `EG_BAD_URL` (10.0).
- **Public fuzzy storage** (`rspamd.com`): not configured. To enable, add a second `rule` to a deployment `override.d/fuzzy_check.conf` (it shares hashes of scanned mail with a third party; a privacy decision).

## DNS: a recursive resolver is required

Rspamd needs a local, caching, recursive resolver it may use for blocklist queries at volume (Unbound/BIND on the node or in the VPC, not the VPC's AmazonProvidedDNS and not a public resolver; DNSBLs block both). Set `RSPAMD_DNS_SERVERS` to it. With `RSPAMD_DNS_SERVERS` set, Rspamd's own resolver cannot resolve Compose/Kubernetes service names, so the entrypoint resolves the Redis host itself (`getent ahostsv4`) and writes the address; a Redis address change then needs an Rspamd restart (in production use a stable endpoint, e.g. the ElastiCache primary endpoint resolved by the node resolver, or leave `RSPAMD_DNS_SERVERS` empty and point the container resolver at the recursive resolver).

Locally and in CI `RSPAMD_DNS_SERVERS=172.31.250.53` (dns-sink on `mailtest`, `rspamd` at `172.31.250.11`): Rspamd resolves the `scan.test` test zones and nothing else (all other names are `REFUSED`, so map downloads from `maps.rspamd.com` fail and are logged; cached copies in the `rspamd-data` volume are used when present). Without the `smtp-test` profile there is no resolver at all: Rspamd still scans, SPF/DKIM/DMARC end in `*_DNSFAIL` (temperror).

## Redis and sizing

Rspamd keeps Bayes tokens (`RS*`), fuzzy hashes (`fuzzy*`), reputation buckets (`RR:*`), history (`rs_history*`, 1000 rows, compressed, subjects hashed) and ratelimit buckets in `RSPAMD_REDIS_DB`. Locally that is DB 1 of the shared `redis` (AOF, `noeviction`); **production uses a dedicated Redis** (ElastiCache replication group, encryption in transit, AUTH; with `noeviction` alert well before `maxmemory`, or choose `volatile-lru` knowing that only TTL-bearing keys (reputation, history, fuzzy) are evicted and Bayes tokens are not). Rough sizing: Bayes with OSB tokens grows with distinct learned text (plan 0.5-2 GiB for a few hundred thousand learned messages); fuzzy hashes ~100-200 bytes each, expiring after 90 days; reputation and history are bounded by TTLs and `nrows`. Monitor `used_memory` and evictions; Bayes expiry (`bayes_expiry`, Rspamd default) trims unused tokens.

## Fuzzy storage and Bayes operations

- **Who:** platform administrators only, through the api route `POST /api/v1/platform/organizations/{organizationId}/messages/{messageId}/scan-training` (S13; permission `platform:scan_training`). The api streams the EML from S3 to the controller with the enable password through `@email-gateway/rspamd` (`learn('spam'|'ham')`, `fuzzy('add'|'delete', flag, SCAN_FUZZY_WEIGHT)`). Bayes and fuzzy state are shared by all tenants (hence no tenant training).
- **Bayes:** explicit learning only (`autolearn = false`). Controller replies verified on 3.12.1: `200 {"success":true}` learned; `208` "already learned as <class>" (same message digest); `204` skipped by Rspamd's learn condition because the classifier already puts the message in that class with >= 95 % probability. The client reports both 208 and 204 as `already_learned`. Learning the other class for the same message relearns it (`200`). Classification starts after `min_learns` per class.
- **Fuzzy:** flags 11 (`EG_FUZZY_SPAM`, 10.0) and 12 (`EG_FUZZY_PHISH`, 12.0); the symbol's score is scaled by the stored weight (`max_score = 20`). `200 {"success":true,"hashes":[…]}` for add and delete (delete is idempotent); `404 "No content to generate fuzzy for flag N"` when the message has no part long enough to hash (`min_bytes = 1k`, shingles from 64 words); `404 "No fuzzy rules matched for flag N"` for an unknown flag. Changes reach scans after the storage's `sync` (5 s). Hashes expire after 90 days.
- **Manual checks** (from the host; passwords from `.env`, never echo them): `curl -s -H "Password: …" http://127.0.0.1:${RSPAMD_CONTROLLER_HOST_PORT}/stat` (read password) shows `learned` and the version.

## Memory settings

Compose: `mem_limit: 768m`, one proxy, one normal worker, one controller, one fuzzy worker; `neural`, `clickhouse`, `elastic`, `metric_exporter`, `rspamd_update`, `url_redirector`, `asn`, `external_services` disabled. Hyperscan caches live in the `rspamd-data` volume (first start compiles them, later starts reuse them). Production: start with 1-2 GiB per pod and `RSPAMD_NORMAL_WORKERS` ≈ vCPUs for the scan pool; `task_timeout = 15s` bounds a single scan, the email-worker's `SCAN_RSPAMD_TIMEOUT_MS = 20000` bounds the call.

## Deviations from the step 4.1 design

| Decision                      | Design                                                                  | Implemented, and why                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ----------------------------- | ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| S7 R1 / S9 GTUBE              | `is_skipped = true` → `unknown` (`engine.skipped`)                      | Rspamd 3.12 answers GTUBE with `is_skipped: true` **and** `passthrough_module: "GTUBE"` (score 15, action `reject`). `normalizeReply` returns `skipped = is_skipped && !passthrough_module` and `passthroughModule`; the email-worker mapping must use the normalized `skipped` so GTUBE reaches R4 (`spam.gtube`). Invariant 1 holds: a real skip is still `unknown`.                                                                                                                                                     |
| S9 `check()`                  | returns `RspamdCheckReply`                                              | returns `RspamdCheckResult { reply, serverVersion, rcptTruncated, omittedHeaders, durationMs }` (the version comes from the `Server` header Rspamd 3.12 sends, so the worker needs no `/stat` call per scan; truncation must reach `evidence.rcptTruncated`).                                                                                                                                                                                                                                                              |
| S9 SPF domain                 | parsed from symbol options                                              | `R_SPF_*` options carry the matched mechanism (`-all`, `+ip4:…`), never the domain. `normalizeReply(reply, { envelopeFrom, helo })` takes the checked domain from the trusted envelope (HELO for the null sender, RFC 7208 §2.3); without the context the domain is null.                                                                                                                                                                                                                                                  |
| S9 `Rcpt` headers             | one `Rcpt` header per recipient                                         | Node's fetch joins repeated headers into one `Rcpt: a, b` (Fetch standard); verified that Rspamd 3.12 splits it into the same recipient list. Recipients containing a comma (quoted local parts) are omitted and flagged in `omittedHeaders`.                                                                                                                                                                                                                                                                              |
| S13 learn results             | `learned` / `already_learned`                                           | Besides `208`, Rspamd answers `204` when its learn condition skips a message already >= 95 % in the class; both are `already_learned`.                                                                                                                                                                                                                                                                                                                                                                                     |
| S11 headers                   | `use = ["authentication-results", "remove-spam-flag"]` + remove options | Rspamd's `milter_headers` removes headers by exact name only, so a `custom` routine `eg-strip-forged` removes `X-Spam*`, `X-Spamd-*`, `X-Rspamd-*` and our forged `Authentication-Results`. The milter path takes **one** index per header name: one forged A-R is removed by index (foreign ones kept, verified); two or more forged ones remove every inbound A-R (none is trusted downstream). The added A-R's authserv-id is Postfix's `j` macro, so `RSPAMD_AUTHSERV_ID` must equal `POSTFIX_MYHOSTNAME`.             |
| S12 files                     | everything in the tmpfs `local.d`                                       | Rspamd merges `local.d` into the defaults, which cannot remove the public fuzzy rule, the default RBL list or the default `local_addrs` entries; those files (and `actions.conf`, `redis.conf`, `worker-controller.inc`) are rendered into a second tmpfs `/etc/rspamd/override.d`. The whole `infrastructure/rspamd` directory is mounted read-only at `/opt/rspamd`.                                                                                                                                                     |
| S12 `EG_DISPLAY_NAME_ADDRESS` | multimap regexp/selector                                                | A multimap cannot compare the display name's domain with the From domain; Rspamd 3.12 already computes exactly that (`FROM_NEQ_DISPLAY_NAME`, `SPOOF_DISPLAY_NAME` when the display domain is a recipient domain). `EG_DISPLAY_NAME_ADDRESS` is a composite of the two (score 3, `policy = "leave"`).                                                                                                                                                                                                                      |
| S12 `EG_BAD_URL`              | `filter host`                                                           | 3.12 has no `host` filter; without a filter the url multimap matches the exact URL host (`bad-url.scan.test`, not its subdomains). URLs on the non-public TLD `.test` are only extracted from HTML links, so the known-bad-URL fixture is HTML.                                                                                                                                                                                                                                                                            |
| S12 test RBL/DBL              | `EG_TEST_RBL`, `EG_TEST_DBL`                                            | As designed; `EG_TEST_DBL` uses `url_full_hostname` (the eSLD of a `.test` host would be `scan.test`) and checks URLs, body addresses, DKIM domains and Reply-To. Without returncodes the rule name is the symbol.                                                                                                                                                                                                                                                                                                         |
| S12 reputation                | rules with Rspamd native settings                                       | Rspamd registers the reputation symbols without scores; `groups.conf` gives conservative weights (`IP_REPUTATION_SPAM` 1.0 / `_HAM` -0.5, `SPF_REPUTATION_SPAM` 0.5 / `_HAM` -0.25, `DKIM_REPUTATION` 0.5, `SENDER_REP` 0.5) and the DKIM rule `max_accept_adjustment = 0.5` (default 2.0), so learned reputation nudges a score by about ±2.5 at most. The `generic` and `dkim` rules insert single signed symbols (`SENDER_REP`, `DKIM_REPUTATION`), not `_SPAM`/`_HAM` pairs (the design's R9 names `SENDER_REP_SPAM`). |
| S12 fuzzy worker              | —                                                                       | `sync = 5s` (default 60 s) so administrator training is visible within seconds.                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| S12 controller                | hashed with `rspamadm pw -q -p`                                         | As designed; `rspamadm pw` takes the password only as an argument (no stdin), so it is visible in the container's own process list for the duration of the command. The rendered file holds hashes only.                                                                                                                                                                                                                                                                                                                   |
| S12 `settings.conf`           | `eg_outbound`: no RBL on `from`, no hfilter HELO checks                 | With `User` set Rspamd already skips IP RBLs (`exclude_users`), SPF and hfilter; `eg_outbound` additionally disables the `HFILTER_HELO_*` symbols for requests without `User` (verified both).                                                                                                                                                                                                                                                                                                                             |
| S12 production RBL            | DQS zen/dbl/zrd, SURBL, URIBL, mailspike rendered with the key          | Without a DQS key the production profile keeps Rspamd's default list (public Spamhaus mirrors included); with the key `spamhaus` and `DBL` switch to DQS and `SPAMHAUS_ZRD` is added. Not verifiable locally.                                                                                                                                                                                                                                                                                                              |
| §5 keys                       | —                                                                       | Added `RSPAMD_NORMAL_WORKERS` (named in S12, missing in §5). `RSPAMD_LOCAL_ADDRS` default written `127.0.0.0/8,::1` (no space, so `.env` stays shell-friendly; both forms are accepted).                                                                                                                                                                                                                                                                                                                                   |
| §9 corpus                     | at least the listed fixtures                                            | Two more: `spoofed/dmarc-quarantine.eml`, `header-anomaly/display-name-address.eml`. Every sender/recipient domain is under `scan.test` so lookups are answered (NXDOMAIN or records) instead of refused. `expect.scoreRange` is the verdict-preserving interval (reputation drift), not a margin around one score.                                                                                                                                                                                                        |
