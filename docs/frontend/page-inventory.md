# Admin portal page inventory (step 7.1)

The 22 pages and 12 dashboard widgets of the admin portal as built and verified in step 7.1 ([design note](../plan/steps/20-admin-portal.md) §1.3/§1.4, [verification record](../plan/steps/20-admin-portal.md#14-verification-record)). Operation ids omit the `_v1` suffix. **Gate** is the `x-eg-permissions` of the primary operation(s): the page and its navigation entry are shown when the user may call **any** of them; the api stays authoritative (every write is checked again). **Real** means every row and number comes from the listed operations; **Unavailable** names the state the page shows instead of a missing feature and the step that delivers it.

Verified end to end on 2026-11-13 by `tests/portal-e2e` (Playwright, real api, MySQL writer/replica, Redis, MinIO; [running and testing](running-and-testing.md)): every page below rendered seeded data with no error state and no serious or critical axe violation as `organization_admin` (and `platform_admin` / `mailbox_user` where relevant), and the unavailable states are present.

Routes without a navigation entry: domain onboarding (from Domains), email details and scan details (from the explorer and alert links), entry, approval and release details (from Quarantine and digest links), webhook details (from Integrations and alert links). Links the platform sends by e-mail and that the portal serves: `/messages/<id>`, `/domains/<id>`, `/webhooks/<id>`, `/quarantine`, `/quarantine/me`, `/quarantine/me/<entryId>`, `/quarantine/approvals/<approvalId>`, `/quarantine/releases/<releaseId>`, `/auth/reset-password`, `/auth/accept-invitation`, `/auth/verify-email`.

Foreign and unknown ids look the same: the shared "Page not found" page (domains, users, webhooks, roles) or the page's 404 error state with the api's `*_not_found` code (messages, quarantine entries and approvals); the isolation spec asserts that a beta id and a random id render the same state for an alpha user.

## Dashboard widgets

One range for all widgets (24 h hourly, 7 d daily (default), 30 d daily, or custom whole UTC days ≤ 31). Each tile loads on its own and shows `generatedAt`; the reports are cached per organization by the api (`REPORTS_CACHE_TTL_SECONDS`).

## What later steps add

- **7.2 Email Explorer and Email Details:** saved views and column sets, side panel, bulk actions (rescan, release), export, custom ranges in the explorer; details tabs (recipients, deliveries, lifecycle history, policy evaluations, risk breakdown, header and authentication results); the audited DLP evidence view; any api additions it needs (e.g. `sort` on the v0 lists users, domains and quarantine entries).
- **7.3 Visual policy builder:** the builder over the DSL catalogue, test and dry-run, draft / publish / activate / enable / disable, risk-profile drafts. Whether DLP and BEC configuration editing belongs to 7.3 is an open product-owner question (the api exists; 7.1 shows read-only lists).
- **8.1** archive, journaling and retention pages (Settings `archive` tab, Integrations archive card); **8.2** Microsoft 365 / Google Workspace connectors (Integrations); **8.3** the deployment manager (Organizations).
