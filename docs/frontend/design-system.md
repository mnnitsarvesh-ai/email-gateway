## Principles

1. **Real data or an honest state.** Every number comes from an API operation. Missing data is an `EmptyState`; missing features are an `UnavailableState` naming the step; failures are an `ErrorState` with the `requestId`. Never a placeholder number, never an estimate, never "—" pretending to be a value.
2. **Security data is dense; keep it calm.** Neutral surfaces, one accent (primary blue), colour reserved for meaning (verdicts, severities, states). Colour is never the only cue: badges carry text, charts carry text legends and a table.
3. **The API is authoritative.** The UI hides what a user cannot do (`<Can>`, `<RouteGate>`), but every rule is enforced by the API; a `403` from the API is rendered, not swallowed.
4. **Accessible by construction.** WCAG 2.2 AA: contrast is tested on the tokens, components are keyboard operable and labelled, and every page test runs axe.

## Typography

- **Inter Variable** for the UI and **JetBrains Mono Variable** for ids, hashes, header values, codes and secrets; both self-hosted from `@fontsource-variable/*` (no external font requests).
- Scale (`text-*`): 12/16 (`xs`), 13/18 (`2xs`), **14/20 (`sm`, body default)**, 16/24 (`base`), 18/26 (`lg`), 20/28 (`xl`), 24/32 (`2xl`), 30/36 (`3xl`). Page title `text-2xl font-semibold`; section title `text-lg font-semibold`; card title `text-base font-semibold`; table text `text-sm`; captions and meta `text-xs text-muted-foreground`.
- Numbers use `tabular-nums` (table cells do by default). Format counts with `formatNumber` (`Intl.NumberFormat`, browser locale); percentages with one decimal; durations with `formatDuration` (`ms`, `s`, `min`).
- Never use colour alone to carry emphasis; use weight or an icon with a label.

## Spacing, radius, elevation, motion

- 4 px grid (Tailwind spacing). Page padding `px-4 md:px-6 lg:px-8`, section gap `gap-6`, card padding `p-4 md:p-5`, form field gap `gap-4`.
- Radius: `rounded-sm` 6 px (badges, inputs inside tables), `rounded-md` 8 px (buttons, inputs), `rounded-lg` 10 px (cards, dialogs), `rounded-xl` 14 px (hero panels only).
- Elevation: `shadow-xs` (cards), `shadow-sm` (popovers, menus, sticky headers), `shadow-lg` (dialogs, drawers). Dark mode relies more on surface steps than shadows.
- Motion ≤ 200 ms (`--motion-fast` 120 ms for hover/press, `--motion-base` 200 ms for overlays); everything is disabled under `prefers-reduced-motion: reduce` (global rule in `globals.css`).
- Density: table rows 36 px (compact, default) or 44 px (comfortable toggle in the DataTable toolbar). Interactive targets are at least 24 × 24 px (WCAG 2.5.8); icon buttons are 32 px (`size="icon"`), 36 px in toolbars.

## Tables

`DataTable` (`src/components/data-table/`) wraps TanStack Table for server-side cursor lists:

- **Data:** pass the result of `useCursorList(operationId, filters)`. It reads `data` or `items` (the 5.3 quarantine lists), handles cursor v0 and v1, keeps a cursor stack (Previous pops it), resets to page 1 on any filter change, and shows "Page N · R rows" (no totals exist). A short page with a `nextCursor` (scan budget) shows "More results may exist further back — Load next page".
- **Filter bar:** `filters` slot (render `Select`/`Input` bound to `useUrlState`), `search` (debounced 300 ms, written to the URL), "Clear filters".
- **Sort:** only when the operation declares `sort` (`operations[id].sort`); the header button cycles through the allowed values only. v0 lists have a fixed order and show no sort control.
- **Columns:** `ColumnDef<Row>[]` with `meta: { label, hideable?, className? }`; a column visibility menu persisted per `tableId` in `localStorage` (guarded by try/catch; nothing else of the table is persisted). A page that applies column sets itself (saved views, step 7.2) passes `columnVisibility` + `onColumnVisibilityChange` (controlled) and persists with `readColumnVisibility(tableId)` / `writeColumnVisibility(tableId, v)` (the same preference key). Give wide-text columns a minimum width (`min-w-48`) so they do not collapse to a few characters next to badges; the table scrolls inside its container instead.
- **Rows:** `rowActions(row)` renders a `DropdownMenu` per row; `enableSelection` adds checkboxes and the `bulkActions(selectedRows)` slot (selection is per page and cleared on page change).
- **Responsive:** sticky first column and horizontal scroll inside the container at tablet; `mobileCard(row)` renders a stacked card per row below 768 px (required for every table used on mobile). The scroll container is a named, focusable group (`role="group"`, `tabIndex=0`, labelled by the caption) and `position: relative`: a wide table must be keyboard-scrollable even without links in its cells (axe `scrollable-region-focusable`), and absolutely positioned descendants (the copy button's live region) must not escape the scroller and widen the page (step 7.2 WP5; the details `DataGrid` follows the same rule).
- **States:** skeleton rows while loading, `EmptyState` (or the filtered-empty variant), `ErrorState` with `requestId`; previous data stays visible while the next page loads. `errorState(error)` may return a custom body for an error the page explains elsewhere (the explorer shows `422 message_search_too_broad` / `503 message_search_timeout` next to its search and "The search was refused" in the table); returning `null` keeps the `ErrorState`.
- **List query options:** `useCursorList(op, filters, { queryOptions: { refetchOnWindowFocus, staleTime, retry } })` (step 7.2; the explorer turns off focus refetches and never retries a refused search).
- **Accessibility:** a real `<table>` with a visually hidden `<caption>`, `aria-sort` on sorted headers, `aria-busy` while fetching, row action buttons named after the row.

## Detail pages with many sections (step 7.2)

The Email Details page (`src/features/messages/details/`) is the pattern for a detail page with many independently loaded sections:

- **Sections in the URL** (`?section=<id>`, zod `catch` to the default) with a definition table (`sections.ts`: id, label, the operations whose `x-eg-permissions` gate it, extra permissions, whether it is scoped to a scan round). A section is listed only when the user passes its gate; a direct `?section=` without it renders `SectionForbidden` (the permissions it needs; nothing is fetched).
- **Responsive section navigation** (`section-nav.tsx`): vertical Radix `Tabs` (`orientation="vertical"`) at ≥ 1280 px, a horizontally scrollable tab list at 768–1279 px, a labelled native `<select>` below 768 px. `activationMode="manual"`: arrow keys move focus without loading a section; Enter/Space opens it. Section changes push a history entry.
- **Only the active section is mounted**, so only its queries run; shared reads (the detail, the scans page) are deduplicated by TanStack Query. Round-scoped sections share one `RoundScope` (`useCursorList` of the scans) that stays mounted while the user moves between them, with `RoundPanel` rendering the round selector (`?round=`, newest by default, older pages through the cursor) and the honest "no rounds yet" / "round not loaded" states.
- **Per-page reveal state** (`useMessageReveal`, `MessageRevealContext`): one audited reveal call fills the page's masked values (subject, header values by `seq`, recipients by `rcptSeq`; sections read them through `useRevealed()`), "Reveal more recipients" continues with the reveal cursor, `aria-live` announces each reveal, "Hide again" and unmounting forget everything; the mutation is reset and removed from the mutation cache after each call.
- **Audited or secret reads on demand only:** the quarantine entry detail loads when its card is expanded (`refetchOnWindowFocus: false`); the sanitized preview after an explicit click with `PREVIEW_QUERY` (`staleTime: Infinity`, `gcTime: 0`, no refetch on focus, mount or reconnect); the DLP evidence in a dialog mounted only while open (`gcTime: 0`, removed from the cache on close, `403 mfa_required` raises the MFA dialog).
- **Reuse of feature actions:** the quarantine feature exports `useEntryActions`, `EntryActionButtons`, `OperatorDialogs` (reason dialogs, Idempotency-Key per intent, reload after a `409` row-version or state conflict), `EntryHistory` and `PreviewSection`; other pages compose them instead of re-implementing the flows.
- Small presentational helpers of the feature (`parts.tsx`): `DataGrid` (a captioned table for engine results), `Block`, `NoData` (an honest absent-data sentence, never an invented number) and `QueryBoundary`.

## Forms

- `react-hook-form` + `zod` (v4) with `zodResolver`. One schema per form in the feature folder, a **strict** object (`z.object({...}).strict()`) mirroring the operation's request schema. Every form has a test calling `expectRequestMatchesContract(operationId, body)` on its output.
- Submit through `useApiMutation(operationId)`: `submit(input)` resolves to `{ ok: true, data }` or `{ ok: false, error }` (it never throws); one `Idempotency-Key` per submission, reused by `retry()`; replays toast "Already applied"; `429` disables the submit button with a countdown (`retryAfterSeconds`); `403 mfa_required` opens the MFA dialog.
- Errors: `applyApiErrors(form, error)` maps `400 validation_failed` lines (`"<path>: <issue>"`) to fields and puts the rest, and every other `4xx` message, in a `FormErrorSummary` at the top of the form (`role="alert"`). Field errors use `FormMessage` (`aria-describedby`, `aria-invalid`).
- Labels are visible (no placeholder-only fields); required fields are marked "(required)" in text; helper text under the field; passwords show the policy (12–128 characters) and a show/hide toggle.
- Destructive submits go through `ConfirmDialog`.

## Charts

Recharts wrapped in `src/components/charts/`; never use Recharts directly in a page.

- `ChartFigure` renders `<figure>` with a `<figcaption>` (title + description), the chart in a container with `role="img"` and an `aria-label` built from a computed summary (total, peak, trend), a "View data as table" toggle that renders a real `<table>` with a `<caption>`, and text legends. The chart region is focusable; arrow keys move the active point and the tooltip follows (keyboard reachable).
- Wrappers: `TimeSeriesChart` (line or stacked area over buckets), `BarChart` (horizontal or vertical, optionally stacked), `DonutChart` (≤ 6 slices, others grouped), `Sparkline` (decorative trend inside a tile, `aria-hidden` with the value stated in text).
- Colours come from `--chart-1…8` in series order (blue, orange, aqua, yellow, magenta, green, violet, red; checked with a colour-vision-deficiency validator: lightness band, chroma floor and normal-vision separation pass in both themes; the worst adjacent light-mode pair is ΔE 6.5 under protanopia, which is acceptable only because every chart also has a text legend and the table view, so never drop them); verdict series keep a fixed order (spam, phishing, malware, bec, suspicious, dlp_violation) so position also distinguishes them. Grid lines use `--chart-grid`; axis text uses `muted-foreground`.
- Never draw a number the API did not return: missing buckets are gaps, not zeros, unless the API returned zero.

## Data fetching

- `api.GET('/api/v1/…')` (typed, `src/lib/api/client.ts`) or `callOperation(operationId, { path, query, body })`; hooks `useApiQuery(operationId, { path, query })`, `useCursorList(operationId, filters)`, `useApiMutation(operationId)`; URL state with `useUrlState(shape)`. No other `fetch` to `/bff/api` (lint rule).
- Query keys are `[operationId, params]`; invalidate by operation id (`invalidates: ['DomainsController_list_v1']`). Lists are stale after 30 s, reports after 60 s (no refetch on focus). Retries happen only for network errors and `503`.
- The current user: `useMe()` (`GET /auth/me`: `permissions`, `organization`, `override`). The session (no tokens): `useSession()`.
- Errors are `ApiError { status, code, apiMessage, requestId, correlationId, retryAfterSeconds, details }`.

## Accessibility rules

- WCAG 2.2 AA. Text contrast ≥ 4.5:1 (large ≥ 3:1), non-text ≥ 3:1: enforced on the tokens.
- Every interactive element is reachable and operable by keyboard with a visible focus ring (`ring` token, 2 px outline, offset 2 px). No positive `tabindex`.
- Landmarks: one `<header>` (top bar), `<nav aria-label="Main">` (sidebar), `<main id="main">` with a "Skip to content" link first in the document.
- One `<h1>` per page (`PageHeader`); headings in order.
- Icon-only buttons have `aria-label`; decorative icons `aria-hidden`.
- Dialogs: labelled by their title, focus trapped, Escape closes, focus returns to the trigger. A dialog or drawer opened by a plain button (not its Radix `Trigger`) returns focus explicitly (`onCloseAutoFocus` → the button), as the mobile navigation drawer does.
- Label in name (WCAG 2.5.3): when a control has visible text, that text is part of its accessible name. Prefer a name from content (`<span className="sr-only">Account menu for</span> <name>`) over `aria-label`; decorative content (avatar initials) is `aria-hidden`; a filter button showing its value is named `aria-labelledby="<label id> <value id>"`.
- Links inside running text (a sentence or paragraph) are underlined (`underline underline-offset-2`): colour alone does not distinguish them (axe `link-in-text-block`). Links in tables, navigation and button-like positions may rely on position and hover.
- Live feedback: toasts are announced by sonner's live region; inline form errors use `role="alert"` for the summary.
- Targets ≥ 24 × 24 px; content reflows at 320 px without horizontal page scroll; respects `prefers-reduced-motion`.
- Every page test runs `expectNoAxeViolations` (serious and critical impact fail).

## Content-safety rules (P12)

- **Never render message bodies or attachment content.** The only message text shown is the sanitized quarantine preview, rendered as React text in a `pre-wrap` block (`<PreviewText>` in the quarantine feature). `dangerouslySetInnerHTML` is forbidden by lint (no exceptions); no `iframe`, no `blob:`/`data:` URLs of message content.
- Downloads only through the quarantine download grants: create the grant, then navigate to `/bff/api/v1/quarantine/downloads/{token}`; never store the token.
- Attacker-controlled strings go through `UntrustedText` (text, truncated, `title` tooltip, never a link; URLs get a copy button instead).
- **Sensitive message metadata (step 7.2, ADR-0062):** subjects, recipient addresses and To/Cc/Subject header values arrive masked from every read and render through `SensitiveValue`. Clear values exist only after an explicit, audited reveal (`POST /messages/reveal`, `POST /messages/{id}/reveal`, `message:reveal` holders only) and live **only in component state** for the page view: never in the URL, browser storage or the TanStack caches (reset the mutation and remove it from the mutation cache right after use, as `useSubjectReveal` does), forgotten when switched off and on unmount. Say on the page that every reveal is recorded in the audit log.
- On the Email Details page the reveal is one action for the page (`useMessageReveal`): revealed subjects, header values and recipient addresses are held in React state only and shown by position (`seq`, `rcptSeq`) where the api returns masked values (headers, recipients, deliveries). Addresses inside SMTP replies, delivery events and Rspamd symbol options stay masked (never revealed); URLs and filenames are text with a copy button, never links; nothing can be downloaded except through a quarantine entry's grant.
- Secrets are shown once in `SecretRevealDialog`, never logged, never put in query caches (`gcTime: 0`) and removed on close. Decrypted DLP evidence follows the same rule in its own dialog ("Close and forget the values").
- No tokens, codes or user data in `localStorage`/`sessionStorage`/IndexedDB. `localStorage` keeps only UI conveniences (column visibility, sidebar collapsed, theme) behind try/catch.

## Policy builder components (step 7.3)

The visual policy builder lives in `src/features/policies/builder/` ([design note](../plan/steps/22-policy-builder.md) §4.7, [ADR-0063](../architecture/adr/0063-policy-builder-dsl-driven-no-client-evaluation.md)); pages import it from `@/features/policies/builder`. Every component is **controlled** and **fetches nothing** (no `useApiQuery`/`useApiMutation`, no `fetch`): the page loads the catalogue, the version and the directory, owns the state and calls the api.

**The catalogue is the only vocabulary.** `toBuilderCatalog(response)` (zod, non-strict: extra keys of a newer api are ignored; `CatalogShapeError` names what is missing; a catalogue of another DSL version is refused) gives the `BuilderCatalog` every component reads through `<BuilderProvider catalog readOnly violations paths highlightPath directory>`. Fields, groups, labels, units, suggestions, operators with their value shapes, item kinds and limits, actions with their parameters, quantifier phrases, scope nouns, placement contexts (`contexts`, `contextRules`), weekdays, time zones, directions and limits all come from it; the builder holds rendering only. Offering is catalogue-driven: `fieldsFor(catalog, place)` (place `when`, `relaxingWhen`, `holdRule`, `exception`), `operatorsFor(catalog, field, place)` (the field's `ops` with a known value shape; in exceptions only `allowedInException`), `defaultLeaf` (first operator, empty value of its shape, the exception quantifier in exceptions). Two value kinds the catalogue does not state are derived from the field name's last segment and fall back to generic choices: the directory of an `id` field (`department`/`user`, else both lists) and the time value of a `time` field (`window`/`date_range`, else the value's own keys or a kind choice).

**Model.** `parseDefinition(doc)` → `BuilderDefinition` (rules, `group`/`not`/`leaf` nodes and actions with stable UI keys) or a refusal (`not_object`, `unsupported_version`, `unknown_key`, `malformed` with the JSON path; the page then shows the JSON). `buildDefinition(model)` returns the document and its path index; build → parse → build is exact (optional keys keep their presence; `not` is its own node). `useBuilderState(initial)` gives `{ state, dispatch, isDirty, baseline, resetBaseline }` (dirty = canonical JSON differs from the baseline); `builderReducer` commands that grow the document carry `limits` (the catalogue's) and are refused above them; new rules get `rule-<n>` and the highest priority + 10; Move up/down of a rule swaps the two priorities (the evaluation order), of a condition or action its array position.

**Structure and accessibility.**

| Part                  | Pattern                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PolicyBuilderEditor` | Policy direction (`policyDirections`) and priority ("Lower numbers run first"), the canonical document size against `limits.documentBytes`, server problems that map to no node, the rules in evaluation order (every card starts collapsed above 10 rules; a highlighted node opens its card), "Add rule", the policy-wide exceptions                                                                                                                                                                                           |
| Rule card             | `section` named "Rule <id>": id, priority, description (`maxLength` = `limits.descriptionLength`), Enabled switch (off writes `enabled: false`, on removes the key), direction toggles only when the policy covers every direction, "After a match" (Default / Stop / Continue = `stop` absent / true / false), the override switch only for a rule with a decision action, then Conditions (IF), Exceptions (UNLESS) and Actions (THEN)                                                                                         |
| Group                 | `fieldset` with a visually hidden legend ("Conditions of rule r1, all of the following (AND), level 1" for the root, "Group 3, any of the following (OR), level 2" when nested); All (AND)/Any (OR) toggle buttons (`aria-pressed`), NOT toggle (not offered in exceptions while `contextRules.exceptionNegation` is false), Move up/Move down/Remove buttons, "Add condition" / "Add group" disabled at the catalogue limits with the reason as `aria-describedby`                                                              |

Focus: after an add the focus moves to the new row's field picker (a new group: its first row; a new action: its first parameter), after a remove to the previous row or, for the first one, to the group's add button; after a move or a NOT toggle it stays on the pressed button. A polite live region (inside `BuilderProvider`; pages announce validation results through `useBuilderContext().announce`) announces every structural change ("Condition added. Choose its field.", "Condition moved down, now 2 of 3.", "The group now matches any of the following (OR)."). No drag-only interaction exists.

**Value widgets** (chosen by the operator's `valueShape` × the field's type and vocabulary): enum select (humanized vocabulary); checkboxes for lists of a closed vocabulary (enum `in`, closed code sets); whole-number input with B/KiB/MiB/GiB for `bytes` fields (stored as integer bytes; an existing value shows in its largest exact unit) or the unit word for counts and scores, `min`/`max` attributes from the field; `[low, high]` range written only when both are whole numbers; chips for domains, globs, CIDRs, strings and open codes (trimmed, de-duplicated, comma/newline lists split where items cannot contain commas, `maxItems`/`maxItemLength` of the operator, suggestions as a `datalist`); regex list (pattern + "Case-insensitive" → a string or `{ pattern, flags: 'i' }`; edit and remove per item); time window (time-zone combobox from `timeZones`, weekday toggles from `weekdays`, from/to `HH:MM` with `24:00`); date range (time zone, two dates); directory pickers (searchable department/user options from the provider, names on the chips; plain UUID entry when there are none); yes/no select; nothing for `none`. Input hygiene only: no widget validates DSL semantics or compiles a pattern.

**Warnings, not errors.** Catalogue flags turn into inline warnings ("… is not accepted in a rule with Allow or an override; the server will refuse it."): a field with `contexts.relaxingWhen` false in an ALLOW/override rule, `contexts.holdRule` false in a holding rule, `contexts.exception` false or an operator not `allowedInException` in an exception, a wrong exception quantifier (with a one-click fix), a NOT in an exception. Nothing is changed silently; the server's answer wins.

**Server violations.** `violations` (`{ path, code, message }`) map onto nodes through `paths` (`keyForPath`: the deepest indexed prefix of the DSL path) and render under the node with `aria-describedby`; the matching control gets `aria-invalid`; unmapped ones are listed as "Problems with the policy as a whole". `ViolationList` is the error summary: each item names the location ("Rule 1 › conditions › item 2 › value"), message and code, and moves the focus to the node (in view mode to the row itself). `highlightPath` (for example from a test trace) outlines and scrolls to the node and opens its rule card.

**Responsive (B14).** Below 640 px condition rows stack (field, operator and value each full width, `grid-cols-1 sm:grid-cols-[…]`), nested groups are a 2 px left rule plus a "Level n" label (`sm:hidden`; the group name says the level at every width), toolbars wrap, long values wrap. Panels and the editor/summary columns are the page's layout (WP3).

**Read-only.** `readOnly` renders the same tree as text (labels, operator labels, formatted values) with no input, select, switch or structure button; the collapse toggles stay.

**Summary and diff.** `summarizeDefinition(definition, catalog, names)` and `PolicySummaryView` render the grammar of B5 (title line, `IF:` with the direction first, `AND`/`OR` joiners, nested `all of:`/`any of:`, `NOT:`, `UNLESS:`, `THEN:` with parameters, notes for an explicit stop and an override, "(disabled)", the policy-wide exceptions, the catalogue's floor statement under it) with keywords emphasized and "Copy summary" (`summaryToText`, the same text). `diffDefinitions(a, b, catalog)` and `DefinitionDiffView` show counts, policy changes and one card per rule (aligned by id) with property changes and `+`/`−` line diffs (each changed line also says "Added:"/"Removed:" to screen readers; colour is never the only cue), and a "Raw JSON" tab with the canonical JSON diff (long unchanged runs folded); Myers' algorithm, no dependency. Neither ever states what would happen to a message.

**Test panel parts.** `SyntheticFactsForm` (controlled `RequestBody<'PolicyToolsController_test_v1'>['facts']`) offers sections per B7 whose vocabularies come from the catalogue field with the same meaning (SPF from `auth.spf`, DLP categories from `dlp.categories`, the trigger from `scan.outcome`, …); a control whose field is missing is not shown; only the keys the user sets are written (emptied objects are removed). `FACT_PRESETS` are facts only (clean inbound, outbound confidential data, phishing link, malware attachment, executable attachment). `EvaluationResultView` renders the server's answer as returned (disposition and lifecycle disposition, decisive source, explanation, recipient decisions, matched rules, actions with applicability, delivery edits, floor, recommendation, override, clamps, invalid versions, trace) with "Show in editor" on trace rows the page accepts (`onShowPath`, `isEditorRef`).

**No policy evaluation in the browser (ADR-0063 decision 2).** The portal builds and displays `policy-dsl/1` documents; matching, validation, test, dry-run and execution are api calls. Three guards keep it so:

1. ESLint (`eslint.config.mjs`): every file under `apps/admin-portal` may not import `@email-gateway/policy-dsl`, `@email-gateway/risk-scoring`, `@email-gateway/dlp`, `@email-gateway/bec`, `re2js` or their subpaths (nor `packages/<them>` by relative path); the message cites ADR-0063.
2. Source scan (`src/test/scripts/assert-no-policy-evaluator.test.ts`): no shipped module under `src` (generated clients, tests, test data, `src/test/**` and the dev fixtures excluded) imports those packages, nothing under `src/features/policies/**` constructs a RegExp from text, and `package.json` declares none of them.
3. Build output (`scripts/assert-no-policy-evaluator.mjs`, run by `build` after `assert-no-mock-layer.mjs`): `.next` (server, static, standalone; `cache` and the copied monorepo root manifest skipped) must not contain the evaluator-only needles (`@email-gateway/policy-dsl`, `@email-gateway/risk-scoring`, `re2js`, `policy-input/1`, `evaluatePolicyPerRecipient`, `compileSnapshot`, `buildPolicyInput`, `policy.floor.hard_block`, `policy.clamp.ai_only`, `policy.override.applied`) in file contents or names. Its unit test proves every needle exists in `packages/policy-dsl/src`, so a needle cannot silently stop meaning anything. Never write these strings as literals in portal code (show reason codes as the api returns them).

**Testing.** `test-support/` holds a realistic catalogue (`TEST_CATALOG`: every operator and action definition and at least one field of every type and scope), a seeded document generator, the brief's example with its exact B5 text, a test response and `EditorHarness` (state hook + provider + the built document in an `<output>`). Component tests use keyboard-only structure editing, assert focus and the live region, run axe on every component and validate test request bodies with `expectRequestMatchesContract('PolicyToolsController_test_v1', body)`.
