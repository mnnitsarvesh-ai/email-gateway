## 2. Decisions

### 2.0 Invariants (never traded away)

1. **Never clean by accident.** An engine timeout, error, open breaker, missing EML, unparseable reply, skipped scan or empty result is never `clean`. A round whose required engine did not produce a definite verdict ends `scan_failed`, never `scanned`.
2. **No content in MySQL, events or logs.** The EML stays in S3; the scan stage streams it to Rspamd and never persists a body or attachment. Results hold scores, codes, symbol names, bounded symbol options and authentication outcomes. Events and logs carry ids, codes, counts, versions and timestamps only (no addresses, subjects, symbol options or URLs).
3. **One door for the lifecycle.** Every state change goes through `@email-gateway/message-lifecycle` in the transaction of its cause, with `expectedRound`.
4. **Idempotent per (message, round, engine).** Redelivered or duplicated events never create a second final result or a second transition; at most one final `scan_engine_results` row per `(scan, engine)` (unique key) and one `email_scans` row per `(message, round)` (unique key).
5. **Tenant from trusted context.** The worker takes the organization from the envelope and checks it against the writer row and the EML key prefix (`org/<id>/`). The api takes it from the authenticated scope; the platform training route is authorized by a platform permission and audited.
6. **Writer for decisions, replica for reads.** The scan stage reads and writes the writer only; the read APIs use the replica with the existing lag fallback.
7. **Trusted envelope only.** SPF, IP reputation and HELO checks use `client_ip`, `client_helo`, `client_name` and `envelope_from` recorded by smtp-adapter from Postfix XFORWARD, never header values.
8. **Engines classify, policy decides.** The stage records verdicts and reasons; it never rejects, quarantines or delivers (the dev pass-through is a local/ci stand-in for policy).

### S1. Where the scan stage runs: the email-worker scan role

`apps/email-worker/src/scanning/` (new module `ScanningModule`), enabled by `SCAN_ENABLED` (default `true`; with `MIME_INGESTION_ENABLED` the worker runs both roles, locally in one container). Production runs two Deployments of the same image: `email-worker` (MIME: `SCAN_ENABLED=false`) and `email-worker-scan` (`MIME_INGESTION_ENABLED=false`), scaled independently on `email.received` and `scan.*` lag (Kubernetes base manifest, WP3). Rationale (ADR-0026 decision 6): ADR-0002/0007 and step 3.1 M1 already place engines in the email-worker; one image, shared S3/metrics/database infrastructure; independent scaling and failure isolation through separate Deployments; least privilege through a separate broker role user.

The scan role connects to RabbitMQ with its **own** role user `eg-scanner` (`RABBITMQ_SCANNER_URL`): `ScanningModule` builds its own `AmqpConnection` and `ConfirmPublisher` instances (not the global `AmqpModule`, which keeps `RABBITMQ_EMAIL_WORKER_URL` for the MIME role and is only imported when `MIME_INGESTION_ENABLED`). Readiness lists both connections under distinct indicator names (`rabbitmq` for MIME, `rabbitmq-scanner` for scan). If the classes cannot be instantiated outside the module as they are, WP3 adds the smallest factory export to `@email-gateway/common` **only if WP3 owns it in wave 2** (it does; see §11) and documents it.

### S2. What starts a scan and through which queues (topology v3)

- **Trigger:** `mail.message.parsed.v1` (round 0) and `mail.message.rescan_requested.v1` (its round ≥ 1). Engines may use the parse results (4.2 attachments, 4.3 URLs); Rspamd scans the raw EML and ignores them. `mail.message.parse_failed.v1` does **not** start a scan: it goes to the policy fail-safe (E5, 5.2), as ADR-0025 decided.
- **One queue per engine.** The registered engine's queue consumes both event types. Rspamd consumes **`scan.spam`** (ledger consumer `email-worker.scan.rspamd`) and supplies SPF/DKIM/DMARC/ARC in the same call.
- **Topology v3** (`TOPOLOGY_VERSION = 3`, ADR-0026; exchanges and the fourteen queues unchanged):
  - `scan.spam`: role `work` (policy `policyFor('work', …)`: delivery limit 20, dead-letter to `email.events dead-letter.scan.spam`, `reject-publish`, max length 1 000 000), consumer `{ kind: 'ledger', ledgerName: 'email-worker.scan.rspamd', service: 'email-worker' }`, retry `{ strategy: 'hold', maxAttempts: 10, baseDelayMs: 2000, maxDelayMs: 60000, maxRetryAgeMs: 24 h }`, bindings unchanged (parsed, rescan, `retry.scan.spam.#` on `email.security`), description "Rspamd: spam, phishing, reputation and SPF/DKIM/DMARC/ARC (step 4.1)".
  - `scan.auth`: **no event bindings** (only its retry binding is kept for uniformity), role `dormant`, consumer `{ kind: 'none', reason: 'reserved: authentication results come from the rspamd engine on scan.spam (step 4.1, ADR-0026)' }`. The queue stays (the brief fixes fourteen queues) so a future first-party authentication engine can bind it.
  - `scan.url`, `scan.attachment`, `scan.dlp`, `scan.sandbox`: unchanged (dormant, planned 4.2–4.6).
  - `email.policy.evaluate`: unchanged (receives `scanned.v1`; dormant until 5.2).
- **Provisioning:** `definitions.json` regenerated; `init.mjs` (a) creates role user **`scanner`** (`RABBITMQ_SCANNER_USER` / `RABBITMQ_SCANNER_PASSWORD`): configure `^$`, write `^email\.(security|events)$`, read `^scan\.spam$`, topics `email.security` `^retry\.scan\.spam\.` and `email.events` `^dead-letter\.scan\.spam(\.|$)`; (b) extends **ops** for replay of the new work queue: write `^email\.(ingestion|delivery|security)$`, topic `email.security` `^retry\.scan\.spam\.`; (c) **prunes bindings** whose destination is a topology queue or exchange and that are not in the definitions (so `scan.auth` loses its two event bindings on an existing broker; never touches objects outside the topology); (d) verify checks the exact binding set (no extra bindings on topology queues) and the new user. The relay already publishes `^org\.` keys to every exchange; if the reconciler re-drives through keys the relay user may not publish (check `apps/event-relay` reconciler), WP1 extends the relay topics accordingly. The vhost description becomes `email-gateway topology v3`.
- **Reconciler:** `RECONCILE_QUEUES=email.received,email.delivery.pending,scan.spam` (env only; the reconciler is data-driven by the topology). A lost `parsed.v1` copy is re-driven like the other work queues.
- **Dead-letter replay** covers `scan.spam` automatically (`REPLAYABLE_QUEUES` is derived from the topology); the controller's description text is updated (WP4).

### S3. Scan round identity

A **scan round** is `(message_id, received_at, lifecycle_round)`: exactly one `email_scans` row (unique `(message_id, lifecycle_round, received_at)`).

| Trigger                            | Round                          | `scan_kind` | Expected lifecycle state when the round opens                                        |
| ---------------------------------- | ------------------------------ | ----------- | ------------------------------------------------------------------------------------ |
| `mail.message.parsed.v1`           | 0                              | `initial`   | `persisted` (the opener applies E3) or `scanning` round 0 (another engine opened it) |
| `mail.message.rescan_requested.v1` | `payload.lifecycleRound` (≥ 1) | `rescan`    | `scanning` with `lifecycle_round = payload.lifecycleRound` (the api applied E19)     |

`email_scans.attempt` keeps its default 1 and is unused from this step on (documented); `release_revalidation` and `retro` are reserved for 5.3 and later. Old rounds' rows are never updated or deleted by a newer round.

### S4. The engine registry

- **Catalog (data, `@email-gateway/security-contracts`):** `ENGINE_CATALOG: readonly EngineCatalogEntry[]` with `{ name: EngineName; stage: SecurityStage; queue: string /* QueueName */; requiredByDefault: boolean; tenantMayDisable: boolean; description }`. 4.1: `{ name: 'rspamd', stage: 'antispam', queue: 'scan.spam', requiredByDefault: true, tenantMayDisable: false }`. `EngineName` = `'rspamd' | 'clamav' | 'yara' | 'url' | 'bec' | 'dlp' | 'sandbox'` (only `rspamd` in the catalog now). The api lists engines and settings from it without depending on the worker.
- **Adapters (email-worker):** `ScanEngineRegistration { catalog: EngineCatalogEntry; consumerName: string; create(deps): ScanEngineAdapter; settingsFor(effective tenant settings) }` in `scanning/registry.ts`; `ENGINE_REGISTRY = [rspamdRegistration]`. The orchestrator (round service, consumer factory, completion, sweeper) iterates the registry and never names an engine.
- **Adapter contract (`scanning/engine.ts`):**

```ts
interface EngineScanContext {
  organizationId: bigint;
  messageId: bigint;
  receivedAt: Date;
  round: number;
  direction: 'inbound' | 'outbound' | 'internal';
  envelope: {
    clientIp: string | null;
    clientHelo: string | null;
    clientName: string | null;
    envelopeFrom: string;
    recipients: string[];
    queueId: string | null;
  };
  eml: { key: string; sizeBytes: number; open(signal: AbortSignal): Promise<Readable> };
  settings: unknown; /* the engine's effective settings, validated */
}
type EngineScanOutcome =
  | { kind: 'definite'; result: NormalizedEngineResult /* security-contracts */ }
  | {
      kind: 'failure';
      outcome: 'timeout' | 'error';
      errorCode: string;
      durationMs: number;
      retryable: boolean;
      engineVersion: string | null;
    };
interface ScanEngineAdapter {
  readonly name: EngineName;
  scan(ctx, signal): Promise<EngineScanOutcome>;
}
```

- **Required engines of a round** = catalog entries enabled on the platform (`SCAN_ENGINES`, default `rspamd`; validated against the catalog) with `requiredByDefault`, minus those a tenant disabled where `tenantMayDisable` (none in 4.1). Snapshotted into `email_scans.required_engines` (JSON array of names) when the round opens.

### S5. One engine delivery: the handler (generic, `scanning/engine-consumer.ts` + `round-service.ts`)

Consumer per registration: `QueueConsumer` of its queue, `eventTypes = [parsed.v1, rescan_requested.v1]`, prefetch `SCAN_<ENGINE>_CONCURRENCY` (Rspamd default 8, max 64), retry `hold` with `SCAN_RETRY_BASE_MS` / `SCAN_RETRY_MAX_MS`, `progress` = `PrismaConsumerProgress`, classification: database/S3/network outages → `transient`; the stage's own `EngineAttemptFailedError` → `retryable`; `NonRetryableError` → fatal. Config refuses `SCAN_<ENGINE>_MAX_ATTEMPTS ≥` the queue's `maxAttempts` (10), as MIME does, so the engine budget always finalizes before the broker dead-letters.

Per delivery:

1. **Ledger check:** if `message_idempotency (consumer, eventId)` exists → `duplicate`, ack.
2. **Load and check (writer):** message by `(id, received_at)` with `organization_id = envelope org`; absent → commit the ledger row with no effect, count `scan_events_skipped_total{reason="message_not_found"}`. EML key must start with `org/<envelope org>/` and equal the row's `eml_object_key` (else final `error` `eml_key_mismatch`, see 5). Round = 0 for `parsed.v1`, `payload.lifecycleRound` for rescan.
3. **Open the round (short writer transaction):** `lockLifecycle` (message row lock) →
   - state `persisted`, round 0, trigger `parsed.v1` → `transitionMessage` E3 (`to: 'scanning'`, reason `scan_started`, actor `{ role: 'scanner', service: 'email-worker', type: 'system' }`, `transitionKey: 'scan-open:<messageId>:0'` (shared by every engine, so the first wins and the rest get `duplicate`), `expectedRound: 0`, `expectedFrom: ['persisted']`, causation = event id);
   - state `scanning` and `lifecycle_round = round` → no transition;
   - anything else (older/newer round, `scanned` of this round is fine only for completion re-check, other states) → stale: commit the ledger row, count `scan_events_skipped_total{reason="lifecycle_<state>"|"older_round"}`, ack. (A `scanned`/`scan_failed` message of the same round with this engine's final row present is a duplicate; without it, it cannot happen: completion requires every required engine.)
   - `INSERT IGNORE`-style create of the `email_scans` row (`lifecycle_round`, `scan_kind`, `status = running`, `started_at`, `deadline_at = now + SCAN_ROUND_DEADLINE_SECONDS`, `required_engines` snapshot, `trigger_event_id`); read it back.
   - Read this engine's rows for the scan: a final row exists → skip to step 6 (completion re-check), else `attempts = count(non-final rows)`.
     The open transaction does **not** write the ledger row (the delivery is not handled yet).
4. **Scan (no transaction open):** settings resolved (S8), EML opened from S3 (`eml.open`, `SCAN_S3_TIMEOUT_MS`), `adapter.scan(ctx, AbortSignal.timeout(SCAN_<ENGINE>_TIMEOUT_MS))` through the engine's breaker (S10). `NoSuchKey` → `failure` `error`/`eml_unavailable` (not retryable). S3 outage → transient (thrown; no attempt row).
5. **Record:**
   - `failure` with `retryable`, `attempts + 1 < SCAN_<ENGINE>_MAX_ATTEMPTS` and `now < deadline_at` → one writer transaction inserting a **non-final** row (`attempt = attempts + 1`, `is_final = false`, outcome `timeout`/`error`, `error_code`, reason codes `engine.timeout` / `engine.error` / `engine.circuit_open` / `engine.soft_reject`, duration, engine version if known) — no ledger row — then throw `EngineAttemptFailedError` (retryable) so the consumer retries with backoff.
   - otherwise (definite, or the last allowed failure) → **finalize** in one writer transaction through `processOnce(consumer, eventId)`: insert the **final** row (`is_final = true`, `attempt = attempts + 1`); a unique violation on `(scan_id, final_engine)` means another delivery finalized first → keep going to completion (no second row); for Rspamd, insert the `email_auth_results` row (unique per `(scan_id, engine)`); then step 6 **in the same transaction**.
6. **Completion check (same transaction, lock order message → scan):** `lockLifecycle` → `SELECT … FROM email_scans WHERE id = ? AND received_at = ? FOR UPDATE`; `status ≠ running` → done. Else read the final rows; if every name in `required_engines` has a final row → aggregate (S6), `UPDATE email_scans SET status, scan_verdict, reason_codes, completed_at`, transition (E6 `scanned` / E7 `scan_failed`, `transitionKey: 'scan-complete:<messageId>:<round>'`, `expectedRound: round`, `expectedFrom: ['scanning']`, causation = the event id), and insert the `mail.message.scanned.v1` outbox row (S6). A `stale` transition (the round was superseded by a rescan or the message expired) still completes the `email_scans` row but writes no `scanned.v1` (count `scan_rounds_superseded_total`).
7. Ack (`handled`). Metrics per S17.

### S6. Aggregation, lifecycle outcome and `mail.message.scanned.v1`

Pure function `aggregateRound(required, finals)` (`scanning/aggregate.ts`):

- `failedRequired` = required engines whose final outcome is `timeout` or `error`.
- **Lifecycle:** `failedRequired` empty → `scanned` (E6, reason `scan_complete`, `email_scans.status = completed`); else `scan_failed` (E7): reason `eml_unavailable` if any final has `error_code = eml_unavailable`, else `scan_error` if any `error`, else `scan_timeout`; `email_scans.status = failed` (errors) or `timed_out` (timeouts only).
- **Aggregate verdict** (`email_scans.scan_verdict`): `malicious` if any final is `malicious`; else `error` if any required `error`; else `timeout` if any required `timeout`; else the most severe definite verdict among all finals (`malicious > spam > suspicious > unknown > clean`; `skipped` ignored; no definite final → `unknown`). Non-required engines' failures are recorded but never fail the round.
- **Reason codes** (`email_scans.reason_codes`): union of the finals' reason codes, ordered by severity of their rule then name, at most 32.

**`mail.message.scanned.v1`** (schema replaced in place: the placeholder was never produced or consumed, so v1 is redefined; registry exchange `email.security`, aggregate `message`, correlation from the triggering event):

```ts
{
  messageId: decimalId, receivedAt: iso, direction,
  emlS3Key: 'org/<id>/…',
  lifecycleRound: int 0..65535,
  scanId: decimalId,
  scanKind: 'initial' | 'rescan',
  outcome: 'scanned' | 'scan_failed',
  verdict: 'clean' | 'spam' | 'suspicious' | 'malicious' | 'unknown' | 'timeout' | 'error',
  engines: [{ engine: /^[a-z][a-z0-9_]{0,31}$/, required: boolean,
              outcome: <verdict values> | 'skipped', attempts: int ≥ 1 }],   // 1..16
  reasonCodes: string[],   // ≤ 32, each /^[a-z][a-z0-9_]*(\.[a-z0-9_]+)+$/, ≤ 64 chars
  completedAt: iso,
}
```

Consistency refinements: `outcome = scanned` ⇒ no required engine with `timeout`/`error` and `verdict ∉ {timeout, error}`; `outcome = scan_failed` ⇒ at least one required failure. No symbol options, no addresses, no URLs (content guard). Bound to `email.policy.evaluate` (dormant until 5.2) and `email.analytics`; consumed from the **outbox** by the dev pass-through (S15).

### S7. Verdict model and the Rspamd mapping

Verdicts (`SCAN_VERDICTS`, `@email-gateway/security-contracts`, lower-case everywhere): `clean`, `spam`, `suspicious`, `malicious`, `unknown`, `timeout`, `error`. `ENGINE_OUTCOMES = [...SCAN_VERDICTS, 'skipped']`. `VERDICT_SEVERITY = { clean: 1, unknown: 2, suspicious: 3, spam: 4, malicious: 5 }` (failures have no severity). Reason code format `/^[a-z][a-z0-9_]*(\.[a-z0-9_]+)+$/`, ≤ 64 characters.

**Rspamd mapping** (pure `verdict-mapper.ts` in the email-worker Rspamd engine; `RSPAMD_MAPPING_VERSION = 'rspamd-map/2'` since review round 2 (R6 ARC trust; `rspamd-map/1` results were made with the old R6); symbol categories in `symbol-catalog.ts` as data: exact names plus prefix patterns). Input: the normalized reply (S9) and the effective settings (S8). Rules are evaluated in order; R0/R1 end evaluation; R2–R8 each may raise the verdict and add a reason code; the result is the most severe verdict raised, `clean` if none.

**Platform settings (env, both api and email-worker read them; validated at start):**

| `SCAN_RSPAMD_SCORE_MIN` / `SCAN_RSPAMD_SCORE_MAX` | `1` / `15`    | `0 < MIN < MAX ≤ 100`           |
| `SCAN_RSPAMD_PHISHING_VERDICT`                    | `suspicious`  | `suspicious`, `malicious`       |
| `SCAN_RSPAMD_DMARC_REJECT_VERDICT`                | `suspicious`  | `suspicious`, `malicious`       |
| `SCAN_RSPAMD_AUTH_FAILURE_VERDICT`                | `reason_only` | `reason_only`, `suspicious`     |

**Tenant overrides:** table `scan_engine_settings` (§3), one row per `(organization_id, engine)`, `settings` JSON validated by `rspamdTenantSettingsSchema` (`security-contracts`): optional `spamScore`, `suspiciousScore` (numbers, 2 decimals), `phishingVerdict`, `dmarcRejectVerdict`, `authFailureVerdict`. `resolveRspamdSettings(platform, override)` (pure) returns the effective settings or the list of violations:

- score thresholds anywhere inside the platform bounds, `suspiciousScore < spamScore` after merging (a tenant may loosen or tighten scores: thresholds are tuning, and the non-score rules R2/R3/R4 are not tunable down);
- severity settings may only be **raised** relative to the platform default (order `reason_only < suspicious < malicious`), never lowered;
- a tenant can never disable a required engine (`tenantMayDisable = false`; no plan feature allows it in 4.1);
- unknown keys are refused (strict schema).

The worker re-validates every row at use: an invalid row (e.g. platform bounds tightened after it was saved) is ignored in favour of the platform settings, logged once per version, and counted (`scan_settings_invalid_total{engine}`); the result records `settings_version = 'platform'`. `settings_version` = `<mapping version>;p=<first 12 hex of SHA-256 of the canonical platform settings>;t=<row version | none>`.

**Cache:** in-process per worker, keyed by organization and engine, TTL `SCAN_SETTINGS_CACHE_TTL_MS` (default 30 000; max 300 000), bounded size 10 000 entries (LRU). A changed setting takes effect within the TTL (documented in the API).

### S9. The Rspamd adapter and the `@email-gateway/rspamd` package

**Package `packages/rspamd` (`@email-gateway/rspamd`, new, CommonJS like `packages/mail-routing`, zod only, Node global `fetch`/undici):** transport and normalization of Rspamd's own protocol, no platform verdicts. Used by the email-worker (scan) and the api (training).

- `RspamdClient({ baseUrl, controllerUrl, controllerPassword?, controllerEnablePassword?, timeoutMs })`:
  - `check(input: { body: Readable | Buffer; sizeBytes: number; envelope: RspamdEnvelope; logTag: string; settingsId?: string }, signal): Promise<RspamdCheckReply>`: `POST /checkv2`, the body **streamed** (`duplex: 'half'`, `Content-Length` = size), never buffered by the client;
  - `learn(kind: 'spam' | 'ham', body, sizeBytes, signal)`: controller `POST /learnspam` / `/learnham` with the enable password;
  - `fuzzy(op: 'add' | 'delete', flag: number, weight: number, body, sizeBytes, signal)`: controller `POST /fuzzyadd` / `/fuzzydel`;
  - `version(signal)`: controller `GET /stat` (read password) → `version` string; or the `Server` reply header of `/checkv2` if Rspamd sends one (verify; prefer it, it costs no extra call).
  - Errors are typed: `RspamdTimeoutError`, `RspamdUnavailableError` (connect/reset/DNS), `RspamdHttpError(status)`, `RspamdProtocolError` (invalid JSON/schema), `RspamdSoftRejectError`; no error message carries a body, a header value or a password.
- `buildRequestHeaders(envelope)`: `IP` (client IP, if valid), `Helo`, `Hostname` (client name; omitted when null), `From` (envelope sender; `<>` for the null sender), one `Rcpt` per recipient (at most `RSPAMD_MAX_RCPT_HEADERS` = 100, the rest omitted and flagged), `Queue-Id`, `User` (only for outbound and internal mail: `org-<organizationId>`, because smtp-adapter authenticated the submitter at SMTP time; Rspamd then skips SPF/greylist-style checks for authenticated senders), `Settings-Id` (`eg_inbound` / `eg_outbound`), `Log-Tag` (`m<messageId>r<round>`, ids only). Values are validated (no CR/LF, length-bounded) before use.
- `rspamdCheckReplySchema` (zod, permissive for unknown fields): `is_skipped`, `score`, `required_score`, `action`, `symbols{ name, score, metric_score?, options?[] }`, `messages`, `milter`, `message-id` (ignored), `time_real`.
- `normalizeReply(reply)` → `NormalizedRspamdResult`: `score`, `requiredScore`, `action`, `skipped`, `symbols: [{ name, score, options: string[] /* ≤ 5, each ≤ 200 chars, control characters stripped */ }]` sorted by |score| desc then name (≤ 200 symbols), and **`auth`**:

```ts
auth: {
  spf: {
    result: AuthOutcome | null;
    domain: string | null;
  }
  dkim: {
    result: AuthOutcome | null;
    signatures: {
      domain: string;
      result: AuthOutcome;
      selector: string | null;

  }

    result: AuthOutcome | null;

  }

```

Symbol → outcome table (data, unit-tested): SPF `R_SPF_ALLOW` pass, `R_SPF_FAIL` fail, `R_SPF_SOFTFAIL` softfail, `R_SPF_NEUTRAL` neutral, `R_SPF_NA` none, `R_SPF_DNSFAIL` temperror, `R_SPF_PERMFAIL` permerror; DKIM `R_DKIM_ALLOW` pass, `R_DKIM_REJECT` fail, `R_DKIM_TEMPFAIL` temperror, `R_DKIM_PERMFAIL` permerror, `R_DKIM_NA` none, per-signature from `DKIM_TRACE` options (`domain:+|-|?|~`); DMARC `DMARC_POLICY_ALLOW` / `DMARC_POLICY_ALLOW_WITH_FAILURES` pass, `DMARC_POLICY_REJECT` fail+reject, `DMARC_POLICY_QUARANTINE` fail+quarantine, `DMARC_POLICY_SOFTFAIL` fail+none, `DMARC_NA` none, `DMARC_DNSFAIL` temperror, `DMARC_BAD_POLICY` permerror; ARC `ARC_ALLOW` pass, `ARC_REJECT` fail, `ARC_NA` none, `ARC_DNSFAIL` temperror, `ARC_INVALID` permerror. **Engine adapter (`apps/email-worker/src/scanning/engines/rspamd/rspamd.engine.ts`):** builds the envelope from the writer row (`client_ip`, `client_helo`, `client_name`, `envelope_from`, recipients from `email_recipients` ordered by `rcpt_seq`, `mta_queue_id`, `direction`), refuses `size_bytes > SCAN_RSPAMD_MAX_BYTES` without calling (R1 `engine.too_large`), streams the EML, maps the reply (S7) into a `NormalizedEngineResult`:

### S10. Resilience

- **Timeouts:** per call `SCAN_RSPAMD_TIMEOUT_MS` (default 20 000; Rspamd `task_timeout` 15 s, below it); S3 waits `SCAN_S3_TIMEOUT_MS` (default 30 000); writer transactions `SCAN_DB_TIMEOUT_MS` (default 15 000).
- **Circuit breaker** (`scanning/circuit-breaker.ts`, generic, one per engine per worker, in memory): states `closed → open` after `SCAN_BREAKER_FAILURE_THRESHOLD` consecutive failures (default 5) or a failure ratio ≥ `SCAN_BREAKER_FAILURE_RATIO` (default 0.5) over the last `SCAN_BREAKER_WINDOW` calls (default 20, minimum 10 calls); `open` for `SCAN_BREAKER_OPEN_MS` (default 15 000), then `half_open`: one probe call at a time (`SCAN_BREAKER_HALF_OPEN_PROBES` = 1); success → `closed`, failure → `open`. Open → immediate `failure` `error`/`engine.circuit_open` (an attempt row, retried with backoff, never `clean`). Only transport failures (R0) count; definite verdicts and `unknown` count as successes. Clock injected for unit tests.
- **Retries:** attempts recorded as non-final rows and retried through the `hold` strategy until `SCAN_RSPAMD_MAX_ATTEMPTS` (default 6; < 10) or the round deadline. With the defaults (2 s doubling to 60 s) a message survives an Rspamd outage of about two minutes; longer outages end `scan_failed` (policy fail-safe, administrative rescan after recovery).
- **Bounded concurrency:** prefetch = handler concurrency per engine per worker; the Rspamd client additionally limits in-flight HTTP calls to the same number (semaphore), so a slow Rspamd never accumulates sockets.
- **Round deadline sweeper** (`scanning/deadline-sweeper.ts`): one leader per cluster through `AdvisoryLocks` (lock `scan:deadline`), every `SCAN_SWEEP_INTERVAL_MS` (default 30 000): `email_scans` with `status = 'running' AND deadline_at < now` and `deadline_at ≥ now - SCAN_SWEEP_LOOKBACK_HOURS` (default 48; review round 2: bounded by the round's deadline, not by the message's `received_at`, which every round, rescans included, copies as its partition key, so a rescan of a message received earlier than the lookback was never swept), batch `SCAN_SWEEP_BATCH_SIZE` (default 200), index `(status, deadline_at)`. For each: one writer transaction: lock message → lock scan → still running → insert a final `timeout` row (`error_code = deadline_exceeded`, reason `engine.deadline_exceeded`) for every required engine without a final row → completion (S5 step 6, causation null, actor service `email-worker`). Validated: `SCAN_ROUND_DEADLINE_SECONDS ≥ SCAN_RSPAMD_MAX_ATTEMPTS × (SCAN_RSPAMD_TIMEOUT_MS + SCAN_RETRY_MAX_MS) / 1000` and ≤ 6 hours (documented: must stay below `LIFECYCLE_DEADLINE_SCANNING_HOURS`). Default 1 800 s.
- **Idempotency:** the ledger row commits with the final result and the completion; the final-row unique key and the scan-row unique key make concurrent deliveries of different event ids for the same `(message, round, engine)` converge on one result; the completion transition key `scan-complete:<messageId>:<round>` makes the transition once.

### S13. Bayes learning and fuzzy hashes (admin operations)

- **Who:** platform administrators only (new permission **`platform:scan_training`**, held by `platform_admin`; `super_admin` holds every permission). Justification: the Bayes statfiles and the fuzzy storage are **shared by all tenants**; letting a tenant admin train them would let one tenant poison another's filtering. Per-tenant Bayes is not in scope (§10).
- **Route:** `POST /api/v1/platform/organizations/{organizationId}/messages/{messageId}/scan-training` (`organizationId`: the organization's public id, as the platform organization routes address it; `messageId`: the message public id), `@UserOnly()`, `@RequireMfa()`, `@RequirePermissions('platform:scan_training')`, `@RateLimit` 60 per caller per minute. Body `{ operation: 'learn_spam' | 'learn_ham' | 'fuzzy_add' | 'fuzzy_delete'; fuzzyFlag?: 'spam' | 'phishing' /* required for fuzzy ops; 11 / 12 */; reason: string 1..512 }`. The message is looked up on the writer **within that organization** (another organization's message → 404); its EML is streamed from S3 (key prefix checked) to the controller through `@email-gateway/rspamd`. Response `200 { operation, result: 'learned' | 'already_learned' | 'added' | 'deleted', engineVersion }`; Rspamd unavailable → `503 rspamd_unavailable`; EML missing → `409 content_unavailable`. One `audit_logs` row per call (`scan_training.<operation>`, actor, organization, message id, outcome, never content) and one `email_events` row `scan.training` (`details { operation, result }`).
- **Fuzzy weight** `SCAN_FUZZY_WEIGHT` (default 10). Learning does not rescan; an operator rescans through the existing rescan API.

### S14. Rescan

The api's E19 rescan is unchanged (state change, new round, `rescan_requested.v1`). The scan stage consumes it on every registered engine's queue (`scan.spam` today), opens round N (`scan_kind = rescan`), records new results and completes with `expectedRound = N`. Old rounds' `email_scans`, `scan_engine_results` and `email_auth_results` rows are never modified or deleted. Results of an older round that finish late complete their own `email_scans` row but their transition is `stale` (no state change, no `scanned.v1`). `RESCAN_NOTE` in the api is replaced by a note that the scan runs on every registered engine.

### S15. Development pass-through after scanning

`DevPassThroughApprover` (delivery-worker, local/ci only, unchanged refusal outside local/ci):

- Feed: `OutboxPoller<MessageScannedV1>` over `mail.message.scanned.v1` rows, new consumer/cursor name `delivery-worker.dev-passthrough-scanned` (`initialPosition: 'latest'`).
- `outcome = 'scanned'` → `transitionMessage` **E27** (`to: 'approved'`, reason `dev_passthrough`, role `dev_passthrough`, `transitionKey: 'evt:<scannedEventId>:approved'`, `expectedRound: payload.lifecycleRound`, `expectedFrom: ['scanned']`), then approvals exactly as today with `lifecycleRound: payload.lifecycleRound`. Any verdict is approved (the pass-through stands in for a "deliver everything scanned" policy; it logs the verdict); this is development behaviour only.
- `outcome = 'scan_failed'` → never approved: ledger row, `delivery_approvals_skipped_total{reason="scan_failed"}`, info log.
- `parse_failed` messages are never seen by the pass-through any more: they stay `persisted` until 5.2 (policy fail-safe) or their `persisted` deadline (documented in the routing runbook and README).
- Lifecycle table: add **E27** `scanned → approved` (`roles: ['dev_passthrough']`, `reasons: ['dev_passthrough']`, `producedBy: '4.1'`) — WP1, wave 1; **remove E4** (`persisted → approved`) together with its last producer — WP4, wave 2; the id E4 is never reused (documented as retired). `DEV_PASSTHROUGH_WARNING` becomes "mail is delivered after scanning but without policy".

### S18. Security boundaries

- Rspamd's normal worker (11333) and controller (11334) are reachable only on the internal networks; the controller requires passwords from the api and worker (secrets in env/`_FILE`, rendered hashed); learning uses the enable password, held only by the api.
- The worker never sends Rspamd anything but the EML and the trusted envelope; it never trusts `Authentication-Results` or `X-Spam*` headers in the message.
- Symbol options can contain addresses and URLs: they are stored in `scan_engine_results.evidence` (tenant-scoped, `message:read` in the API) and are never logged, evented or put in metrics labels. Metrics labels are bounded enums only.
- Redis: Rspamd uses DB `RSPAMD_REDIS_DB` (1) of the shared instance locally; production uses a dedicated Redis. Bayes and fuzzy state are shared across tenants, hence platform-only training (S13).

## 3. Data model (one forward migration `scan_pipeline`, WP1)

Created with `pnpm db:migrate:dev --create-only`, SQL reviewed by hand (partitioned tables: no foreign keys; every unique key contains `received_at`; follow `20261103200000_mime_ingestion` for creating a partitioned table and registering it). Never `migrate reset`; the clean-schema check runs in `email_gateway_verify` and drops it afterwards.

1. **`email_messages`**: `ADD COLUMN client_name VARCHAR(255) NULL` after `client_helo` (`ALGORITHM=INSTANT` if MySQL accepts it on the partitioned table, else the default; record which). smtp-adapter writes Postfix's XFORWARD `NAME` (the verified client host name; Postfix's literal `unknown` is stored as `unknown`; `[UNAVAILABLE]`/`[TEMPUNAVAIL]` and missing → NULL), truncated to 255 (WP1 changes `lmtp-listener.ts`, `ingestion.service.ts`, `ingestion.repository.ts` and their tests; the SMTP hot path gains no statement).
2. **`email_scans`**: `ADD lifecycle_round SMALLINT UNSIGNED NOT NULL DEFAULT 0`, `scan_verdict ENUM('clean','spam','suspicious','malicious','unknown','timeout','error') NULL`, `required_engines JSON NULL`, `reason_codes JSON NULL`, `trigger_event_id CHAR(36) NULL`, `deadline_at DATETIME(3) NULL`; `DROP INDEX` the unique `(message_id, scan_kind, attempt, received_at)`; `ADD UNIQUE (message_id, lifecycle_round, received_at)`; `ADD INDEX (status, deadline_at)`. `verdict`, `risk_score`, `scoring_version` stay for 5.1 (risk scoring) and are not written in 4.1. No rows exist (no producer ever).
3. **`scan_engine_results`**: `EngineOutcome` **appends** `spam`, `unknown`; `ADD attempt SMALLINT UNSIGNED NOT NULL DEFAULT 1`, `is_final TINYINT(1) NOT NULL DEFAULT 1`, `final_engine VARCHAR(32) GENERATED ALWAYS AS (IF(is_final = 1, engine, NULL)) VIRTUAL` (read-only in Prisma, documented like `org_scope`), `required_score DECIMAL(8,3) NULL`, `action VARCHAR(32) NULL`, `reason_codes JSON NULL`, `error_code VARCHAR(64) NULL`, `settings_version VARCHAR(96) NULL`; `DROP` unique `(scan_id, engine, received_at)`; `ADD UNIQUE (scan_id, engine, attempt, received_at)` and `ADD UNIQUE (scan_id, final_engine, received_at)` (MySQL allows many NULLs, so only one final row per engine). `evidence` holds `{ signals[], auth?, rcptTruncated? }` (S9). Non-final rows have outcome `timeout`/`error` only (enforced in code and by a `CHECK (is_final = 1 OR outcome IN ('timeout','error'))` if MySQL accepts it on the partitioned table; else code only, recorded).
4. **`email_auth_results`** (new, partitioned monthly by `received_at`, retention 6 months, tier `core`; registered in `packages/database/src/partitioning/registry.ts`): `id BIGINT UNSIGNED AUTO_INCREMENT`, `received_at DATETIME(3)`, `message_id`, `organization_id`, `scan_id` (all `BIGINT UNSIGNED`), `engine VARCHAR(32)`, `spf AuthOutcome NULL`, `spf_domain VARCHAR(253) NULL`, `dkim AuthOutcome NULL`, `dkim_signatures JSON NULL` (≤ 10 `{domain, result, selector}`), `dmarc AuthOutcome NULL`, `dmarc_policy DmarcPolicy NULL`, `dmarc_domain VARCHAR(253) NULL`, `arc AuthOutcome NULL`, `created_at DATETIME(3)`; PK `(id, received_at)`; UQ `(scan_id, engine, received_at)`. Enums `AuthOutcome` (`pass`, `fail`, `softfail`, `neutral`, `none`, `temperror`, `permerror`) and `DmarcPolicy` (`none`, `quarantine`, `reject`).
5. **`scan_engine_settings`** (new, not partitioned): `id BIGINT UNSIGNED PK`, `organization_id` FK `organizations` (Restrict), `engine VARCHAR(32)`, `settings JSON`, `version INT UNSIGNED NOT NULL DEFAULT 1`, `updated_by_user_id` FK `users` (SetNull), `created_at`, `updated_at`; UQ `(organization_id, engine)`.
6. Prisma: `ScanVerdict` enum; `EmailScan`, `ScanEngineResult` (with `finalEngine String? @map("final_engine")` documented "READ-ONLY, generated by MySQL; never write it"), `EmailAuthResult`, `ScanEngineSetting` models; `EmailMessage.clientName`. Drift check must pass (follow how `org_scope` / `verified_name` generated columns are reconciled).
7. **Seed catalog:** permissions `scan:settings_manage` ("Change the organization's security scan thresholds"; `organization_admin`, `security_analyst`) and `platform:scan_training` ("Train the shared spam classifiers (Bayes, fuzzy) from a message"; `platform_admin`): 39 permissions. `seed-catalog.test.ts` updated.

## 7. Alternatives considered

| Decision             | Chosen                                                     | Rejected                                                                                                                     |
| -------------------- | ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Orchestration        | Per-engine queues + completion under the message lock (S5) | Central fan-out in one handler (one slow engine holds all); saga with result queue (extra hops, unused brief queues)         |
| Home                 | email-worker scan role + own broker user (S1)              | New `scanner` deployable (supersedes ADR-0002 for little gain; reconsider if 4.2–4.6 grow the worker too much)               |
| Auth queue           | `scan.auth` unbound, reserved (S2)                         | Two Rspamd calls per message; dormant queue filling forever                                                                  |
| Trigger              | `parsed.v1` (engines can use parse results)                | `received.v1` (parse results not yet available; would race the MIME stage)                                                   |
| Attempts             | Non-final rows + final row, one table (§3)                 | Attempts only in logs/metrics (failures not explainable per message); a separate attempts table (one more partitioned table) |
| Verdict set          | Seven verdicts + `skipped`                                 | ADR-0007's five outcomes                                                                                                     |
| Thresholds           | Env platform settings + bounded JSON per tenant (S8)       | Policy rows (5.2 not built); Rspamd per-request settings (cannot express our rules, harder to audit)                         |
| Milter               | Reject GTUBE/≥ 15 only, accept on failure (ADR-0027)       | tempfail; headers only; DMARC reject by default                                                                              |
| Training             | Platform admins only (S13)                                 | Tenant admins on shared statfiles (cross-tenant poisoning); per-tenant Bayes (cold start, out of scope)                      |
| Hostname for hfilter | Store XFORWARD NAME (`client_name`)                        | Omit `Hostname` (every post-queue scan gets `HFILTER_HOSTNAME_UNKNOWN`); parse our own `Received` header (fragile)           |
| Dev pass-through     | Outbox feed of `scanned.v1`, E27                           | Keep approving on `received.v1` (unscanned delivery); consume `email.policy.evaluate` (that is 5.2's queue)                  |

## 8. Risks and mitigations

| Risk                                                                      | Mitigation                                                                                                                                                              |
| ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Rspamd 3.12 option, symbol or reply names differ from this note           | WP2 verifies every assumption against the container (`rspamadm configdump`, `rspamc -j` on the corpus) and records real names; the symbol catalog is data               |
| Rspamd resolves `redis` through dns-sink and fails                        | Entrypoint resolves with `getent` and writes the address (S12)                                                                                                          |
| Bayes with a low `min_learns` changes other fixtures' scores              | Bayes tests use per-run random tokens; corpus expectations assert verdicts/reason codes with margins, not exact scores; local `min_learns = 10` documented as test-only |
| Shared Redis growth (Bayes, fuzzy, history, reputation) with `noeviction` | Separate DB 1, `history_redis nrows`, fuzzy `expire`, reputation TTLs; production dedicated Redis; documented sizing                                                    |
| Double scanning cost (milter + post-queue)                                | Accepted (ADR-0027); production may split SMTP-time and post-queue Rspamd pools                                                                                         |
| End-to-end latency grows (dev pass-through waits for scan)                | Stack-test timeouts adjusted by WP5; `smtp-concurrency` and `messaging-backlog` numbers recorded against the 3.3 baselines                                              |
| Hold retries keep prefetch slots during an outage                         | Bounded (prefetch × engines); breaker makes attempts fast; deadline sweeper finalizes                                                                                   |
| An engine registered but not deployed                                     | Every round ends `scan_failed` at its deadline (fail-safe, alerted by `ScanDeadlineFinalizations`)                                                                      |
| Partitioned-table DDL (generated column, CHECK, instant add) refused      | WP1 records the fallback (code-only enforcement) in §12                                                                                                                 |
| Removing bindings on a live broker                                        | `init.mjs` prunes only bindings of topology-owned objects; tested by the messaging stack suite and a dry-run log                                                        |
| Committed test DKIM key mistaken for a credential                         | Lives under `tests/fixtures/scan-corpus/keys/` with a README; only for `scan.test`, which no real resolver serves                                                       |
| Symbol options containing addresses                                       | Stored only in `evidence`, never logged/evented; covered by the logger redaction test and the content guard                                                             |

- **S1 readiness and broker users.** `AmqpConnection.healthName` is fixed (`rabbitmq`), so the scan role's readiness is a small wrapper `ScannerBrokerHealth` (`rabbitmq-scanner`) around its own `AmqpConnection`; `HealthModule.forRoot` gained an `imports` option (`packages/common`) so a non-global module can export an indicator (the same `ScanningModule` object is imported by `AppModule` and `HealthModule`; Nest 11 identifies dynamic modules by reference, one instance). `RABBITMQ_EMAIL_WORKER_URL` is now optional and required only with `MIME_INGESTION_ENABLED` (a scan-only replica has no `eg-email-worker` credentials); `RABBITMQ_SCANNER_URL` is required only with `SCAN_ENABLED`, `SCAN_RSPAMD_URL` only with the rspamd engine; `RSPAMD_CONTROLLER_URL` / `_PASSWORD` are optional (the version comes from the `Server` header). Both roles off is refused. The scanner connection is named `email-worker-scanner` (`amqp_connection_up{connection}`).
- **S4 adapter contract (additive).** `EngineScanContext.settingsVersion` (the engine records it on its result), `EngineFailure.engineFault?` (default true; a missing EML, a refused request and an infrastructure error never count toward the breaker, only R0 transport failures do), `EngineDefinite.evidence?` (`{ rcptTruncated }`, merged into `scan_engine_results.evidence`), `EmlUnavailableError` (the S3 opener's `NoSuchKey`).
- **S5 finalize order.** Inside `processOnce` the transaction locks message → scan first, checks whether this engine already has its final row, and inserts only when it has none, instead of inserting and catching the unique violation on `(scan_id, final_engine)`: every finalizer serializes on the message lock, so the check is exact, and a failed statement never has to be recovered inside a Prisma interactive transaction. The unique keys stay the backstop. Same lock order and invariants.
- **S5 codes not named by the design.** Failure finals use `error_code` + reason `engine.eml_unavailable`, `engine.eml_key_mismatch` (key outside `org/<envelope org>/` or different from the row: final error without a scan, not retried), `engine.max_attempts_exceeded` (defence in depth: a round whose non-final rows already reached the budget, e.g. after crash loops, finalizes without another call), `engine.protocol_error` (also when a client-accepted reply fails `normalizedEngineResultSchema`), and `invalid_request` (`RspamdRequestError`, not retryable). `scan_events_skipped_total{reason}` also has `already_final` (a redelivery after this engine finalized) and `duplicate` (ledger). Failure rows carry `settings_version = NULL` (no settings were applied to a verdict).
- **S6 reason ordering of a round.** Rule severity is engine-specific, so the round's union orders codes by the severity of the final that raised them (failures first, then malicious … clean), then by name; each engine's own list is ordered by rule severity then name (S7).
- **S7 mapping details.** R8 adds `spam.suspicious_score` only when the score is below `spamScore` (R5 already says `spam.score`). R3's auth failure uses the normalized DMARC result `fail` or SPF `fail` (symbol or normalized result). R10 adds `clean.below_threshold` whenever the verdict is clean (informational codes stay, e.g. `auth.dkim_fail` on the body-altered fixture). Categories as data in `symbol-catalog.ts`: WP2's reputation symbols are signed singles, so `SENDER_REP` counts as `reputation.domain_listed` only with a positive score (`SENDER_REP_SPAM` kept for production names); `fuzzy.unknown` is the code of "fuzzy unknown flags" (`EG_FUZZY_UNKNOWN`, `FUZZY_UNKNOWN`). R1 `engine.too_large` records score/required score/action NULL and no signals. GTUBE is a definite result (WP2's `passthroughModule`), mapped by R4.
- **S8 cache.** `SCAN_SETTINGS_CACHE_TTL_MS` accepts 0 (no cache; the integration suites use it); the default stays 30 000, max 300 000.
- **S9 version.** The `Server: rspamd/<v>` header of every `/checkv2` reply is used; the controller `/stat` (read password, 2 s budget) only when a reply carries none, cached for `SCAN_ENGINE_VERSION_TTL_MS`; otherwise `engineVersion = 'unknown'` (never blocks a scan).
