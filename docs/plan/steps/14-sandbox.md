## 2. Decisions

### 2.0 Invariants (never traded away)

1. **No execution of unknown files outside an approved runner.** Production accepts `SANDBOX_BACKEND ∈ {disabled, static}` only. `hardened-container` runs only with `APP_ENV ∈ {local, ci}`, outside Kubernetes, with `SANDBOX_ALLOW_NON_VM_EXECUTION=true`, and is labelled "not a VM boundary" everywhere it is reported (readiness, metrics info series, logs, result `isolation = container`). `vm` refuses until its preflight proves isolation **and** a runner exists (not in 4.6). Only synthetic benign samples written for the tests and the EICAR test string are ever executed or stored; **no real malware is downloaded or committed**.
2. **Never clean by accident.** `not_executed`, `failed`, `timeout`, static-only and non-VM executions never yield `clean`. `clean` exists only as rule C1 of `sandbox-map/1` (isolation `vm`), unreachable in 4.6.
3. **The controller holds nothing worth stealing.** No database, Redis, main-S3, token, DLP, DKIM, AI or other broker credential (configuration refuses to start, naming keys only); only its broker user `eg-sandbox`, its sandbox-bucket S3 user (`samples/` read, `artifacts/` write), `SANDBOX_SAMPLE_KEY`, `SANDBOX_RESULT_KEY` and the artifact **public** key.
4. **No route to tenant data or metadata** from the controller or any runner (§X5, threat model §4.5).
5. **No email content in MySQL, events, logs or metrics.** Rows and events hold ids, hashes, sizes, types, codes, counts, host names / IPs of observed indicators, path **hashes** and object keys; sample and artifact bytes live only in the sandbox bucket, sealed, and in process memory / runner scratch. Indicators are never metric labels; URLs paths are hashed.
6. **The mail round never waits for the sandbox and its verdict never changes the round** (asynchronous engine, X10). Delivery is unaffected by any sandbox outage.
7. **Idempotent everywhere:** `processOnce` ledgers on both email-worker consumers, state-conditional updates, the unique `dedupe_key`, the unique final row per `(scan, engine)`; the stateless controller's duplicates are absorbed downstream.
8. **Tenant from trusted context.** The dispatcher checks the envelope organization against the submission row and the part key prefix; results are bound to the analysis row (organization, SHA-256, task id, result MAC); the api scopes by the authenticated organization.
9. **Every runner and scratch area is removed** on success, failure, timeout and controller crash; leftovers are reaped at startup and on a timer, metered and alerted.
10. **Bounded everything** by validated configuration: samples, artifacts, indicators, processes, durations, memory, pids, CPU, concurrency, queue length, retries, batch sizes.

### X1. The `sandbox-controller` deployable (ADR-0039 decision 1)

- New Nest app `apps/sandbox-controller` (package `@email-gateway/sandbox-controller`), pino logger, zod config, `/health/live`, `/health/ready`, `/metrics` on `SANDBOX_HTTP_PORT` (3092). Image built from the generic `infrastructure/docker/node-service.Dockerfile` (`APP=sandbox-controller`); no Prisma client in the bundle (the app does not depend on `@email-gateway/database`).
- **Forbidden configuration** (`FORBIDDEN_KEYS` / `FORBIDDEN_PREFIXES`, also their `<KEY>_FILE` variants; refusal names keys only, exit code 1, unit-tested): prefixes `DATABASE_`, `MYSQL_`, `REDIS_`, `S3_`, `MINIO_`, `URL_TOKEN_`, `AUTH_`, `DLP_`, `BEC_LLM_`, `CLICK_`; keys `DATA_ENCRYPTION_KEY`, `DATA_ENCRYPTION_KEY_PREVIOUS`, `ATTACHMENT_CACHE_HMAC_KEY`, `URL_CACHE_HMAC_KEY`, `URL_EGRESS_PROXY_TOKEN`, `ANTHROPIC_API_KEY`, `SANDBOX_ARTIFACT_PRIVATE_KEY`, `RABBITMQ_URL`, `RABBITMQ_ADMIN_URL`, `RABBITMQ_DEFAULT_USER`, `RABBITMQ_DEFAULT_PASS`, and every `RABBITMQ_*_URL` / `RABBITMQ_*_PASSWORD` except `RABBITMQ_SANDBOX_URL` / `RABBITMQ_SANDBOX_PASSWORD`. Because the sandbox's own S3 settings must not match the `S3_` prefix, they are named `SANDBOX_S3_*` (§5).
- Host-run development never loads `../../.env` wholesale (it holds forbidden keys): `pnpm --filter @email-gateway/sandbox-controller dev` runs `scripts/dev-env.mjs` (in the app), which reads `../../.env`, keeps only the controller's allow-listed keys, rewrites container host names to `127.0.0.1` and published ports, and spawns `dist/main.js`. Integration tests build the config from explicit env objects.
- **Startup order:** load config (refusals) → build the backend (factory) → `backend.selfTest()`; a failing self-test of `vm` or `hardened-container` **refuses to start** (exit 1, log `sandbox backend refused: <code>`); `static` and `disabled` start and report readiness → reaper `startup` pass (X8) → start the consumer. Shutdown: stop consuming, wait for in-flight tasks up to `SANDBOX_TASK_TIMEOUT_MS`, abort the rest (their runners are removed in `finally`; anything left is reaped next start), close the backend.

### X2. Isolation backend interface (`apps/sandbox-controller/src/backends/backend.ts`, written in WP1)

```ts
export type BackendName = 'disabled' | 'static' | 'hardened-container' | 'vm';
/** What isolates the sample: nothing runs (none), an isolated analyzer process (process), a hardened shared-kernel container (container — NOT a VM boundary), a VM-class runtime (vm). */
export type IsolationClass = 'none' | 'process' | 'container' | 'vm';
export type SandboxProfile = 'static' | 'execute' | 'browser';

export interface TaskLimits {
  wallTimeoutMs: number;
  memoryMb: number;
  cpuMillis: number;
  pids: number;
  scratchMb: number;
  maxArtifacts: number;
  maxArtifactBytes: number;
  maxTotalArtifactBytes: number;
}
export interface SandboxTaskInput {
  taskId: string;
  analysisId: string;
  organizationId: string;
  profile: SandboxProfile;
  sample: { bytes: Buffer; sha256: string; sizeBytes: number; detectedType: string };
  limits: TaskLimits; // already clamped to the controller maxima
  deadlineAt: Date;
}
export interface RunContext {
  signal: AbortSignal; // aborted at the task timeout or shutdown
  scratchDir: string; // controller-side per-task directory (0700), removed by the caller
  logger: Logger; // ids only
  now(): Date;
}
export interface RawArtifact {
  kind: ArtifactKind;
  contentType: ArtifactContentType;
  bytes: Buffer;
}
export interface BackendObservation {
  status: 'completed' | 'not_executed' | 'failed';
  executed: boolean;
  notExecutedReason: NotExecutedReason | null;
  errorCode: SandboxErrorCode | null;
  observations: SandboxObservations; // shape of the task_completed.v1 `observations` (§4)
  artifacts: RawArtifact[]; // in memory, bounded by limits; sealed by the controller
  analyzerVersion: string | null;
  cleanup: { runnerRemoved: boolean | null; scratchRemoved: boolean };
}
export interface BackendSelfTest {
  ok: boolean;
  code: string; // 'ok' | refusal code (e.g. 'not_in_kubernetes', 'runtime_class_missing', 'handler_not_allowed', 'self_test_failed', 'vm_runner_not_implemented', 'docker_unreachable', 'spec_not_enforced')
  details: Record<string, string | number | boolean>; // bounded; never secrets
}
export interface ReapReport {
  runnersRemoved: number;
  scratchRemoved: number;
  failures: number;
}
export interface SandboxBackend {
  readonly name: BackendName;
  readonly isolation: IsolationClass;
  readonly version: string; // e.g. 'disabled/1', 'sandbox-static/1', 'hardened-container/1+runner:<image digest prefix>'
  readonly executes: boolean;
  selfTest(signal: AbortSignal): Promise<BackendSelfTest>;
  supports(
    task: Pick<SandboxTaskInput, 'profile' | 'sample'>,
  ): { ok: true } | { ok: false; reason: NotExecutedReason };
  run(task: SandboxTaskInput, ctx: RunContext): Promise<BackendObservation>;
  /** Removes runners/scratch this backend created that are not in `active` task ids. */
  reap(active: ReadonlySet<string>, mode: 'startup' | 'periodic'): Promise<ReapReport>;
  close(): Promise<void>;
}
export class BackendRefusedError extends Error {
  constructor(readonly code: string) {
    super(`sandbox backend refused: ${code}`);
  }
}
```

`NotExecutedReason`, `SandboxErrorCode`, `ArtifactKind`, `ArtifactContentType` and `SandboxObservations` come from `@email-gateway/security-contracts` (`sandbox.ts`, WP1). A backend never throws for a sample property: it returns `not_executed` or a completed observation with findings; it throws only for infrastructure faults (classified by the task handler, X7).

### X4. Static analysis (`apps/sandbox-controller/src/backends/static/`)

- **Child process isolation** (the ADR-0036 pattern, own small pool in this app; the email-worker `ChildPool` cannot be imported across apps): `child_process.fork` of `dist/backends/static/analyzer-child.js` with `env: {}`, `execArgv: ['--permission', '--allow-fs-read=<dist dir>', '--allow-fs-read=<task scratch>/in', '--allow-fs-write=<task scratch>/out', '--max-old-space-size=<SANDBOX_STATIC_HEAP_MB>']` (no `--allow-child-process`, no `--allow-worker`, no addons), cwd = the task scratch, IPC handshake with `ANALYZER_VERSION`; the parent samples RSS and CPU from `/proc/<pid>` (Linux) and kills on `SANDBOX_STATIC_MAX_RSS_MB`, `SANDBOX_STATIC_CPU_SECONDS` or `SANDBOX_STATIC_TIMEOUT_MS`; `prlimit` (RLIMIT_CPU/AS) as a backstop when available; one child per task (no reuse across tasks), killed and reaped in `finally`. The sample is written to `<scratch>/in/sample` with mode `0400` (never executable). A crash or kill is `failed` with `analyzer_crashed` / `analyzer_timeout`; a resource kill on a parse is a finding `limit.analyzer_resources` (medium) — the file is hostile to parsers.
- **Analyzers** (pure TypeScript, bounded input = the sample, bounded output; version `sandbox-static/1`; each has unit tests with synthetic fixtures generated in the test, never real malware):
  - `pe`: DOS/PE headers, machine, section names/entropy, import table names (no full disassembly); findings `static.pe_injection_imports` (VirtualAllocEx/WriteProcessMemory/CreateRemoteThread/NtUnmapViewOfSection families), `static.pe_downloader_imports` (URLDownloadToFile, InternetOpenUrl + WinExec/ShellExecute), `static.pe_packed` (UPX/ASPack/MPRESS section names, entropy > 7.2 on executable sections), `static.pe_anti_debug` (IsDebuggerPresent, CheckRemoteDebuggerPresent), `static.pe_overlay`.
  - `elf`: header sanity, `static.elf_packed` (UPX! magic, entropy).
  - `ole`: Compound File Binary directory walk (bounded sectors/entries), VBA project streams, **MS-OVBA decompression** of module source (bounded), keywords → `static.office_macro`, `static.office_auto_exec` (AutoOpen, Document_Open, Workbook_Open, Auto_Open, AutoExec), `static.office_macro_shell` (Shell, WScript.Shell, CreateObject("…Shell"), URLDownloadToFile, powershell), `static.office_ole_object`.
  - `ooxml`: zip central directory (bounded entries, inflate caps), `vbaProject.bin` (→ `ole` analyzer), relationships with `TargetMode="External"` on `attachedTemplate`/`oleObject`/`frame` → `static.office_external_template`, `DDEAUTO`/`DDE` field codes → `static.office_dde`, embedded `oleObject*.bin` → `static.office_ole_object`.
  - `pdf`: tokenizer for names (with `#xx` decoding → `static.pdf_obfuscated_names`), counts of `/JavaScript`, `/JS`, `/OpenAction`, `/AA`, `/Launch`, `/EmbeddedFile`, `/RichMedia`, `/XFA`, `/URI` (hosts extracted) → `static.pdf_javascript`, `static.pdf_open_action_js` (OpenAction/AA with JS), `static.pdf_launch`, `static.pdf_embedded_file`.
  - `html`/`svg` (no rendering, no script execution): `<script>` count, `eval`/`atob`/`unescape`/`String.fromCharCode` density, `Blob` + `URL.createObjectURL` + `download` / `msSaveOrOpenBlob` / data-URI downloads → `static.html_smuggling`, password inputs → `static.html_password_form`, form actions to other hosts → `static.html_external_form`, external meta refresh → `static.html_meta_refresh_external`, heavy obfuscation → `static.html_obfuscated_script`.
  - `script` (js, vbs, ps1, bat, sh, hta): encoded PowerShell (`-enc`, `-EncodedCommand`, `FromBase64String`) → `static.script_encoded_powershell`; download cradles (`DownloadString`, `Invoke-WebRequest`, `curl|wget … | sh`, `XMLHTTP` + `ADODB.Stream`) → `static.script_download_cradle`; LOLBins (`mshta`, `regsvr32 /i:http`, `rundll32 …javascript:`, `certutil -decode|-urlcache`, `bitsadmin`) → `static.script_lolbin`; `WScript.Shell`/`ActiveXObject`/`child_process`/`eval` of long strings → `static.script_shell_exec`; obfuscation (long base64 runs, char-code arrays, string reversal) → `static.script_obfuscation`.
  - `lnk`: Shell Link header + CLSID → `static.lnk_present`; command-line arguments naming powershell/cmd/mshta/rundll32 → `static.lnk_command`.
  - `generic` (all types): EICAR test string (built from parts in code, never a committed file) → `static.eicar_test`; URL/host/IPv4 extraction (bounded, hosts only, IPs canonical) → `static.embedded_urls` / `static.embedded_ips` (info) and network indicators of kind `static`; overall entropy > 7.5 → `static.high_entropy` (low).
- Static analysis never evaluates the sample: no `eval`, no `vm` module, no JS engine for page scripts, no decompressor beyond bounded inflate/MS-OVBA, no external tools. A test proves that a benign probe script that would write a marker file and query the sinkhole when executed is **not** executed by `static` (no marker, no sinkhole record, `executed: false`).

Records are kept per source IP in a bounded ring (≤ 1 000 per IP, ≤ 50 000 total, TTL 15 min). Admin HTTP on `172.31.252.53:3094` only (bind to the control address), bearer token `SANDBOX_SINKHOLE_ADMIN_TOKEN` (constant-time compare): `GET /records?ip=&since=` and `DELETE /records?ip=`, `/health`. Never forwards anything.
- Production (documented in `docs/deployment/sandbox.md`, rendered manifests only): controller NetworkPolicy egress only to the broker, the S3 endpoint and DNS, denying `169.254.0.0/16`, `fd00:ec2::/32` and the cluster pod/service CIDRs except the broker; no ingress except Prometheus on 3092; `automountServiceAccountToken: false` (the `vm` backend, when it exists, gets a dedicated namespaced service account).

### X6. The `hardened-container` runner (local/CI only; `apps/sandbox-controller/src/runner/`)

The controller enforces the outer wall timeout (`wallTimeoutMs + 5 s`): on expiry it kills and removes the runner and reports `limit.wall_timeout`; on exit it reads `inspect.State.OOMKilled`, exit code and the stdout frame (malformed or over-cap output → `output_invalid` finding `limit.output_truncated`, never a failure of the controller). Output from the runner is **untrusted** (the sample can tamper with it in the same uid): it is parsed with strict bounded schemas and only ever becomes evidence.
- **Network indicators:** after the run the controller fetches the sinkhole records for the runner's IP and the run window (admin API), then deletes them; merged with the trace's `connect()` attempts (direct-IP connects show as `unreachable`/`refused`).
- **Self-test** (startup and every `SANDBOX_SELF_TEST_INTERVAL_MS`): `_ping`; the runner image exists; a probe runner (`bootstrap.mjs --self-test`) must report uid ≠ 0, `CapEff` = 0, `NoNewPrivs` = 1, `Seccomp` = 2, root filesystem read-only, `/scratch` writable, no default route except the detonation subnet, DNS = sinkhole, no `/var/run/docker.sock`, empty environment; `details: { apparmor: <bool>, seccomp: true, dockerVersion, runnerImage }`. Any failure → `ok: false` (`spec_not_enforced`); at startup the controller refuses to start, at runtime readiness fails and the consumer is paused (X7).
- **Escape-resistance** is verified by the suite of §9.3 against this runner.

### X7. Task handling and the state machine (`apps/sandbox-controller/src/task/`)

- **Consumer:** `scan.sandbox` (stateless kind; the `@email-gateway/common` consumer with manual acks, prefetch = `SANDBOX_CONCURRENCY` (1, max 4), hold retries of the topology: 3 attempts, 5 s–60 s, max age 1 h). The handler refuses an unknown type/version or a tenant mismatch (fatal → dead-letter, as every consumer). When the backend self-test fails at runtime the consumer is **cancelled** (no nack loop) and resumed when it passes again.
- **States** (`task-state.ts`, a pure transition table with unit tests): `received → validated → admitted → (not_executed | fetching) → running → collected → cleaned → stored → published → acked`; side exits `rejected` (schema/tenant → dead-letter), `transient_failure` (S3/broker/Docker outage → retry with hold, no result), `failed` (budget exhausted or a non-retryable infrastructure error → a `failed` result is published), `deadline_passed` (→ `not_executed` result). Invariants (tested): every path that created a runner or scratch passes through `cleaned` before `published`/`acked`/retry; no path produces a `clean` verdict (the controller produces no verdict at all); `published` precedes `acked` (confirm first); a duplicate delivery of a task id already in flight in this process waits for the first and is acked without a second run (in-process map; cross-process duplicates are absorbed by the results consumer).
- **Steps:** validate (strict schema; sample key regex; organization of the routing key = envelope; `deadlineAt` not passed else `not_executed`/`deadline_passed`); clamp limits to the controller maxima (`SANDBOX_MAX_*`); `backend.supports()` false → `not_executed` with its reason (no S3 read); fetch the sample (`GetObject samples/…`, size ≤ `sizeBytes` and ≤ `SANDBOX_MAX_SAMPLE_BYTES`, `openSample` with `SANDBOX_SAMPLE_KEY`(+previous), plaintext SHA-256 = `sampleSha256` else `failed`/`sample_integrity`; `NoSuchKey` → `failed`/`sample_unavailable`; outage → transient); create the scratch dir (`SANDBOX_SCRATCH_DIR/<taskId>-<attempt>`, `0700`); `backend.run` under an `AbortSignal` of `SANDBOX_TASK_TIMEOUT_MS`; cleanup (backend runner removal inside `run`'s `finally`, then scratch removal; results recorded in `cleanup`); seal and store artifacts (X12; `PutObject artifacts/…`; outage → transient: the whole task is retried, the runner is gone already); build the result (bounded; `resultMac` X11) and publish with confirms to `email.security` (`org.<id>.mail.sandbox.task_completed.v1`); ack.
- Logs carry task id, analysis id, organization id, backend, status, codes and durations only — never sample names, indicators or artifact content.

### X8. Cleanup and the reaper

- Per task: `finally` removes the runner (`kill` + `DELETE ?force=true&v=true`, retried 3× with backoff; failure → `sandbox_cleanup_failures_total{kind="runner"}` + error log with the container id) and the scratch directory (`rm -rf` of the task directory only, refusing any path outside `SANDBOX_SCRATCH_DIR`; failure → `{kind="scratch"}`); the static analyzer child is killed (`SIGKILL`) and awaited.
- **Reaper** (`reaper/reaper.service.ts`): at startup before consuming (`mode: 'startup'`: every runner labelled `eg.sandbox.controller=<SANDBOX_CONTROLLER_NAME>` and every scratch entry — nothing of this process can be running yet) and every `SANDBOX_REAPER_INTERVAL_MS` (`mode: 'periodic'`: runners whose `eg.sandbox.expires` < now and that are not in the active set; scratch entries older than `SANDBOX_TASK_TIMEOUT_MS` + 60 s not in the active set). Each controller instance has a distinct `SANDBOX_CONTROLLER_NAME` (Compose: fixed; Kubernetes: the pod name via the downward API). Metrics `sandbox_reaped_total{kind,mode}`.
- Tests (§9) prove zero labelled containers and an empty scratch directory after success, failure, timeout, a runner crash, a killed controller (startup reap) and an orphan past expiry (periodic reap).

### X13. The sandbox engine in the email-worker (`apps/email-worker/src/scanning/sandbox/`)

Runs when `SCAN_ENABLED=true`, `SANDBOX_ENABLED=true` and `SCAN_CONSUMERS` is empty or contains `sandbox` (`SCAN_CONSUMERS` accepts `sandbox` although it is not in `SCAN_ENGINES`). Kubernetes runs it in its own Deployment `email-worker-sandbox` (`SCAN_CONSUMERS=sandbox`).

**Dispatcher** (`sandbox-dispatcher.ts`, ledger `email-worker.scan.sandbox`, concurrency `SANDBOX_DISPATCH_CONCURRENCY`), per `sandbox_requested.v1`:

1. Ledger pre-check; payload already schema-validated by the consumer; `organizationIdOfKey(attachment.objectKey)` = envelope organization, else fatal (`tenant_mismatch`).
2. Load the submission `(id, receivedAt)` on the writer with echo checks (organization, message, scan, attachment, part index, sha256, object key equal to the event; mismatch → `InconsistentReadError`, retryable). Missing → ledger no-op (warn, metric `skip{reason=submission_missing}`). Status ≠ `pending` and ≠ `submitted` → ledger no-op (`duplicate`).
3. **Settings:** plan feature `attachment_sandbox` (`organization_features`) and the tenant's `scan_engine_settings` row for engine `sandbox` through `resolveSandboxSettings` (invalid row → platform settings + the existing invalid-settings metric). Feature off → `skipped`/`feature_disabled`; `enabled` false → `skipped`/`tenant_disabled`; type ∉ `fileTypes` → `skipped`/`type_excluded`; size > `maxSampleBytes` → `skipped`/`size_excluded`. A skip updates the submission (`status = skipped`, `skip_reason`, `sandbox_reason_codes`, `completed_at`) and runs the round check (X15) in one transaction with the ledger row.
4. **Profile:** `browser` for `html`/`svg` when `browserAnalysis`; `execute` for `script_*`, `hta`, `pe_executable`, `msi`, `elf`, `lnk`; `static` otherwise. **Limits** from `SANDBOX_RUN_*` (browser: memory ≥ 1024 MiB, pids ≥ 256). `analysisKey = sha256(JSON{ profile, limits, epoch: SANDBOX_ANALYSIS_EPOCH, map: 'sandbox-map/1' })[0..16]`; `dedupeKey = <sha256>:<analysisKey>`.
5. **Dedup (transaction A):** `SELECT … FROM sandbox_analyses WHERE dedupe_key = ? FOR UPDATE`. Reusable (terminal with `reuse_until > now`) → link (`analysis_id`, `status = submitted`) and complete the submission from the stored analysis right away (X15) — no staging, no task; in flight (`pending`/`dispatched`, `deadline_at > now`) → link only; stale → set its `dedupe_key = NULL` and create; none → create `sandbox_analyses` (`status = pending`, `public_id` UUIDv7, `organization_id` = this submission's organization, `sample_object_key`, `deadline_at = now + SANDBOX_TASK_DEADLINE_SECONDS`, `expires_at = now + SANDBOX_ANALYSIS_RETENTION_DAYS`) and link. A unique violation on `dedupe_key` (a concurrent dispatcher) → re-read and link.
6. **Staging** (only by the event that created the analysis, or by its redelivery while the analysis is still `pending`): read the part from the mail bucket (key = the submission's `object_key`, prefix `org/<org>/part/` re-checked), bounded by `maxSampleBytes` and `SCAN_S3_TIMEOUT_MS`, SHA-256 must equal the submission (else the analysis → `failed`/`sample_integrity`, `dedupe_key = NULL`, the submission → `failed`; X15), seal (`sandbox-sample/1`) and `PutObject` to the deterministic sample key (idempotent overwrite). `NoSuchKey` → submission and analysis `failed`/`sample_unavailable`. S3 outage → transient (retried without consuming an attempt).
7. **Transaction B:** `UPDATE sandbox_analyses SET status = 'dispatched', dispatched_at = now WHERE id = ? AND status = 'pending'`; only when one row changed: the `mail.sandbox.task_requested.v1` outbox row (aggregate `sandbox_analysis`, aggregate id = analysis id, organization = the analysis organization). Then the ledger row. Idempotent by state: a redelivery after A or after the put resumes; after B it is a ledger duplicate.

**Results consumer** (`sandbox-results.ts`, ledger `email-worker.scan.sandbox.results`, concurrency `SANDBOX_RESULTS_CONCURRENCY`), per `task_completed.v1`:

1. Ledger pre-check; validate the payload (event schema) **and** every code against the security-contracts enums (unknown finding/reason/error codes → reject `invalid_result`); then, inside the transaction of step 2 after the analysis lock (it needs the analysis's `result_token_sha256`), verify `resultMac` (whole payload + organization, timing-safe; mismatch or no token hash → reject `bad_mac`). Rejections write a ledger no-op row, `scan_sandbox_results_rejected_total{reason}` and a warning with ids only.
2. Transaction (`SCAN_DB_TIMEOUT_MS`): `SELECT … FROM sandbox_analyses WHERE id = ? FOR UPDATE` with echo (public id = task id, sha256, organization = envelope; mismatch → reject `analysis_mismatch`); status must be `dispatched` (`pending` → reject `not_dispatched`; terminal → ledger no-op `duplicate`; `expired` → ledger no-op `late`, metric). Every artifact key must start with `artifacts/<yyyy>/<mm>/<taskId>/` and be unique by `seq` (else reject `artifact_key_invalid`).
3. `mapAnalysis` (`sandbox-map/1`, X14) → verdict and reason codes; update the analysis (status `completed`/`not_executed`/`failed`, verdict, codes, the bounded `report` view, backend, backend version, isolation, executed, controller/analyzer/map versions, not-executed reason, error code, duration, `result_event_id`, `completed_at`, `reuse_until` by verdict: definite `malicious`/`suspicious` `SANDBOX_REUSE_DEFINITE_SECONDS`, `unknown` from a completed run `SANDBOX_REUSE_UNKNOWN_SECONDS`, `not_executed` `SANDBOX_REUSE_NOT_EXECUTED_SECONDS`, `error` never — `dedupe_key = NULL`); insert `sandbox_artifacts` rows (`expires_at = now + SANDBOX_ARTIFACT_RETENTION_DAYS`).
4. Complete up to 200 linked `submitted` submissions (X15) in the same transaction; the sweeper completes the rest. Optional: `SANDBOX_PUBLISH_HASHES=true` and verdict `malicious` → `INSERT IGNORE` into `malware_signatures` (`source = 'sandbox'`, severity `high`, `expires_at = now + 90 days`, `reason = 'sandbox analysis <public id>'`).
5. Ledger row; commit. After commit, best effort: delete the sample object and set `sample_deleted_at` (failures left to the sweeper).

| F1   | status `failed`                                                                                                                                                    | `error`      | `sandbox.error`, `sandbox.error.<errorCode>`                         |
| F2   | expired by the sweeper (no result by the deadline)                                                                                                                 | `timeout`    | `sandbox.timeout`                                                    |
| N1   | status `not_executed`                                                                                                                                              | `unknown`    | `sandbox.not_executed`, `sandbox.not_executed.<reason>`              |
| M1   | any finding with severity `critical` or `high` (e.g. `behaviour.metadata_access`, `static.office_auto_exec` with `static.office_macro_shell`, `static.eicar_test`) | `malicious`  | `sandbox.<finding code>` per finding                                 |
| S1   | any finding `medium`, or any resource limit hit other than `wall_timeout`/`output_truncated`/`artifact_cap`                                                        | `suspicious` | `sandbox.<finding code>`, `sandbox.limit.<limit>`                    |
| U1   | completed, `executed: false` (static only)                                                                                                                         | `unknown`    | `sandbox.static_only`, `sandbox.no_findings` (when no finding ≥ low) |
| U2   | completed, executed, `isolation ≠ vm`                                                                                                                              | `unknown`    | `sandbox.not_vm_isolated`, `sandbox.no_findings` (when none)         |
| U3   | completed, executed, `isolation = vm`, and (run shorter than `minRuntimeMs` or any `evasion.*` finding)                                                            | `unknown`    | `sandbox.incomplete_run` / `sandbox.evasion_suspected`               |
| C1   | completed, executed, `isolation = vm`, no finding ≥ low, no evasion, run ≥ `minRuntimeMs` (default 30 s)                                                           | `clean`      | `sandbox.no_findings`                                                |

Low and info findings are kept as codes but never raise the verdict. Severities are fixed per finding code in `SANDBOX_FINDING_SEVERITY` (security-contracts); tenants cannot change them in 4.6. Per submission: skipped submissions carry `sandbox.tenant_disabled` / `sandbox.feature_disabled` / `sandbox.type_excluded` / `sandbox.size_excluded` / `sandbox.part_unavailable` / `sandbox.part_integrity` codes and no verdict. **Round-level final** (`aggregateSubmissions`): `malicious` > `suspicious` > `error` > `timeout` > `unknown` > `clean` over non-skipped submissions; all skipped → outcome `skipped` (codes of the skips). The final row records `engine_version = <controller version>+<backend>/<backend version>` of the most severe analysis (or `sandbox-engine/1` when all skipped), `settings_version` of the dispatch-time resolution (stored on the submission), `attempt = 1`, `duration_ms = 0` (async), reason codes ≤ 16, and `evidence = { submissions: n, executed: m, isolation: [...] }`.

### X15. Completing submissions and the round final (`sandbox-finalizer.ts`)

Shared by the dispatcher (skips, reuse), the results consumer and the sweeper, always inside the caller's transaction:

1. `UPDATE sandbox_submissions SET status = <completed|failed|expired|skipped>, sandbox_verdict, sandbox_reason_codes, skip_reason, completed_at, external_ref = <analysis public id> WHERE id = ? AND received_at = ? AND status IN ('pending','submitted')`; only if one row changed: one `mail.attachment.sandbox_completed.v1` outbox row for the submission's organization.
2. For each distinct scan of the changed submissions: `SELECT id FROM email_scans WHERE id = ? AND received_at = ? FOR UPDATE` (serializes concurrent finishers of one round), then if no submission of that scan is `pending`/`submitted`: insert the `sandbox` final row (`scan_engine_results`, `is_final = true`; a unique violation = already written, ignored). The final may be written before or after the round's completion; it never touches `email_scans` or the lifecycle (X10).

### X16. Sweeper (`sandbox-sweeper.ts`, leader lock `scan:sandbox`)

Every `SANDBOX_SWEEP_INTERVAL_MS` (60 s), batches of `SANDBOX_SWEEP_BATCH` (500), each batch its own transaction (`SCAN_DB_TIMEOUT_MS`), in this order: (a) `pending` submissions older than `SANDBOX_SUBMISSION_TTL_SECONDS` → `expired` (`sandbox.timeout`) — also covers pre-4.6 rows and a stopped dispatcher; (b) `pending`/`dispatched` analyses with `deadline_at < now` → `expired` (verdict `timeout`, `dedupe_key = NULL`) and their linked submissions → `expired`; (c) `submitted` submissions whose analysis is terminal → completed from the analysis (catch-up of X13 step 4); (d) terminal analyses with `sample_object_key` and no `sample_deleted_at` → delete the object (`NoSuchKey` = done) and set `sample_deleted_at`; (e) artifacts with `expires_at < now` and `purged_at IS NULL` → in a transaction `wrapped_key = NULL, purged_at = now, purge_reason = 'retention'` (crypto-shredding first), then delete the object and set `object_deleted_at` (retried until done); (f) analyses with `expires_at < now` whose artifacts are all object-deleted → delete artifact rows, then the analysis row. Metrics per step.

### X19. Resilience and failure recovery

| Failure                               | Behaviour                                                                                                                                                                                                                        |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Runner crash / OOM / pids exhaustion  | The run ends; observation `completed` with `limit.*` findings (a property of the sample) — or `failed`/`runner_crashed` when the runner died without a parseable frame for a non-limit reason; runner removed; result published. |
| Controller crash or restart mid-task  | The task is unacked → redelivered by the broker; the startup reaper removes the orphan runner and scratch; the redelivered task runs again; duplicate results (if the first was published) are ledger no-ops downstream.         |
| Broker redelivery / duplicate task    | In-process duplicate suppression; otherwise a second run and a second result, absorbed (`duplicate`).                                                                                                                            |
| S3 outage (controller)                | Sample fetch or artifact put fails → transient retry (hold) up to max age 1 h → then a `failed` result (`storage_unavailable`) if publishing works, else the analysis expires (`timeout`).                                       |
| S3 outage (email-worker)              | Staging fails → transient retry of the submission event; sample/artifact deletes retried by the sweeper.                                                                                                                         |
| Broker outage (controller)            | Publish with confirms fails → the task is not acked; reconnection by the common client; retried.                                                                                                                                 |
| Controller absent / backend not ready | Tasks wait in the bounded lossy `scan.sandbox` (dropped beyond 10 000); analyses expire at their deadline → `timeout`. Mail flow unaffected.                                                                                     |
| MySQL outage (email-worker)           | Consumers retry transiently; results stay in `scan.sandbox.results` (work queue).                                                                                                                                                |
| Wrong reads (4.2 §6)                  | Echo checks on every deciding read (submission, analysis, scan lock); mismatch → `InconsistentReadError`, retryable; metric `scan_sandbox_inconsistent_reads_total{read}`.                                                       |
| Forged result                         | Rejected (MAC, state, organization, hash, key prefix); metered and alerted.                                                                                                                                                      |

## 6. Prisma wrong-read mitigation in this step (4.2 §6)

New interactive transactions: dispatcher A and B, the results transaction, the finalizer (inside them), every sweeper batch — all with `SCAN_DB_TIMEOUT_MS` (≥ 120 s), no socket timeout. Echo checks on: the submission read (ids, sha256, object key, organization), the analysis read (public id, sha256, organization, status), the `email_scans` lock row (id, received_at), the linked-submissions read (each row's `analysis_id` equals the analysis). Mismatch → `InconsistentReadError` (retryable; metric). No new code uses Prisma's default 5 s budget.

## 7. Alternatives considered

- **Required stage-2 sandbox engine** (round waits): in production it could only answer `not_executed`, adds a hard dependency and latency; rejected for 4.6 (ADR-0040). **Optional engine counted in the aggregation:** order-dependent verdicts; rejected.
- **Controller consumes `sandbox_requested.v1` with a read grant on tenant parts** (ADR-0028 decision 8 as written): the most exposed component would read every tenant's attachments; rejected for staging by the email-worker. **Staging inside the attachment engine:** couples a required engine to the sandbox bucket; rejected.
- **Sandbox inside the email-worker:** an escape lands next to MySQL, Redis, tenant S3 and every key; rejected. **Privileged controller / Docker-in-Docker:** equals host root; rejected. **nsjail/bubblewrap:** needs capabilities the locked-down container lacks and is still shared-kernel; rejected.
- **Implementing the Kubernetes VM runner now:** cannot be verified here; an unverified execution path would be presented as working; rejected (preflight only).
- **Cuckoo/CAPE, commercial or hosted sandboxes:** nested virtualization or third-party data transfer; possible future backends behind X2.
- **`dockerode`:** a large dependency tree for ~10 endpoints; the own client is small and auditable.
- **Symmetric artifact encryption (DLP pattern):** a compromised controller could open earlier artifacts; asymmetric wrap chosen. **HMAC result signing with a key in the task:** the task reaches the analytics firehose; the MAC key is out-of-band instead.
- **Re-using `url-browser-worker` as a long-lived browser analysis service:** a long-lived browser would carry state between samples; disposable runners from the same image chosen.
- **Packet capture (tcpdump) for network indicators:** needs `NET_RAW`/`NET_ADMIN` on the sinkhole or runner; the sinkhole + `connect()` trace give the indicators without capabilities.
