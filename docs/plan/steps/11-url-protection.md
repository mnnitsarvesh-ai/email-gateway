## 2. Decisions

### 2.0 Invariants (never traded away)

1. **Never clean by accident.** A provider error or open breaker, a fetch that was attempted and did not complete, an SSRF block, an incomplete extraction (body not stored, limits) and a cache error are never `clean`. `clean` is reachable only through rule C1 (U10).
2. **No SSRF.** Every outbound HTTP(S) request of this step (scan-time fetch, click-time recheck, RDAP, browser traffic) goes through the one guarded connector of `@email-gateway/url-security` (U8) or through the egress proxy that uses the same guard. Nothing calls `fetch()`, `http.get()` with a host name, or `dns.lookup()` for a URL target.
3. **No email content in MySQL, Redis, events (except U15's URL), logs or metrics.** Rows hold normalized URLs, hashes, hosts, codes, counts and bounded structured findings; never page bodies, titles, anchor text or HTML. URLs are **never logged** (hash prefix only) and never used as metric labels.
4. **Idempotent per (message, round, engine)** through the 4.1 orchestrator and unique keys on every child row; a duplicate delivery writes nothing twice.
5. **Tenant from trusted context.** The engine takes the organization from the envelope checked against the writer row; S3 keys are checked against `org/<org>/`; the click service takes the organization only from a token whose MAC it verified, and checks every row against it; the api takes it from the authenticated scope.
6. **Engines classify, policy decides.** The URL engine records verdicts and produces a rewritten copy; it never blocks or quarantines a message. The click service decides only about the click.
7. **Never an open redirect.** The click service redirects only to the URL stored server side for a verified token, never to a URL taken from the request.
8. **Bounded everything** by validated configuration: URLs per message, bytes, hops, time, headers, DNS answers, cache entries, concurrent fetches, browser jobs, request rates.

### U1. One `url` engine on `scan.url`, required for every tenant

- **Catalog** (`security-contracts`): `{ name: 'url', stage: 'url', queue: 'scan.url', requiredByDefault: true, tenantMayDisable: false, description: 'URLs: extraction, normalization, reputation, lookalikes, redirect chains, rewriting (step 4.3)' }`. `SCAN_ENGINES` default `rspamd,attachment,url`.
- **Consumer:** email-worker scan role, broker user `eg-scanner`, ledger consumer **`email-worker.scan.url`**, registration `urlRegistration` in `ENGINE_REGISTRY` (the orchestrator iterates it, unchanged). Production runs it in its own Deployment `email-worker-url` with `SCAN_CONSUMERS=url`. The results consumer of U15 (`email-worker.scan.url.results`) and the pending-inspection sweeper run in every replica whose `SCAN_CONSUMERS` contains `url`.
- **No URLs (rule U0):** a complete extraction (bodies stored or absent, no limit hit, U4) with **zero** http(s) URLs and zero dangerous-scheme links → definite outcome **`skipped`**, reason `url.none`; a `url_rewrites` row with `status = skipped, skip_reason = no_urls` is still written. Tested explicitly.
- **Rspamd's URL symbols are not consumed at scan time.** Engines of one round run in parallel; reading the Rspamd final row would make the URL verdict depend on arrival order. Rspamd's URL findings already reach the round verdict through its own engine row and are combined by risk scoring (5.1). The local feed of U6 is the platform's own URL list (the `eg_bad_urls.map` test host is not copied into it).

### U3. Data flow of one engine call (`UrlEngine.scan(ctx, signal)`)

1. **Load (writer, echo-checked, A3 pattern of 4.2):** the `email_message_parses` row (status, `limits_exceeded`, body keys/hashes/sizes/charsets, `structure`), `email_attachments` rows of type html/text (U4), existing `message_urls` rows of the message (rescans), the tenant's active domains (`domains` with `status = 'active'`, LRU 60 s per org), effective settings (`ctx.settings`, U13). Every read selects and verifies its identifying columns (message, organization, `received_at`); a mismatch is the retryable attempt failure `error`/`inconsistent_read` (`scan_url_inconsistent_reads_total{read}`), never a verdict. No parse row → `error`/`parse_row_missing` (not retryable).
2. **Read parts** from S3 (key prefix `org/<org>/part/` and equal to the row; SHA-256 and size verified against the row; `NoSuchKey` → `error`/`part_unavailable` not retryable; integrity → `part_integrity` not retryable; other S3 errors thrown → transient). Reuse the 4.2 `S3PartReader` (move it to `scanning/parts/` if needed; do not duplicate).
3. **Extract** (U4) and **normalize** (U5) → unique URL list, per-URL extraction flags and sources, message-level codes. Assign `url_seq`: existing `message_urls` rows keep their seq (matched by `url_sha256`); new URLs get `max + 1…` in extraction order.
4. **Static analysis per URL** (pure): lookalike (U7), host checks, obfuscation flags, anchor-text mismatch.
5. **Reputation** (U6) for every unique URL, host, registrable domain and resolved/literal IP, through providers with the breaker and cache, bounded concurrency `URL_PROVIDER_CONCURRENCY`. Resolved IPs: the public A/AAAA answers of every domain host (restricted resolver, `HostAddressResolver`, ≤ 4 per host; internal answers are dropped), for the URL hosts before the lookup and for the chain hosts after the fetches (review round 1).
6. **Fetch selection and fetch** (U8, U9): at most `URL_FETCH_MAX_PER_MESSAGE` URLs selected by `scanTimeFetch` (shorteners first, then by risk), redirect chain resolution and static landing features; final URLs of chains go through reputation (step 5) too.
7. **Map** (U10) per URL and aggregate to the engine result.
8. **Rewrite** (U11): when enabled for this message, stream the EML through the rewriter and upload the rewritten copy to S3 (outside any transaction). An S3 upload error is thrown (transient). A rewrite that cannot be done safely is a `skipped` rewrite, not a failure.
9. **Dynamic inspection requests** (U15): up to `URL_DYNAMIC_MAX_PER_MESSAGE` URLs with verdict `suspicious` or `unknown` (not `malicious`, not `clean`), when enabled.
10. Return `{ kind: 'definite', result, childRows: { urls: { messageUrls, results, rewrite, inspections } } }`. `ScanRepository.insertFinal` inserts them (U16) only when the final row was inserted, in that transaction (`createMany` with `skipDuplicates` for `message_urls`; unique keys elsewhere), plus one `inspection_requested.v1` outbox row per inspection.

The engine call timeout `SCAN_URL_TIMEOUT_MS` covers the whole message. **Failure classes:** internal infrastructure (S3 read/write, MySQL, wrong read) → attempt failure (retry, breaker for `engineFault` only); **external** problems (a target site, a DNSBL or RDAP outage, an open provider breaker) → definite per-URL `unknown` with a reason code: mail flow never depends on third parties, and the result is never clean.

### U4. Extraction (`@email-gateway/url-security` `extract/`)

- **Sources (no re-parse of the EML):** the stored text body (UTF-8), the stored HTML body (UTF-8), and up to `URL_MAX_EXTRA_PARTS` (default 5) `email_attachments` rows whose detected or declared type is `text/html` / `text/plain` (or extension `.htm`, `.html`, `.shtml`, `.xhtml`, `.txt`) and whose size is ≤ `URL_EXTRA_PART_MAX_BYTES` (default 2 097 152). Attachment bytes are decoded with the charset from `structure` (else the HTML `<meta charset>` within the first 1 024 bytes, else UTF-8 with flag `url.charset_guess`). URLs found only in attachments get the informational code `url.in_attachment` and are never rewritten.
- **HTML** (parse5, WHATWG tokenizer, `sourceCodeLocationInfo: true`; never rendered, never re-serialized): `a[href]`, `area[href]`, `form[action]`, `button[formaction]`, `input[formaction]`, `iframe|frame|img|script|embed|source|video|audio|track[src]`, `img|source[srcset]` (each candidate), `link[href]`, `object[data]`, `meta[http-equiv=refresh][content]` (`url=` part), `base[href]` (resolves relative URLs; only an absolute http(s) base is used). Relative URLs without a usable base are ignored. Anchor text of `a` is kept in memory only, to detect **text mismatch** (U10 S7: the visible text is URL-like and its registrable domain differs from the href's).
- **Plain text** (text body and HTML text nodes are _not_ the same thing: only the text body and text attachments): RFC 3986 URLs with `http://`, `https://` (case-insensitive) and `www.` (treated as `http://`), terminated by whitespace, `<>"` and trailing `.,;:!?)]}'` unless balanced; `<URL:…>` and `<…>` wrappers.
- **Obfuscations** (reason codes, URL still extracted): entities in the raw attribute source of the scheme/host part (`&#104;ttp`, `&colon;`) → `url.entity_obfuscation`; percent-encoded host → `url.obfuscated_host`; tab/newline/control characters inside the raw value → `url.control_chars`; decimal/octal/hex/short IPv4 forms (`http://2130706433/`, `0177.0.0.1`, `0x7f.1`, `127.1`) → `url.ip_obfuscated`; userinfo → `url.userinfo`.
- **Schemes:** `http`, `https` → URL rows. `javascript:`, `vbscript:` in any link attribute → message code `url.script_scheme`; `data:` in `href`/`action`/`iframe src`/`object data` → `url.data_uri` (data images in `img src` are ignored); `file:`, `smb:`, UNC `\\host\share` in a link → `url.unsafe_scheme`. These are counted per message (no rows). `mailto:`, `tel:`, `sms:`, `cid:`, `#fragment` links are ignored.
- **Bounds:** `URL_MAX_PER_MESSAGE` unique URLs (default 200; more → `limit.url_count`, the extra URLs are not stored), `URL_MAX_OCCURRENCES` (default 5 000 occurrences scanned; more → `limit.url_count`), `URL_MAX_LENGTH` (2 048 characters after normalization; longer → stored with `truncated = 1`, the column holds the first 2 048 characters, hash of the full form, `url.too_long`, never rewritten or fetched), part bytes ≤ `URL_MAX_PART_BYTES` (default 10 485 760, ≤ `MIME_MAX_BODY_BYTES`), `URL_EXTRACT_TIMEOUT_MS` (default 5 000; exceeded → attempt failure `timeout`/`extract_timeout`, retryable — load dependent).
- **Incomplete content (rule E1):** a parse row not final, or `limits_exceeded` containing `body_size` (a body was not stored) or any structural limit (`message_size`, `nesting_depth`, `part_count`, `header_*`, `parse_timeout`, `decoded_ratio`, `total_decoded_size`) → engine verdict at least `suspicious`, `url.content_incomplete` (U0 never fires).
- `EXTRACTOR_VERSION = 'url-extract/1'` (stored in `message_urls`).

### U5. Normalization (`normalize/`)

WHATWG URL parsing (`new URL()`, Node 22's Ada parser, which applies **UTS #46 non-transitional IDNA** with `CheckHyphens=false`, `UseSTD3ASCIIRules=false` per the URL Standard), then:

- scheme and host lower case; IDN host kept as A-labels (`host`), U-labels for display (`unicode_host` via `url.domainToUnicode`, only when they differ); a host that fails IDNA → not a URL row, message code `url.invalid` (informational count);
- default ports removed (`:80` http, `:443` https), other ports kept (`url.nonstandard_port`);
- dot segments resolved and path percent-encoding normalized by the parser; query order kept (never sorted);
- trailing dot of the host removed (`url.trailing_dot`);
- IPv4 in any form canonicalized to dotted decimal by the parser; IPv6 compressed (RFC 5952) by the parser; `host_kind` `domain` | `ipv4` | `ipv6`;
- **identity form** (for `url_sha256`, feeds, caches) = serialization **without userinfo and fragment**; **redirect form** (`message_urls.url`, the 302 target) = serialization without userinfo (credentials are never forwarded), with the fragment;
- **registrable domain** via `tldts` (`allowPrivateDomains: true`; unknown TLDs such as `.test` use the default `*` rule, so `a.foo.test` → `foo.test`); NULL for IP hosts.

### U6. Reputation: providers, local feed, cache

- **Interface** (`reputation/`): `ReputationProvider { id; version; kinds: ('url'|'domain'|'ip')[]; cacheable: boolean; lookup(items, signal): Promise<ProviderAnswer[]> }`, `ProviderAnswer = { kind, value, status: 'listed'|'clear'|'error', category: 'phishing'|'malware'|'spam'|'scam'|'c2'|'other'|null, severity: 'low'|'medium'|'high'|'critical'|null, detail: token|null }`. A provider never throws for one item; a whole-provider failure returns `error` for every item. Each provider sits behind its own breaker (`URL_PROVIDER_BREAKER_*`; open → `error`) and timeout (`URL_PROVIDER_TIMEOUT_MS`).
- **Implemented providers** (`URL_REPUTATION_PROVIDERS`, default `local_feed,dnsbl`):
  1. **`local_feed`** — `threat_indicators` platform rows (`org_scope = 0`, `expires_at` NULL or future), `indicator_type` `url` (identity-form hash), `domain` (the host and every parent down to the registrable domain), `ip` (canonical text). One `SELECT … WHERE indicator_type = ? AND value_sha256 IN (…)` per kind, chunks of 500. **Never cached** (authoritative; an analyst change applies to the next scan and click). Version `local_feed/1`.
  2. **`dnsbl`** — generic DNS blocklist over the restricted resolver (U8): domain zones (`URL_DNSBL_DOMAIN_ZONES`, query `<registrable domain>.<zone>` and `<host>.<zone>`) and IP zones (`URL_DNSBL_IP_ZONES`, reversed octets / nibbles). Zone syntax `zone=code:category[,code:category…]`, zones separated by `;` (e.g. `dbl.scan.test=127.0.1.2:spam,127.0.1.4:phishing,127.0.1.5:malware,127.0.1.6:c2`). Answers in `URL_DNSBL_ERROR_CODES` (default `127.255.255.252,127.255.255.254,127.255.255.255,127.0.1.255`: Spamhaus "query refused / public resolver / error") and answers outside `127.0.0.0/8` are `error`, never `listed` or `clear`; NXDOMAIN is `clear`; SERVFAIL/timeout `error`. This one provider covers **Spamhaus DBL and ZEN (DQS: the key is part of the zone name), SURBL and URIBL by configuration**. Version `dnsbl/1;<hash of zone config, 8 hex>`.
  3. **`rdap`** (domain age; enabled when listed and `URL_RDAP_BASE_URL` is set) — `GET <base>/domain/<registrable domain>` through the guarded fetcher (redirects validated), `events[eventAction=registration].eventDate`; age < `URL_NEW_DOMAIN_DAYS` (default 30) → `listed`, category `other`, detail `new_domain`; 404 → `clear` with detail `not_found`; other errors `error`. Version `rdap/1`.
- **Documented, not implemented** (configuration behind the same interface, never called in tests): Google Safe Browsing (v4 Lookup / v5), PhishTank, URLhaus, OpenPhish, commercial URL classification. `docs/deployment/url-protection.md` lists their configuration shape and data-handling notes (GSB v4 Lookup sends full URLs to Google; Update API / hash prefixes recommended). Feed _imports_ into `threat_indicators` are out of scope (§10).
- **Cache** (Redis, shared app Redis, `RedisService`): key **`eg:url:rep:v1:<providerId>:<providerVersion>:<kind>:<sha256(value)>`**, value `<mac>.<json>` with HMAC-SHA256 under **`URL_CACHE_HMAC_KEY`** (secret, ≥ 32 characters, held only by the URL-consuming email-worker and the click-service) over key + JSON, verified in constant time, then schema-checked; a wrong MAC/shape is `rejected` (counted, overwritten). TTL by answer: `clear` → `URL_CACHE_CLEAN_TTL_SECONDS` (default 900, ≤ 3 600), `listed` with category phishing/malware/c2 or severity high/critical → `URL_CACHE_MALICIOUS_TTL_SECONDS` (default 86 400, ≤ 604 800), other `listed` → `URL_CACHE_OTHER_TTL_SECONDS` (default 300, ≤ 3 600), `error` → `URL_CACHE_ERROR_TTL_SECONDS` (default 30, ≤ 120; avoids hammering a failing provider, still `error`). Redis errors/timeouts (`URL_CACHE_TIMEOUT_MS` 200) bypass the cache. `URL_CACHE_ENABLED` (default true). The same store holds fetch/chain results (`eg:url:chain:v1:<fetcherVersion>:<sha256(identity url)>`, clean-chain TTL ≤ clean TTL, error TTL as above) and dynamic results (`eg:url:dyn:v1:<sha256>`, U15). Cache entries are shared across organizations (they hold no tenant data); their hit/miss and timing are **never shown to tenants** (U16).

### U7. Lookalike detection (`lookalike/`)

**Protected set:** (a) platform brands `packages/url-security/data/brands.json` (`[{ id, label, officialDomains[] }]`, ~60 globally and India-relevant brands: microsoft/office/outlook/live, google/gmail, apple/icloud, amazon, paypal, docusign, dropbox, linkedin, facebook/instagram/whatsapp, netflix, adobe, dhl, fedex, ups, sbi, hdfc, icici, axis, kotak, paytm, phonepe, irctc, incometax…), replaceable with `URL_PROTECTED_BRANDS_FILE`, extended with `URL_PROTECTED_EXTRA_DOMAINS`; (b) the tenant's active domains; (c) the tenant's `lookalike.extraProtectedDomains`. Each protected entry contributes its **label** = registrable domain minus public suffix (`paypal`), its official registrable domains, and the label's **skeleton**.

**Skeleton** = UTS #39 §4: NFD → map every code point through the Unicode **confusables** table (`confusables.txt`, Unicode 16.0.0, generated into `data/confusables.json` by `scripts/generate-confusables.mjs`; the generated file records the source URL, version and the source file's SHA-256; Unicode license notice included) → NFD → lower case. Digits and hyphen are kept (`1`→`l` and `0`→`o` come from the table).

**Candidate** = the URL's (and final URL's) registrable domain label in **Unicode** form. A candidate whose registrable domain is an official domain of the entry, in the tenant `allowedDomains`, or equal to a tenant domain is never a lookalike of that entry.

| Rule | Condition (explicit thresholds)                                                                                                                                                                                                                | Code                                               | Effect (U10)                         |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- | ------------------------------------ |
| L1   | `skeleton(candidate) == skeleton(protected)` and the strings differ (any length)                                                                                                                                                               | `url.lookalike_homoglyph`                          | suspicious; score 1.0                |
| L2   | protected label length ≥ `URL_LOOKALIKE_MIN_LABEL` (5); Damerau–Levenshtein distance _d_ between skeletons with `1 ≤ d ≤ 1` for length < `URL_LOOKALIKE_LONG_LABEL` (9), `1 ≤ d ≤ 2` for ≥ 9 (`URL_LOOKALIKE_MAX_DISTANCE_SHORT` 1, `_LONG` 2) | `url.lookalike_edit_distance`                      | suspicious; score `1 − d / max(len)` |
| L3   | protected label (length ≥ 4) is a whole hyphen/dot-delimited token of the candidate label (`paypal-secure`, `secure-paypal`), or a whole label of a subdomain (`paypal.com.evil.tld`, `login.paypal.evil.tld`)                                 | `url.lookalike_combosquat`                         | suspicious; score 0.8                |
| L4   | a host label fails UTS #39 §5.2 **Highly Restrictive** (one script, or Latin+Han+Hiragana+Katakana, Latin+Han+Bopomofo, Latin+Han+Hangul; Common/Inherited ignored), via `\p{Script_Extensions=…}`                                             | `url.mixed_script`                                 | suspicious                           |

At most 5 findings per URL are kept (highest score first): `{ rule, targetKind: 'brand'|'tenant'|'extra', targetDomain, score, distance }`. **High-confidence lookalike** = L1, L3, or L2 with score ≥ `URL_LOOKALIKE_HIGH_SCORE` (0.85). `lookalikeVersion` = `lookalike/1;cf=<unicode version>;brands=<8 hex>` (part of `engineVersion`).

### U8. The hardened fetcher and the SSRF guard (`net/`)

One implementation used by the engine (scan time), the click-service (click time), the RDAP provider and the egress proxy (browser traffic).

**Tracing (review round 1):** every `fetchChain`/`fetchResource` runs in an OpenTelemetry context with tracing suppressed (`untraced`, `@opentelemetry/core` `suppressTracing`). The email-worker and the click-service start the auto-instrumentation (`startTracing`), whose `http` instrumentation would otherwise add `traceparent`/`tracestate`/`baggage` to every request to an untrusted site (breaking the exact header set below and leaking trace ids) and record the target's path and query in client spans. Suppressed, no span is recorded (http, net, tls) and nothing is injected; `fetcher.tracing.test.ts` runs the real instrumentation and asserts the exact header set. The click-service also never traces incoming `/c/` requests (`startTracing(…, { untracedIncomingPaths: ['/c/'] })`: no server span with the token or the continue nonce, and no child span of the request).

**Guard (`SsrfGuard`):**

- Scheme `http`/`https` only (`fetch_blocked_scheme` otherwise). Port in `URL_FETCH_ALLOWED_PORTS` (default `80,443`) else `blocked_port`. Userinfo is stripped before the request (never sent).
- **Names blocked before DNS:** `localhost` and `*.localhost`, `*.local`, `*.internal` (covers `metadata.google.internal`), `*.home.arpa`, `*.localdomain`, `metadata`, `instance-data`, `metadata.azure.internal`, single-label names, the click-service's own host (`URL_CLICK_BASE_URL` host; loop prevention) and names in `URL_FETCH_DENY_HOSTS`.
- **Addresses:** every address is canonicalized first (IPv4-mapped `::ffff:a.b.c.d` and IPv4-compatible `::a.b.c.d` → the IPv4; NAT64 `64:ff9b::/96`, 6to4 `2002::/16` → their embedded IPv4, which must also pass), then checked with `net.BlockList` against **every non-globally-reachable range of the IANA IPv4 and IPv6 special-purpose registries**: IPv4 `0.0.0.0/8`, `10/8`, `100.64/10` (CGNAT), `127/8`, `169.254/16` (incl. `169.254.169.254`, `169.254.170.2`), `172.16/12`, `192.0.0/24`, `192.0.2/24`, `192.88.99/24`, `192.168/16`, `198.18/15`, `198.51.100/24`, `203.0.113/24`, `224/4`, `240/4`, `255.255.255.255`; IPv6 `::/128`, `::1/128`, `64:ff9b:1::/48`, `100::/64`, `2001::/23` (incl. Teredo `2001::/32`), `2001:db8::/32`, `3fff::/20`, `5f00::/16`, `fc00::/7` (incl. `fd00:ec2::254`), `fe80::/10`, `fec0::/10`, `ff00::/8`; plus `URL_FETCH_DENY_CIDRS` (production: the platform's own public ranges). Blocked reasons (bounded label): `loopback`, `private`, `link_local`, `cgnat`, `multicast`, `reserved`, `documentation`, `metadata`, `ula`, `unspecified`, `mapped`, `name`, `scheme`, `port`, `deny_list`.
- **Test-only allowance:** `URL_FETCH_TEST_ALLOW_CIDRS` may list CIDRs **inside the documentation ranges only** (`192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`) so the local test web server (U19, `203.0.113.10`) is reachable; config validation refuses any other CIDR and refuses the key when `NODE_ENV=production`. Loopback, private, link-local, metadata and the rest stay blocked in every test.

**Resolver (`RestrictedResolver`):** `dns.promises.Resolver({ timeout: URL_DNS_TIMEOUT_MS, tries: URL_DNS_TRIES })` with `setServers(URL_DNS_SERVERS)` (empty = the resolver's default servers from `resolv.conf`; **never** `dns.lookup`/`getaddrinfo`, never `/etc/hosts`). `resolve4` and `resolve6` in parallel; at most 16 answers each; **if any answer is blocked the host is blocked** (`mixed` answers are a rebinding/split-horizon signal); else the first allowed IPv4, else IPv6. No cache across hops (each hop resolves again and is validated again).

**Connector (no TOCTOU):** the request is made with `http.request` / `https.request` and an `agent: false` whose `createConnection` dials **the validated IP literal** (`net.connect({ host: ip, port })`; for https `tls.connect({ host: ip, port, servername: hostname, ALPNProtocols: ['http/1.1'], rejectUnauthorized: true })`), with the `Host` header set to the URL host, and a `lookup` option that throws if Node ever tries to resolve. The address the socket actually connected to (`socket.remoteAddress`) is re-checked after connect. Test-only `URL_FETCH_TEST_DIAL_MAP` (`ip:port=127.0.0.1:port,…`, refused in production) lets host-run integration tests reach the url-test container's published ports **after** the guard validated the resolved documentation-range IP.

**Request discipline:** method `GET` only; headers exactly `Host`, `User-Agent` (`URL_FETCH_USER_AGENT`), `Accept: text/html,*/*;q=0.5`, `Accept-Encoding: gzip, deflate, br` (decoded with an output cap), `Connection: close`; **never** `Cookie`, `Authorization`, `Referer`, `Proxy-*`; `Set-Cookie` ignored. Limits: connect `URL_FETCH_CONNECT_TIMEOUT_MS` (3 000), headers `URL_FETCH_HEADER_TIMEOUT_MS` (5 000), total per URL `URL_FETCH_TOTAL_TIMEOUT_MS` (10 000), header bytes `URL_FETCH_MAX_HEADER_BYTES` (16 384, via `maxHeaderSize`), header count 100, body bytes read `URL_FETCH_MAX_BODY_BYTES` (262 144; only for a final `text/html` 2xx or for a meta-refresh check of a 2xx hop; the rest is discarded and the socket destroyed), decompressed bytes 4 × that cap, global concurrency `URL_FETCH_CONCURRENCY` (8 per process).

**Redirects:** 301/302/303/307/308 with `Location` (resolved against the current URL, normalized by U5, validated by the guard **before** the next hop: scheme, name, port, then DNS+address), and `<meta http-equiv=refresh>` within the first 64 KiB of a 2xx HTML hop (kind `meta`). At most `URL_FETCH_MAX_HOPS` (8) → `redirect_limit`. A loop (same identity URL twice) → `redirect_loop` (= `redirect_limit` code). Each hop is recorded `{ host, port|null, status, kind, blocked: reason|null }` (no paths, no query strings in the chain JSON: `host` only, plus the final URL in its own column).

**Result:** `{ status: 'completed'|'error'|'blocked', error: 'timeout'|'dns_error'|'tls_error'|'connection_error'|'http_error'|'too_large'|'header_limit'|'redirect_limit'|null, blockedReason, hops[], finalUrl, finalStatus, landing: LandingFeatures|null, durationMs }`. `FETCHER_VERSION = 'url-fetch/1'`.

**Egress modes (documented in `docs/deployment/url-protection.md`):** (1) **direct** with the in-process guard plus a Kubernetes NetworkPolicy that denies egress to private ranges and the metadata service (`ipBlock` with `except`), or (2) **egress proxy** (`URL_FETCH_EGRESS_PROXY_URL`, used by default by the browser worker and recommended for production for every fetcher): the client still validates scheme/name/port, sends `CONNECT host:port` (https) or absolute-form `GET` (http) with `Proxy-Authorization: Basic` from `URL_EGRESS_PROXY_TOKEN`, and the proxy (U15) resolves, guards and dials itself; the client never resolves the target in proxy mode. In production the fetcher pods have no route to the Internet except through the proxy.

### U9. Phishing detection signals (static)

- **Landing features** (from at most `URL_FETCH_MAX_BODY_BYTES` of a final `text/html` page, parsed with parse5, never stored): `passwordFields` (inputs `type=password`), `forms`, `crossOriginFormAction` (a form action whose registrable domain differs from the page's), `formActionHosts` (≤ 5), `titleBrandMatches` (brand ids whose label appears as a word in `<title>` while the page's registrable domain is not official for the brand). Only counts, booleans, hosts and brand ids are kept.
- **URL structure signals:** IP host, userinfo, obfuscations (U4), text mismatch, lookalikes (U7), many redirects, redirect to IP, new domain (rdap).
- **Fetch selection** (`scanTimeFetch`, tenant-tightenable; platform `URL_SCAN_TIME_FETCH`, default `suspicious`): `off`; `shorteners` (host in the shortener list: `data/shorteners.txt` ∪ `URL_SHORTENER_EXTRA_HOSTS`, or `URL_SHORTENER_HOSTS_FILE`); `suspicious` (shorteners **plus** URLs with any static risk signal of U10 S-rules or a non-`clear` reputation answer); `all`. Rationale: GET requests at scan time can consume one-time links (magic login, unsubscribe confirmations); the default fetches only what needs it. Selected URLs above `URL_FETCH_MAX_PER_MESSAGE` are not fetched (`url.fetch_skipped_limit`, informational; their verdict comes from the other rules, never clean if the fetch was _required_ — shorteners not fetched → `unknown`).

### U11. URL rewriting: location, exclusions, signed mail, MIME safety

- **Where:** in the **URL engine**, at the end of its definite scan (U3 step 8), producing a rewritten copy of the EML in S3 under `org/<org>/rewrite/<yyyy>/<mm>/<dd>/<messageId>/r<round>-<uuidv7>.eml` (date of `received_at`; the attempt-unique suffix makes concurrent duplicate attempts harmless; the losing attempt's object is an orphan). Object: `ContentType: message/rfc822`, `ContentDisposition: attachment`, tag `eg-object=rewrite`; the MinIO/S3 lifecycle rule expires tagged objects after `URL_REWRITE_OBJECT_RETENTION_DAYS` (30) — orphans included. The `url_rewrites` row of the round (written in the finalize transaction) names the object, its SHA-256 and size. **The original EML is never modified**; archive, quarantine and rescans use it.
- **Delivery:** the approver chooses the object: the dev pass-through (and, by documented contract, policy 5.2 and the quarantine release 5.3) sets `emlS3Key` to the round's `url_rewrites.object_key` when a row with `status = rewritten` exists for `(message, lifecycle_round)` (echo-checked: message, organization, round, key prefix `org/<org>/rewrite/`), else to `email_messages.eml_object_key`. The delivery-worker is unchanged (it already reinjects whatever key the approval names).
- **Why here, not at approval or reinjection:** the URL ids/sequences and the tenant rewrite settings are known at scan time; the rewritten copy is ready before approval, so delivery latency does not change; the reinjector stays a byte pump (no token keys, no URL tables in the delivery-worker); a rescan or release creates a new round and therefore a new copy. Alternatives in §7.
- **Rewrite eligibility per message** (`skip_reason` when not rewritten; skipping is never a failure): `disabled` (tenant/platform), `direction` (message direction not in `rewrite.directions`, default `['inbound']`), `no_urls` (nothing eligible), `parse_incomplete` (E1), `too_large` (EML > `URL_REWRITE_MAX_MESSAGE_BYTES` 26 214 400), `signed_smime` / `signed_pgp` / `encrypted` (from `structure`: `multipart/signed`, `application/(x-)pkcs7-mime`, `application/pkcs7-signature`, `multipart/encrypted`, `application/pgp-encrypted`; or an inline `-----BEGIN PGP SIGNED MESSAGE-----` / `-----BEGIN PGP MESSAGE-----` in a body part) — the **whole message** is skipped because changing any part inside a signed or encrypted structure breaks it, `dkim_policy` (a `DKIM-Signature` header is present and `rewrite.dkimSignedPolicy = skip`), `structure_mismatch` (the rewriter's leaf count/content types differ from `structure`), `error` (unexpected rewriter error; logged with ids, counted, alert U18).
- **DKIM:** inbound mail was authenticated by the gateway (Rspamd results persisted in 4.1); rewriting changes the body, so an existing DKIM signature no longer verifies downstream. Default `dkimSignedPolicy = rewrite` (standard secure-gateway behaviour), `url_rewrites.dkim_signed = 1` recorded; the tenant's mailbox platform must trust the gateway (M365 enhanced filtering / connector, Google inbound gateway) — documented in `docs/domains/` and the deployment doc. ARC sealing of rewritten mail is out of scope (§10). Outbound rewriting (opt-in direction) happens before `rspamd-outbound` signs at 10027, so the gateway's own signature covers the rewritten body.
- **Eligible links:** `a[href]` / `area[href]` with http(s) in rewritable text/html parts, and http(s)/`www.` URLs in rewritable text/plain parts. **Rewritable parts:** `text/html` and `text/plain` leaves without `Content-Disposition: attachment`, without a filename, outside `message/rfc822` subtrees, ≤ `URL_REWRITE_MAX_PART_BYTES` (5 242 880; larger parts pass through, `parts_skipped` counted). **Excluded URLs:** the click host itself (already rewritten), `mailto:`, `tel:`, `cid:`, fragments, non-http(s), truncated/too-long URLs, URLs whose host/registrable domain is in `rewrite.excludedDomains` or `allowedDomains` (suffix match on labels), `src`/`srcset`/`link`/`form`/`meta` URLs (scanned, not rewritten: rewriting images breaks rendering, forms post), URLs in attachments, all headers (including `List-Unsubscribe`), and occurrences whose normalized identity is not in the scan's URL map (`links_unmapped` counted; left untouched).
- **Rewritten form:** `<URL_CLICK_BASE_URL>/c/<token>` (U12); the token alphabet is base64url, so the value never needs escaping; the HTML splice still writes `href="…"` with `"`, `&`, `<`, `>` escaped.
- **MIME mechanics** (`@email-gateway/url-security` `rewrite/`): stream the stored EML through `@zone-eu/mailsplit` `Splitter → (Rewriter for rewritable leaves) → Joiner` into an S3 multipart `Upload`, computing SHA-256 and size on the way. Headers of the message and of every untouched node, and the bytes of every untouched node, pass through **byte-identical** (tested). For a rewritten node: transfer-decode (base64/QP/7bit/8bit), **decode with the part's charset** (iconv-lite) and require a lossless round trip (`encode(decode(b)) == b`, else the part is skipped with `charset_roundtrip`); charsets that are not ASCII-compatible (UTF-16/32, UTF-7, ISO-2022-*, EBCDIC) are skipped (`unsupported_charset`). HTML: parse5 with source locations, replace only the `href` attribute ranges of eligible `a`/`area` start tags (no re-serialization, no other change, so no markup can be injected or lost); text: replace the URL ranges found by the U4 plain-text extractor. Re-encode with the original charset and **the original Content-Transfer-Encoding**, except: a `7bit`/`8bit`/`binary` part whose rewritten content has a line longer than 998 octets is switched to `quoted-printable` (header updated), `format=flowed` text is left flowed (tokens contain no spaces). Folding and line endings follow the original part (CRLF). If mailsplit's `Rewriter` cannot express a needed header change, the implementer does the node encode/decode with `libqp`/`libbase64` (already used by `mime-parser`) and records it.
- **Determinism:** the rewrite for the same inputs differs only by token expiry and key id; nothing depends on it being byte-identical across attempts (attempt-unique keys).

### U12. Click tokens

- **Format** (`token/`, `TOKEN_VERSION = 1`): 46 bytes, base64url without padding (**62 characters**):

  | Bytes | Field                                                                    |
  | ----- | ------------------------------------------------------------------------ |
  | 0     | version `0x01`                                                           |
  | 1     | key id 1..255                                                            |
  | 2–9   | `organization_id` uint64 BE                                              |
  | 10–17 | `message_id` uint64 BE                                                   |
  | 18–23 | `received_at` epoch milliseconds uint48 BE (partition key of the lookup) |
  | 24–25 | `url_seq` uint16 BE                                                      |
  | 26–29 | expiry epoch seconds uint32 BE                                           |
  | 30–45 | HMAC-SHA256(key, `"eg-url-token/v1\0"` ‖ bytes 0–29), first 16 bytes     |

- **Why HMAC, not AEAD:** compact, deterministic for given inputs, constant-time verification, no nonce management. The ids are internal identifiers, not secrets (knowing them grants nothing without a valid MAC); the URL, tenant name and recipient are never in the token. The original URL is stored server side (`message_urls.url`) and is **never** taken from the token.
- **Keys:** `URL_TOKEN_KEY_CURRENT` (secret, 64 hex = 32 bytes) + `URL_TOKEN_KEY_CURRENT_ID` (1..255), optional `URL_TOKEN_KEY_PREVIOUS` + `_ID` (verification only). The engine signs with the current key; the click-service verifies with either. Rotation: new key becomes current, the old becomes previous; the previous key may be removed only after `URL_TOKEN_MAX_EXPIRY_DAYS` (runbook). Held only by the URL-consuming email-worker and the click-service (Kubernetes Secret `email-gateway-url-token-keys`).
- **Verification order:** length 62 and alphabet → decode → version → known key id → constant-time MAC → expiry (`expired` is a distinct outcome: the MAC was valid, so the organization is known and the event is logged) → id ranges (non-zero). Expiry = scan time + `rewrite.expiryDays` (tenant, 1..`URL_TOKEN_MAX_EXPIRY_DAYS` 90, default `URL_TOKEN_DEFAULT_EXPIRY_DAYS` 30). Retention of `message_urls` (6 months) exceeds the maximum expiry.
- **Continue nonce** (warn page): `HMAC-SHA256(HKDF(currentKey, "eg-url-continue/v1"), token ‖ windowStart)` first 16 bytes base64url, windows of `CLICK_CONTINUE_TTL_SECONDS` (600), verified against the current and the previous window.

### U13. Settings (platform defaults with bounded tenant overrides, 4.1 S8 pattern)

`urlTenantSettingsSchema` (strict, `scan_engine_settings` engine `url`, existing API routes and permissions, audited):

```ts
{
  allowedDomains?: domain[] ≤ 500,           // registrable domains or hosts (ASCII after IDNA); suffix match on labels
  blockedDomains?: domain[] ≤ 500,           // → M4 malicious for this tenant
  scanTimeFetch?: 'off' | 'shorteners' | 'suspicious' | 'all',
  lookalike?: { extraProtectedDomains?: domain[] ≤ 50 },
  rewrite?: {
    enabled?: boolean,
    directions?: ('inbound' | 'outbound' | 'internal')[] (non-empty, unique),
    expiryDays?: 1..URL_TOKEN_MAX_EXPIRY_DAYS,
    excludedDomains?: domain[] ≤ 200,
    dkimSignedPolicy?: 'rewrite' | 'skip',
    plainText?: boolean,                     // rewrite text/plain parts (default true)
  },
  click?: {
    suspicious?: 'warn' | 'block',           // default warn
    unknown?: 'allow' | 'warn' | 'block',    // default warn
    allowContinue?: boolean,                 // continue on the warn page (default true)
  },
  dynamicInspection?: boolean,               // default platform URL_DYNAMIC_INSPECTION
}
```

`clean` is always allowed and `malicious` always blocked (not configurable). A domain may not be in both `allowedDomains` and `blockedDomains`; public suffixes are refused; every domain is validated through `url-security` normalization in the api (WP5) and again at use. `resolveUrlSettings(platform, override)` and `urlSettingsBounds(platform)` live in `security-contracts` (pure; validation of domain syntax there is a regex on ASCII labels; the api additionally normalizes). The scan-time **rewrite** settings are snapshotted by `settingsVersion`; the **click** policy and lists are read live by the click-service (a tenant change applies to the next click).

### U14. The time-of-click service (`apps/click-service`)

- **Deployable:** NestJS (express, helmet) app `@email-gateway/click-service`, public port `CLICK_HTTP_PORT` 3080 (routes `GET /c/:token`, `GET /c/:token/continue`, static CSS), **separate admin port** `CLICK_ADMIN_PORT` 3081 (`/health/live`, `/health/ready`, `/metrics`; never exposed by the Ingress). Image from `node-service.Dockerfile` (`APP=click-service`). No RabbitMQ.
- **Data access:** its own MySQL account **`gateway_click`** on the writer (`CLICK_DATABASE_URL`; table grants only: SELECT on `message_urls`, `url_scan_results`, `url_dynamic_inspections`, `scan_engine_settings`, `threat_indicators`, `domains`; INSERT on `url_click_events`, `message_outbox`). Redis (`REDIS_URL`) for rate limits and the U6 cache. No S3, no other secret.
- **Algorithm of `GET /c/:token`:**
  1. Rate limit (Redis fixed window, Lua `INCR`+`EXPIRE`): per client network (`CLICK_RATE_LIMIT_IP_PER_MINUTE` 120), per token (`CLICK_RATE_LIMIT_TOKEN_PER_MINUTE` 30), invalid tokens per client network (`CLICK_RATE_LIMIT_INVALID_PER_MINUTE` 20) → 429 page. Redis down → fail open for rate limiting only (counted), never for decisions. Client IP from `CLICK_TRUST_PROXY` hops.
  2. Verify the token (U12). Invalid → **404** generic "link not valid" page, no database access, metric `click_token_invalid_total{reason}`. Expired → **410** page, click event `expired`.
  3. Look up `message_urls` by `(organization_id, message_id, received_at, url_seq)` with echo checks (every column of the key returned and equal; mismatch → retry once, then 503). Missing → **404** page, event `not_found`.
  4. Re-evaluate within `CLICK_RECHECK_BUDGET_MS` (2 500): latest `url_scan_results` of the URL (highest `scan_id`), latest completed `url_dynamic_inspections`, fresh reputation (local feed uncached; dnsbl/rdap through the shared cache), the public addresses of the URL's host (looked up in parallel with the chain), and — **for every URL that may be fetched** (not truncated; review round 1, brief item 10) — the redirect chain through the same guarded fetcher (chain cache U6: a clean chain is reused for at most `URL_CACHE_CLEAN_TTL_SECONDS`), its final URL, later hop hosts and their addresses through reputation too. Lookalike and extraction findings come from the stored row, merged with the lookalike findings of a re-resolved final URL whose host differs (same `ProtectedSet` as the engine, the tenant's active domains read for it). A clicked URL is therefore fetched by the service right before the user's browser fetches it (one-time links are requested twice; accepted, §8). Anything not answered within the budget counts as an error (→ `unknown`, never clean). Map with `url-map/1` (U10, incl. M5/S9/U3) using the live tenant lists.
  5. Decide with the tenant click policy: `clean` → **allow**; `unknown` → `click.unknown`; `suspicious` → `click.suspicious`; `malicious` → **block**. `allowedDomains` never overrides M1/M2.
  6. Respond: **allow** → `302 Location: <message_urls.url>` (re-parsed with WHATWG URL, must be http(s), serialized; never request data); **warn** → `200` interstitial with the destination's registrable domain (ASCII and, if IDN, Unicode) and, if `allowContinue`, a continue link `/c/<token>/continue?n=<nonce>` (U12), which re-verifies the token and nonce and redirects (event `continued`); **block** → `403` block page with a reference id (the click event's public id). Database unavailable → `503` page, never a blind redirect.
  7. Log: one `url_click_events` row + one `mail.url.clicked.v1` outbox row in **one interactive transaction** with `CLICK_DB_TX_TIMEOUT_MS` (120 000) and Prisma `maxWait` 10 000 (4.2 §6 mitigation). The response waits for the write at most `CLICK_EVENT_WRITE_WAIT_MS` (300); the write continues in the background, bounded by `CLICK_EVENT_MAX_PENDING` (1 000; above → dropped and counted `click_events_total{result="dropped"}`). Client address stored only as a truncated network (`/24` IPv4, `/48` IPv6) when `CLICK_STORE_CLIENT_NETWORK=true`; no user agent, no cookie, no user identity (one rewritten copy serves every recipient).
- **Pages:** server-rendered from constant templates, no tenant name, subject, sender, recipient, scan details or reason codes; only the decision, the destination domain (warn), and the reference id. Headers on every response: `Content-Security-Policy: default-src 'none'; style-src 'self'; img-src 'self'; form-action 'none'; frame-ancestors 'none'; base-uri 'none'`, `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Resource-Policy: same-origin`, `Permissions-Policy: ()`-style deny-all, `Cache-Control: no-store`, `Strict-Transport-Security` when `NODE_ENV=production`, no `X-Powered-By`. No JavaScript.
- **Metrics:** U18.

### U15. Dynamic inspection: browser worker and egress proxy (`apps/url-browser-worker`)

- **Choice:** real headless Chromium through **`playwright-core`** (pinned) with Playwright's **`chromium-headless-shell`** build installed in the image at build time. A static fetch cannot see JavaScript redirects, client-side rendered credential forms or download triggers; a lighter DOM emulator (jsdom) executes attacker JavaScript in Node without a browser sandbox, which is worse isolation, not better. Full rationale in ADR-0032.
- **Two containers from one image** (`infrastructure/docker/url-browser-worker.Dockerfile`): `url-browser-worker` (`node dist/main.js`) and `url-egress-proxy` (`node dist/proxy-main.js`).
- **Browser worker isolation:** own broker user `eg-url-browser` (U2), **no** MySQL, S3, Redis or token/cache keys in its environment (config refuses to start if `DATABASE_URL`, `CLICK_DATABASE_URL`, `S3_*`, `REDIS_URL`, `URL_TOKEN_*`, `URL_CACHE_HMAC_KEY` are set); Compose network **`url-sandbox` (`internal: true`)** shared only with `url-egress-proxy` and `rabbitmq` (alias); Chromium launched with `--proxy-server=http://<proxy>` (proxy credentials via Playwright's proxy option), `--host-resolver-rules="MAP * ~NOTFOUND , EXCLUDE <proxy host>"` (no direct DNS), `--disable-quic`, `--force-webrtc-ip-handling-policy=disable_non_proxied_udp`, `--disable-background-networking`, `--disable-component-update`, `--disable-sync`, `--no-first-run`, `--disable-dev-shm-usage`; one **new incognito context per job** (`acceptDownloads: false`, `serviceWorkers: 'block'`, `permissions: []`, `ignoreHTTPSErrors: false`, `javaScriptEnabled: true`, viewport 1280×800, locale en-US), closed in `finally`; dialogs auto-dismissed; `page.on('download')` → signal + cancel; navigation timeout `URL_BROWSER_NAVIGATION_TIMEOUT_MS` (15 000), job timeout `URL_BROWSER_JOB_TIMEOUT_MS` (20 000), `URL_BROWSER_CONCURRENCY` (1, max 4) contexts, browser restarted after `URL_BROWSER_MAX_JOBS_PER_BROWSER` (50) jobs, on crash, and when the browser process tree RSS (`/proc`) exceeds `URL_BROWSER_MAX_RSS_MB` (768). Container: non-root user, `read_only: true` rootfs, `tmpfs /tmp` (256 MiB; Chromium's ephemeral profile lives there and is deleted per browser), `cap_drop: [ALL]`, `security_opt: [no-new-privileges:true]`, `pids_limit: 256`, `mem_limit: 1g`, `cpus: 1`. Chromium's own sandbox is used when the kernel allows unprivileged user namespaces; otherwise `chromiumSandbox: false` with the container controls above (recorded in readiness details and in ADR-0032; production runs the pod under gVisor `runtimeClassName` when available — documented, not verified locally).
- **Job:** consume `scan.url.inspect` (prefetch = concurrency), validate the event (strict schema, http(s) URL ≤ 2 048, deadline not passed → else publish `failed`/`deadline_passed`), navigate, wait for `load` + up to 3 s of further navigations, collect the `inspection_completed.v1` signals (U2), publish with confirms, then ack. Errors → `failed` with `errorCode` (`navigation_timeout`, `proxy_refused`, `browser_crash`, `job_timeout`). Navigation chain hosts come from main-frame navigations and redirect responses.
- **Egress proxy (`url-egress-proxy`):** HTTP forward proxy (absolute-form `GET`/`HEAD`/`POST` for http, `CONNECT` for https; other methods refused) on `URL_EGRESS_PORT` 3128, admin `URL_EGRESS_ADMIN_PORT` 3091 (health, metrics). Requires `Proxy-Authorization: Basic` matching `URL_EGRESS_PROXY_TOKEN` (constant time) so it is not an open proxy. For every request/CONNECT: parse the target, run the **same `SsrfGuard` + `RestrictedResolver`**, dial the validated IP (no TOCTOU), re-check `remoteAddress`, enforce `URL_EGRESS_MAX_CONNECTIONS` (64), `URL_EGRESS_MAX_BYTES_PER_CONNECTION` (10 MiB, both directions), `URL_EGRESS_IDLE_TIMEOUT_MS` (15 000), `URL_EGRESS_MAX_CONNECTION_MS` (30 000); refused targets get `403` (counted `url_egress_blocked_total{reason}`); the proxy strips `Proxy-*` headers and adds nothing. It does not terminate TLS. Networks: `url-sandbox`, `mailtest` (dns-sink), `urltest` (url-test) and, in production, the egress-only subnet.
- **Results consumer (email-worker, `email-worker.scan.url.results`):** `processOnce` per event; loads the `url_dynamic_inspections` row by `inspectionId` (echo: organization of the envelope, message, `url_seq`, `url_sha256`), and if `pending` updates it (`WHERE status = 'pending'`) to `completed`/`failed` with signals, computed dynamic verdict and codes (U10 M5/S9/U3 applied to the stored lookalike findings), final host/hash; writes the dynamic cache entry `eg:url:dyn:v1:<url_sha256>` (malicious TTL for malicious, other TTL otherwise). A row not pending → no-op (duplicate). Unknown inspection id or org mismatch → dropped with a warning and a metric (a forged result cannot create rows). Uses `SCAN_DB_TIMEOUT_MS` budgets.
- **Sweeper:** leader lock `scan:url-inspections`; every `URL_DYNAMIC_SWEEP_INTERVAL_MS` (60 000) marks `pending` rows older than `URL_DYNAMIC_PENDING_TTL_SECONDS` (3 600) `expired` (batch 500).
- **Enablement:** `URL_DYNAMIC_INSPECTION` (`on` | `off`, default `on`) and tenant `dynamicInspection`; `URL_DYNAMIC_MAX_PER_MESSAGE` (3). The round never waits for it; its results act at click time.

### U17. Resilience

- Timeouts at every level (U4, U6, U8, U14, U15); engine call `SCAN_URL_TIMEOUT_MS` (120 000); per-provider breakers; the 4.1 engine breaker counts only engine faults (S3/DB are not engine faults).
- Bounded concurrency: messages `SCAN_URL_CONCURRENCY` (4), providers `URL_PROVIDER_CONCURRENCY` (16 lookups in flight per message), fetches `URL_FETCH_CONCURRENCY` (8 per process), browser contexts, proxy connections, click event writes.
- Retries through the 3.2 `hold` queues (`SCAN_URL_MAX_ATTEMPTS` 6 < queue 10); deadline validation: 6 × (120 + 60) s = 1 080 s ≤ 1 800 s.
- `processOnce` per (message, round, engine) and per results event; unique keys on all child rows.
- **Wrong-read mitigation (4.2 §6):** engine reads echo-checked (U3); the results consumer echo-checks; the click-service echo-checks and uses a 120 s transaction budget with no socket timeout; no new code uses Prisma's default 5 s interactive budget.

## 6. Prisma wrong-read mitigation in this step (4.2 §6)

New interactive transactions: the click event write (U14, 120 s budget), the results consumer's update (U15, `SCAN_DB_TIMEOUT_MS`), the sweeper batch (`SCAN_DB_TIMEOUT_MS`), the api threat-indicator writes (existing api budget pattern of the threat-hash routes). Every read whose result decides a verdict, a redirect target or a row update is echo-checked; a mismatch is retryable (engine: attempt failure `inconsistent_read`; click: one retry then `503`; consumer: thrown, redelivered). No socket timeout is set.

## 7. Alternatives considered

- **Rewrite at approval** (a new "rewrite stage" consuming `scanned.v1` and producing the object before approving): one more queue, consumer and lifecycle edge for work the URL engine can do with data it already holds; rejected. **Rewrite during reinjection** (delivery-worker streams through the rewriter): puts token keys and URL tables in the delivery-worker, repeats the work on every retry and couples delivery to the URL engine; rejected. **Rewrite at SMTP time (milter):** before scanning and storage, violates ADR-0019/0022 ordering; rejected.
- **AEAD tokens** (encrypted claims): longer (nonce + tag), nonce management, no benefit since claims are not secrets; rejected. **Opaque random tokens** with a lookup table: needs a write per URL and a DB hit before any validation (cheap DoS); rejected. **URL inside the token:** violates "original URL server side" and allows token-length attacks; rejected.
- **Click-service inside the api:** mixes an anonymous Internet-facing, high-rate endpoint with the authenticated control plane and its secrets; rejected. **Click-service writing only to RabbitMQ:** loses the "MySQL + outbox" record when the broker is down and needs a broker user on an Internet-facing service; rejected.
- **Reading Rspamd URL symbols:** order-dependent within a round (U1); rejected for 4.3.
- **jsdom / static-only dynamic analysis:** runs hostile JS in Node or cannot see JS behaviour; rejected (ADR-0032). **Browser in the email-worker:** a browser exploit would get the worker's MySQL writer, S3 and token secrets; rejected. **Route interception only (Playwright `page.route`) without network isolation:** misses WebSocket/WebRTC/DNS paths; kept only as defence in depth, not as the control.
- **Relying on `http.Agent` `lookup` for SSRF:** works for the first connection but is easy to bypass (proxies, agents reusing sockets); the connector dials IP literals and re-checks `remoteAddress` instead. **Blocking only RFC 1918 + loopback:** misses CGNAT, NAT64/6to4/mapped forms and documentation ranges; the IANA special-purpose list is used.
- **Fetching every URL at scan time:** consumes one-time links; default `suspicious`.
- **Caching local-feed answers:** an analyst's block must apply at once; never cached.
- **Using `url_reputation`/`domain_reputation`/`ip_reputation` as the cache:** MySQL writes per lookup on the hot path and TTL handling in SQL; Redis is the cache, tables stay reserved.
- **Tenant-scoped threat indicators:** tenant lists are settings (`blockedDomains`, `allowedDomains`); platform feed is platform-wide (same reasoning as 4.2 A17).
