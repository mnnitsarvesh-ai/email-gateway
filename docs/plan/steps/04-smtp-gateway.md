# Step 2.2: Postfix SMTP gateway (inbound + outbound) with durable LMTP ingestion

Status: **implemented (waves 1–3); verification results in §12**. Owner: principal architect. Decision records: [ADR-0019](../../architecture/adr/0019-smtp-gateway-topology.md) (SMTP gateway topology: two Postfix instances, Node services behind Postfix's own extension protocols, ingestion contract; amends ADR-0006 and ADR-0011) and [ADR-0020](../../architecture/adr/0020-dkim-signing.md) (DKIM signing in a dedicated Rspamd fed by the api through an isolated, non-persistent Redis; amends ADR-0018 decision 1).

This note is the single source of truth for the implementers of this step. Each work package (WP1–WP6, §11) follows the decisions below. If a decision proves impossible (for example a Postfix or Rspamd behaviour differs from what is assumed here), the implementer documents the deviation in the docs their package owns and in their final report, and chooses the closest alternative that keeps the **invariants of §2.0**. **Nobody silently changes a decision.** Section numbers (§) and decision ids (D*n*) are stable references.

## 2. Decisions

### 2.0 Invariants (never traded away)

1. **No SMTP is implemented in Node.** Postfix speaks SMTP on every Internet- and tenant-facing port. Node implements only Postfix extension protocols (policy delegation, socketmap, the Dovecot SASL auth protocol) and an LMTP **server** built on the `smtp-server` library in LMTP mode.
2. **`250` only after durable acceptance.** In-session, Postfix answers `250` after its own `fsync`ed queue file (its spool is the first durable store). Post-queue, LMTP ingestion answers `250` per recipient only after the EML is in S3 **and** the writer transaction has committed. Every infrastructure failure answers `4xx` (`451 4.3.0`), never `5xx`.
3. **Fail closed.** Policy, socketmap, SASL and LMTP failures (timeouts, DB, Redis, S3) all become temporary SMTP errors. Nothing defaults to accept.
4. **No unrestricted relay anywhere.** Every listener's relay permission is explicit (§D9) and tested.
5. **Tenant from trusted context only**: the verified owner of the recipient domain (inbound), the authenticated connector (outbound), never headers.
6. **Bodies never in MySQL or on RabbitMQ**; S3 keys are `org/{organizationId}/…`.
7. **Generic SMTP texts**: no internal error details, tenant names or ids in any SMTP reply.

### D1. Topology

```
 Internet ──25──▶ postfix (inbound MX) ──policy 10040──▶ smtp-adapter
                     │  └─socketmap 10041 (relay_domain)─▶ smtp-adapter
                     │  └─milter 11332──▶ rspamd (existing)
                     └─LMTP 10050 (direction inbound)──▶ smtp-adapter ingestion ──▶ S3 + MySQL writer (1 txn) ──▶ outbox
 Tenant servers ──587 submission (STARTTLS + SASL)──▶ postfix-outbound ──SASL 10042──▶ smtp-adapter
                ──25  connector relay (source IP / client cert)──▶ postfix-outbound
                     │  policy 10040 (contexts submission|relay), socketmap 10041 (relay_client, relay_ccert)
                     └─LMTP 10051 (direction outbound, content_filter)──▶ smtp-adapter ingestion
 delivery-worker (3.x/5.x) ──10026 reinject-inbound──▶ postfix-outbound ──transport/tls_policy socketmap──▶ tenant destination servers
                           ──10027 reinject-outbound──▶ postfix-outbound ──milter──▶ rspamd-outbound (DKIM sign) ──MX──▶ Internet
 postfix-outbound DSN copies (notify_classes bounce, delay) ──LMTP 10052──▶ smtp-adapter bounce handler ──▶ bounce_events, delivery_suppressions, reputation
 api ──DKIM key publisher──▶ redis-dkim (ACL, no persistence) ◀──read── rspamd-outbound ; ◀──selector probe── smtp-adapter
```

- **Two Postfix instances**: `postfix` (inbound MX, existing service, extended) and `postfix-outbound` (new Compose service). Separate queues, separate scaling (inbound absorbs Internet bursts; outbound needs static egress IPs, a long-lived spool for tenant-server outages and its own reputation). Same image family (Debian bookworm Postfix 3.7), separate `infrastructure/postfix-outbound` directory.
- **Outbound mail is ingested like inbound** (diagram 7): authenticated submissions are accepted in-session, queued by `postfix-outbound`, then handed to ingestion over LMTP with `direction = outbound` through `content_filter`. Delivery to the Internet happens only through the **reinjection** listeners after the post-queue pipeline approves a message (delivery-worker, steps 3.x/5.x). In this step nothing reinjects automatically; the listeners exist, are configured, secured and tested (the integration tests act as the delivery-worker). This keeps "nothing leaves unscanned" from day one; there is **no direct submission-to-Internet path**.
- **smtp-adapter** grows from one listener to six (all internal, all fail closed): policy `:10040` (exists), socketmap `:10041`, SASL auth `:10042`, LMTP inbound `:10050`, LMTP outbound `:10051`, LMTP bounces `:10052`. Ports above 1024 because the image runs as `node`.
- **rspamd-outbound** (new): a dedicated Rspamd that only signs (DKIM) on the outbound reinjection listener (§D12). The existing `rspamd` stays the inbound content milter.
- **redis-dkim** (new): a tiny Redis without persistence holding DKIM signing keys, with ACL users per role (§D12).
- Test-only services under the Compose profile **`smtp-test`**: `mail-sink` (Postfix that stores everything it receives and rejects scripted local parts), `dns-sink` (CoreDNS authoritative for `sink.test`, nothing else), `smtp-tools` (swaks, `smtp-source`, openssl). See §6.

### D2. Inbound: relay domains and the LMTP transport

- `relay_domains = socketmap:inet:${SMTP_ADAPTER_HOST}:10041:relay_domain`. The adapter answers `OK` for a domain that `resolveActiveDomain` resolves **and** has `inbound_enabled`; `NOTFOUND` otherwise (including keys that start with `.` or contain `@`). The static `POSTFIX_RELAY_DOMAINS` is no longer read by Postfix (deprecated in `.env.example`).
- Unknown or inactive domains keep failing at `reject_unauth_destination` with Postfix's permanent `554 5.7.1 … Relay access denied`. If the adapter is unreachable, the relay check becomes `451 4.3.0 Temporary lookup failure` (fail closed).
- `relay_transport = lmtp:inet:${SMTP_ADAPTER_HOST}:10050`, `lmtp_send_xforward_command = yes`, `lmtp_destination_recipient_limit = 100` (= `smtpd_recipient_limit`, one LMTP transaction per message), `lmtp_destination_concurrency_limit = 20`, `lmtp_data_done_timeout = 600s`. `transport_maps` stays empty on the inbound instance: every accepted message goes to ingestion, never directly to a tenant.
- `enable_long_queue_ids = yes` on both instances (queue ids are not reused; they feed the ingest key, D7).
- Queue: `maximal_queue_lifetime = 5d`, `bounce_queue_lifetime = 5d`; `minimal_backoff_time`, `maximal_backoff_time`, `queue_run_delay` from the environment (production 300s/4000s/300s; local 30s/120s/30s so recovery tests finish quickly; tests may also `postqueue -f`).
- `hopcount_limit = 30` on both instances (Postfix counts `Received:` headers during DATA and rejects in-session with `554 5.4.0`).
- `smtpd_data_restrictions = reject_unauth_pipelining, reject_multi_recipient_bounce`.
- Policy calls use per-service settings: `check_policy_service { inet:${SMTP_ADAPTER_HOST}:10040, timeout=10s, default_action=DEFER_IF_PERMIT 4.3.5 Policy service unavailable, policy_context=inbound }` in `smtpd_recipient_restrictions` (after `reject_unauth_destination`) **and** in `smtpd_end_of_data_restrictions` (message-size enforcement, D4).

### D3. Inbound recipient validation (tenant configuration model)

Per-domain mode, stored in the **existing** `domain_settings` columns (no enum change):

| `recipient_validation` | `reject_unknown_recipients` | Behaviour at RCPT                                                                                                                                        | API name (WP5)                                  |
| ---------------------- | --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| `none` (or no row)     | any                         | **accept-all**: every local part is accepted                                                                                                             | `mode: accept_all`                              |
| `list`                 | `true`                      | **authoritative allow-list**: local part not in `domain_recipient_addresses` → `REJECT 5.1.1 Recipient address rejected: User unknown` (permanent 550)   | `mode: allow_list, enforcement: reject`         |
| `list`                 | `false`                     | **monitor** (onboarding shadow mode): accepted; a would-reject is counted (`smtp_policy_recipient_unknown_total{enforced="false"}`) and logged at debug  | `mode: allow_list, enforcement: monitor`        |
| `smtp_callout`, `ldap` | any                         | **NOT IMPLEMENTED** in this step: accept-all, counted as `smtp_policy_recipient_validation_unsupported_total`, warn log rate-limited to 1/min per domain | API refuses to set them (`422 Not implemented`) |

- Lookup: lower-cased local part exact match; if not found and `SMTP_RECIPIENT_DELIMITER` (default `+`) is set and present, retry with the part before the first delimiter. Domain part is never part of the key (rows belong to the domain).
- New table `domain_recipient_addresses` (§3). The adapter caches per-address results in Redis for `SMTP_DOMAIN_CACHE_TTL_SECONDS` (positive) / `SMTP_NEGATIVE_CACHE_TTL_SECONDS` (negative). Allow-list and mode changes therefore take effect within ≤ 60 s (documented; no cross-service cache invalidation for settings in this step).
- 5.1.1 is only ever returned when the mode is authoritative. Everything else that is not a definitive "no" is accept or 4xx.

### D4. Inbound policy decision (context `inbound`)

At `protocol_state=RCPT`, in this order; the first non-pass result is returned:

1. **Context check**: unknown or missing `policy_context` → `DEFER_IF_PERMIT 4.3.5 Policy service temporarily unavailable` + error log (misconfiguration must never open anything).
2. **Recipient domain** → domain policy view (D5 cache). Not resolvable or `inbound_enabled = false` → `REJECT 5.7.1 Relay access denied` (normally unreachable because `relay_domains` already rejected; guards cache skew).
3. **Per-client-IP rate**: `SMTP_RATE_CLIENT_RCPT_PER_MINUTE` recipients per minute per `client_address` (fixed 60 s window, D6) → `DEFER_IF_PERMIT 4.7.1 Rate limit exceeded, try again later`.
4. **Per-tenant inbound rate**: `organization_limits.inbound_recipients_per_minute` of the owning organization (fallback `SMTP_RATE_TENANT_INBOUND_RCPT_PER_MINUTE`) → same 4.7.1 deferral.
5. **Recipient validation** (D3).
6. **Size**: tenant size limit = min(`domain_settings.max_message_size_bytes`, `organization_limits.max_message_size_bytes`, Postfix `message_size_limit`). If the client declared `SIZE=` (`size` attribute > 0) and it exceeds the limit → `REJECT 5.3.4 Message too big for recipient`. Otherwise record `min(limit)` for this `instance` in Redis (`sa:inst:{instance}`, TTL 15 min).
7. Pass → `DUNNO`.

At `protocol_state=END-OF-MESSAGE` (same context): read `sa:inst:{instance}`; `size` > recorded limit → `REJECT 5.3.4 Message too big`; missing key → `DUNNO` (no recipient set a stricter limit); Redis error → tempfail.

Any thrown error, Redis/DB failure or a decision exceeding `SMTP_POLICY_DECISION_TIMEOUT_MS` → `DEFER_IF_PERMIT 4.3.5 Policy service temporarily unavailable`. The adapter **never** answers `OK`.

### D5. Tenant resolution cache and invalidation

- `DomainPolicyView` = `resolveActiveDomain` result + `domain_settings` (`recipientValidation`, `rejectUnknownRecipients`, `maxMessageSizeBytes`) + `hasActiveDkimKey` (any `domain_dkim_keys` row with `status = 'active'`). Loaded with at most three indexed writer queries on a miss.
- Cached in Redis as JSON under `sa:dom:{asciiName}` for `SMTP_DOMAIN_CACHE_TTL_SECONDS` (default 60); a negative result is cached as the literal `null` for `SMTP_NEGATIVE_CACHE_TTL_SECONDS` (default 30). Bigints serialized as decimal strings.
- **Explicit invalidation**: a `DomainCacheInvalidator` in each adapter replica tails `message_outbox` every `SMTP_CACHE_INVALIDATION_POLL_MS` (default 5000): `SELECT id, payload FROM message_outbox WHERE id > ? AND event_type = 'domain.status.changed.v1' ORDER BY id LIMIT 500` (writer; PK range per partition), starting from `MAX(id)` at boot, and `DEL`s `sa:dom:{payload.name}` plus the socketmap keys derived from that name. Ids committed out of order may be skipped; the TTL is the guarantee and the tail is the fast path (≤ 5 s typical). When the outbox relay exists (3.2) this becomes a RabbitMQ subscription; the cache contract does not change.
- Cache **read/write errors are non-fatal for lookups** (fall back to the DB, count `smtp_cache_errors_total`); rate limiting is fatal (D6), so the inbound policy still fails closed when Redis is down.

### D6. Rate limits (Redis, fail closed)

- Fixed-window counters with one atomic Lua script (`INCRBY` + `PEXPIRE` on first increment) per key; the window is the current UTC minute (`floor(epochMs / 60000)`) or UTC day. A request over the limit is still counted (attempts count).
- Keys: `sa:rl:ip:{ip}:{minute}`, `sa:rl:in:{orgId}:{minute}`, `sa:rl:out:{orgId}:{minute}`, `sa:rl:outd:{orgId}:{yyyymmdd}`; TTL = window + 10 s.
- Limits per organization come from `organization_limits` (new keys `inbound_recipients_per_minute`, `outbound_recipients_per_minute`, `outbound_recipients_per_day`; seeded per plan by WP1) cached in Redis `sa:lim:{orgId}` (TTL 60 s); missing rows use the `SMTP_RATE_TENANT_*` defaults. A limit value of `0` means "no mail of that kind" (always defer).
- Redis unavailable → `DEFER_IF_PERMIT 4.3.5`. Never DUNNO.
- Connection-level limits are Postfix's (anvil + postscreen, D8); the adapter counts recipients.

### D7. Durable LMTP ingestion

Implemented with `smtp-server` (`lmtp: true`, `useXForward: true`, `disabledCommands: ['AUTH', 'STARTTLS']`, `hideSTARTTLS: true`, `maxClients: LMTP_MAX_CLIENTS`, `size: INGEST_MAX_MESSAGE_BYTES`). Two listeners share one service: `:10050` → `direction = inbound`, `:10051` → `direction = outbound`. The **listener port decides the direction**, never message content. Connections from outside `SMTP_INTERNAL_CLIENT_NETWORKS` are refused at `onConnect` (`554 5.7.1`... closing; internal callers only).

Per LMTP transaction:

1. **Envelope**: `MAIL FROM` (null sender → `envelopeFrom = ''`), each `RCPT TO` is resolved immediately:
   - inbound: recipient domain → **owner** via the new `resolveDomainOwner(db, name)` (WP1, `packages/database`): the verified owner of the name for domain status `active` or `suspended` with organization status `active` or `suspended` (mail accepted in-session before a suspension is still ingested; post-queue policy decides). No owner → that RCPT gets `451 4.3.0 Temporary failure, please retry` (Postfix keeps the recipient queued; after `maximal_queue_lifetime` Postfix returns it, which is standard MTA behaviour for an unroutable destination).
   - outbound: the organization is resolved once from the **envelope sender domain** with `resolveDomainOwner` (the policy already proved, in-session, that the authenticated connector belongs to that organization; port 10051 is reachable only from `postfix-outbound`). Null sender or no owner → `451 4.3.0` for every recipient.
   - XFORWARD must supply `IDENT` (the Postfix queue id). Missing → `451 4.3.0` + error log (the dedupe key needs it). `ADDR` → `client_ip`, `HELO` → `client_helo`. The LMTP client's `LHLO` hostname is the MTA id.
2. **DATA** (streaming, bounded memory): the stream flows through (a) a header scanner that keeps at most `INGEST_HEADER_MAX_BYTES` (64 KiB) until the first empty line, (b) a SHA-256 hash, (c) a byte counter, into (d) `@aws-sdk/lib-storage` `Upload` (multipart above `INGEST_S3_PART_SIZE_BYTES` = 5 MiB, `queueSize = INGEST_S3_QUEUE_SIZE` = 2, `AbortSignal` after `INGEST_S3_TIMEOUT_MS`). Memory per message ≤ part size × (queue size + 1). The whole message is never held in memory beyond one part.
   - The object is written once, under the first organization's key (D8 key format), with `ContentType: message/rfc822` and server-side encryption left to the bucket default (MinIO locally, SSE-KMS in AWS via the bucket policy of step 10.1). For every additional organization of an inbound multi-tenant message, a server-side `CopyObject` creates the object under that organization's prefix (no re-streaming, tenant prefixes stay disjoint).
3. **Header metadata** (no MIME parsing; step 3.1 owns that): unfolded raw values of the first `Message-ID` (≤ 998), `Subject` (≤ 998 characters, cut at a UTF-8 boundary, encoded-words left as-is), `From` (the address inside `<…>` if present, else the raw value, ≤ 320); the count of `Received:` headers (metric only); every `X-Gateway-Trace` header value (D14).
4. **Loop check** (D14) per organization; a looping organization's recipients get `554 5.4.6 Routing loop detected` (exception documented in ADR-0019).
5. **Outbound From check**: for `direction = outbound`, the header `From` must contain exactly one address whose domain equals the envelope sender domain (ASCII-normalized); otherwise every recipient gets `550 5.7.1 From header does not match the authenticated sender domain`. The sender is authenticated, so the resulting DSN is a real bounce to a real tenant user, not backscatter (ADR-0019).
6. **Commit**, one writer transaction **per organization** (`INGEST_DB_TIMEOUT_MS`), all rows sharing one `received_at` (commit-time `new Date()` taken just before the transaction):
   - `message_identities` (`organization_id`, `ingest_key`, `received_at`) — duplicate `(organization_id, ingest_key)` (pre-check `findUnique`, and a `P2002` race also counts) → **duplicate**: roll back, answer `250` for that organization's recipients, and if the just-written object key differs from the committed row's `eml_object_key`, delete the just-written object (best effort).
   - `email_messages` (`id` = registry id, `received_at`, `organization_id`, `domain_id` = inbound: the first recipient's domain of that organization, outbound: the sender domain; `direction`; `status = received`; `status_changed_at = received_at`; header metadata; `envelope_from`; `size_bytes`; `recipient_count` = that organization's recipients; `eml_object_key`; `eml_sha256`; `client_ip`; `client_helo`; `mta_queue_id`).
   - `email_recipients`, one per accepted recipient of that organization (`rcpt_seq` 0..n-1 in RCPT order, `address` as given lower-cased domain, `status = pending`).
   - `email_events` one row (`event_type = 'received'`, `source_service = 'smtp-adapter'`, `occurred_at = received_at`, `details = { direction, queueId, recipientCount, sizeBytes }`).
   - `message_outbox` one `mail.message.received.v1` row (`event_id` = `randomUUID()`, `aggregate_type = 'message'`, `aggregate_id` = decimal message id, `correlation_id = 'lmtp:' + queueId`, payload validated with `messageReceivedV1.parse` before insert).
7. **Replies**: per recipient, in RCPT order: `250 2.0.0 Ok` after that organization's commit (or duplicate); `451 4.3.0 Temporary failure, please retry` for any failure of that organization (S3, DB, timeout, unexpected). Organizations are independent: a partial failure makes Postfix retry only the failed recipients, and the retry for them is idempotent: the ingest key covers each organization's recipient set, so the retry of a subset is stored rather than deduplicated (§12.7). The listener answers one reply per RCPT that got `250`; RCPTs that differ only in letter case (smtp-server merges them in `envelope.rcptTo`) are one recipient and repeat its reply (§12.7).
8. Logs carry `queueId`, organization id(s), message id(s), outcome and duration, never addresses beyond the domain at info level. Metrics: `smtp_ingest_messages_total{direction,outcome}` (`stored|duplicate|tempfail|loop|from_mismatch`), `smtp_ingest_duration_seconds{direction}`, `smtp_ingest_bytes_total{direction}`, `smtp_ingest_s3_errors_total`, `smtp_ingest_db_errors_total`.

**Ingest key** (fits `VARCHAR(128)`), per organization: `v2:` + hex SHA-256 of `{mtaId}|{queueId}|{direction}|{contentSha256}|{recipientSetSha256}`, where the recipient set is that organization's accepted recipient addresses (lower-cased, de-duplicated, sorted, LF-joined). An LMTP retry after a lost `250` carries the same queue file and the same recipients, so the same key → duplicate → `250` without new rows. A retry of only the recipients Postfix still holds (one RCPT tempfailed while another of the same organization was stored) has a different recipient set and is stored as its own message. _Review change (§12.7): the original `v1:` key had no recipient set, so that retry was answered `250` as a duplicate and the recipient was lost._ The organization is the other half of the unique key, so one message split over two organizations yields two registry rows.

### D8. S3 key format (contract change)

`org/{organizationId}/eml/{yyyy}/{mm}/{dd}/{objectRef}.eml`, where the date is the UTC date of the ingestion attempt and `objectRef` = first 32 hex characters of SHA-256(`{mtaId}|{queueId}|{direction}|{organizationId}`). Deterministic per queue file and organization, so a same-day retry overwrites its own object instead of orphaning one. The key is stored in `email_messages.eml_object_key` and carried in the event; consumers never derive it. **This replaces the `{messageId}.eml` example** in `contracts.md` §11 and diagram 6 (the message id does not exist before the transaction that must follow the upload). Orphans (upload succeeded, commit failed and never retried successfully on the same day) are possible and rare; their reconciliation joins the step 3.2 reconciliation job (§10).

- Reinjection ports are **not published** to the host.

### D10. Outbound connectors and SASL

**Model** (new tables, §3): an organization-level `smtp_connectors` row with one `auth_type`:

- `sasl` — SMTP AUTH (PLAIN/LOGIN over TLS) on 587. Username generated by the api (`egc-` + 20 lower-case base32 characters), secret generated by the api (32 random bytes, base64url), returned **once**, stored as an Argon2id PHC hash (same parameters as user passwords, `AUTH_ARGON2_*`).
- `source_ip` — one or more CIDRs in `smtp_connector_networks`. IPv4 prefix ≥ /16, IPv6 prefix ≥ /48. _Review change (§12.7):_ networks must be publicly routable; one overlapping a private, loopback, link-local, shared, documentation, benchmarking, multicast or reserved range (IANA special-purpose registries) is `400`, unless `SMTP_CONNECTOR_ALLOW_NON_PUBLIC_NETWORKS=true` (dedicated deployments relaying from the customer's private networks). **Networks may not overlap any other connector's network, in any organization** (enforced by the api under a MySQL named lock), so an IP maps to at most one organization. The connector option `require_tls` (default `true`) makes the policy refuse unencrypted sessions (`encryption_protocol` empty → `REJECT 5.7.1 Must issue a STARTTLS command first`).
- `client_certificate` — SHA-256 certificate fingerprint (64 hex, stored lower-case without colons; globally unique) on the port 25 relay listener; optional networks restrict the client IPs further.
- `status` `active | disabled`. Disabled connectors, connectors of non-active organizations, and unknown credentials never authorize anything.
- Security note (documented for customers): `source_ip` connectors **must not** be used with shared-IP mail platforms (Microsoft 365, Google Workspace), because any customer of that platform could then send as the tenant. Use SASL or client certificates there. The non-overlap rule prevents two tenants claiming the same range but cannot know who else sends from it.
- `domain_mail_servers.role = outbound_source` (step 1.1) is **deprecated**: not read by the mail path; connectors are organization-level because sending infrastructure is. `inbound_destination` rows remain the tenant destination for D11.

**SASL backend decision**: Postfix's `smtpd_sasl_type = dovecot` client talks to a **Dovecot-auth-protocol server inside smtp-adapter** (`smtpd_sasl_path = inet:${SMTP_ADAPTER_HOST}:10042`). Justification: Postfix stays credential-free (security boundary Z2: Postfix holds spool access only, no data-store credentials); Argon2id verification, connector and organization status, failure throttling and metrics live in one place with the rest of the connector logic; no Dovecot or Cyrus process, no SQL account readable from the edge container. Alternatives in §7.

Protocol subset (server side of the Dovecot auth protocol v1.2, <https://doc.dovecot.org/developer_manual/design/auth_protocol/>):

- On connect the server sends `VERSION\t1\t2`, `MECH\tPLAIN\tplaintext`, `MECH\tLOGIN\tplaintext`, `SPID\t<pid>`, `CUID\t<counter>`, `COOKIE\t<32 hex>`, `DONE`; the client sends `VERSION` and `CPID`. Unsupported major version → close.
- `AUTH\t<id>\t<mech>\tservice=smtp\t…\t[secured]\t[resp=<base64>]`. Mechanisms: `PLAIN` (single response; authzid must be empty or equal the authcid) and `LOGIN` (`CONT\t<id>\t<base64 "Username:">`, then `CONT` for `Password:`). Request without `secured` → `FAIL\t<id>` (Postfix also enforces `smtpd_tls_auth_only`).
- Success → `OK\t<id>\tuser=<username>`. Wrong credentials → `FAIL\t<id>\tuser=<username>` after `SMTP_AUTH_FAILURE_DELAY_MS` (default 2000). DB/Redis error, or more than `SMTP_AUTH_MAX_FAILURES_PER_IP` failures for `rip` in `SMTP_AUTH_FAILURE_WINDOW_SECONDS` (Redis `sa:authfail:{ip}`) → `FAIL\t<id>\ttemp` (Postfix answers `454 4.7.0 Temporary authentication failure`). Lines over 64 KiB or malformed → close the connection. **WP6 deviation (§12, fix 4):** Postfix 3.7 ignores `temp` and answers `535` for every `FAIL`; temporary failures therefore close the connection (Postfix answers `454 4.7.0`), and the 587 listener runs `max_use=1` because Postfix's Dovecot client never reconnects inside a process.
- Successful Argon2id verifications are cached in process memory for `SMTP_AUTH_VERIFY_CACHE_SECONDS` keyed by HMAC-SHA256(per-process random key, username + NUL + secret + NUL + connector `updated_at`), so a rotated secret or changed connector invalidates the entry; connector and organization status are still checked on every AUTH.
- Postfix-side throttles: `smtpd_client_auth_rate_limit` (anvil), `smtpd_hard_error_limit`.

### D11. Outbound policy contexts, transport and TLS maps

**Connector resolution** (Redis cache `sa:conn:*` 30 s TTL): `submission` → `sasl_username` → active `sasl` connector; `relay` → `ccert_fingerprint` (normalized) → active `client_certificate` connector (plus its networks if any), else `client_address` → active `source_ip` connector containing it (indexed range query on `smtp_connector_networks`, §3). Certificate wins over IP.

**`submission` / `relay`** at RCPT, first non-pass wins:

1. No connector, or connector/organization not active → `REJECT 5.7.1 Relay access denied`.
2. `relay` with `require_tls` and no TLS → `REJECT 5.7.1 Must issue a STARTTLS command first`.
3. Sender: non-null; domain resolves with `resolveActiveDomain` (D5 cache); same organization as the connector; `outbound_enabled` → else `REJECT 5.7.1 Sender address not authorized`.
4. `SMTP_OUTBOUND_REQUIRE_DKIM=true` and the sender domain has no `active` DKIM key → `REJECT 5.7.1 Sender domain is not ready for outbound mail`.
5. Suppression: `delivery_suppressions` row for (organization, lower-cased recipient) with `expires_at` null or in the future → `REJECT 5.7.1 Recipient address suppressed` (counted as reputation event `suppressed`).
6. Per-tenant outbound per-minute and per-day limits (D6) → `DEFER_IF_PERMIT 4.7.1 Rate limit exceeded, try again later` (`rate_limited`).
7. Size (`size` attribute vs organization `max_message_size_bytes`) → `REJECT 5.3.4 Message too big`.
8. Pass → `DUNNO`, reputation event `submitted`.

The header `From` check happens at outbound ingestion (D7 step 5), because policy delegation never sees headers.

**`reinject-inbound`** (10026): recipient domain must resolve (`resolveActiveDomain`) → else `REJECT 5.7.1 Relay access denied`; `DUNNO`. (Restricts the trusted delivery network to tenant destinations; it can never relay to the Internet.)

**`reinject-outbound`** (10027): sender domain active and `outbound_enabled` → else `REJECT 5.7.1 Sender address not authorized`; suppression check (as above); DKIM readiness: `HEXISTS dkim_selectors <senderDomain>` on redis-dkim with the probe account → missing or redis-dkim error → `DEFER_IF_PERMIT 4.7.0 Signing key not available` (never send unsigned when signing is required); pass → `DUNNO`, reputation `relayed`.

**Socketmap** (`:10041`, netstring protocol <https://www.postfix.org/socketmap_table.5.html>; replies `OK <value>`, `NOTFOUND `, `TEMP <reason>`, `PERM <reason>`; request ≤ 10 000 bytes; malformed → close):

| Map name       | Used by                                                                        | Key → answer                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| -------------- | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `relay_domain` | inbound `relay_domains`                                                        | domain → `OK active` when active + `inbound_enabled`; `NOTFOUND` otherwise or for `.parent` / `user@domain` keys                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `transport`    | outbound `transport_maps` (after the static `texthash:/etc/postfix/transport`) | domain of an active tenant domain (**WP6, §12 fix 3:** Postfix sends socketmap transport tables the full recipient address `user@domain`, so the domain part of such a key is used) → `smtp:[host]:port` of its highest-priority (lowest `priority`) enabled `inbound_destination` server; tenant domain without one, or whose destination is one of the gateway's own hosts (`GATEWAY_MX_HOSTS`, `POSTFIX_MYHOSTNAME`, `POSTFIX_OUTBOUND_MYHOSTNAME`) → `retry:4.4.1 Destination not configured` (deferred, error log); anything else → `NOTFOUND` (Postfix's MX resolution) |
| `tls_policy`   | outbound `smtp_tls_policy_maps`                                                | `[host]:port` of a tenant destination → `none`→`none`, `opportunistic`→`may`, `required`→`encrypt protocols=>=TLSv1.2`, `verify`→`secure match=nexthop protocols=>=TLSv1.2` (strictest mode if several rows share the host); otherwise `NOTFOUND` (global `smtp_tls_security_level = may`)                                                                                                                                                                                                                                                                                    |

| `relay_ccert`  | outbound port 25 `check_ccert_access`                                          | certificate (or public-key) SHA-256 fingerprint of an active `client_certificate` connector → `OK`; else `NOTFOUND`                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

DB errors → `TEMP Lookup failed` (Postfix defers; fail closed). Unknown map → `PERM Unknown map`. Single next-hop per tenant (multiple destinations with failover are step 2.3). Destination MX resolution, retries, backoff and queue lifetime are **Postfix's** (ADR-0006): no retry logic in Node.

### D12. DKIM signing (ADR-0020)

- **Mechanism**: `rspamd-outbound` (Rspamd 3.12, same image as `rspamd`) runs as the milter of the `10027` reinject-outbound listener only, with `dkim_signing` reading keys from Redis (`use_redis = true`), `use_domain = "header"`, `allow_hdrfrom_mismatch = false`, `allow_username_mismatch = true`, `sign_local = true`, `sign_networks = ["0.0.0.0/0", "::/0"]` (its milter port is reachable only from `postfix-outbound`, and only the 10027 listener uses it; _review change (§12.7)_: enforced locally by the internal Compose network `dkim-signing`, the only network of `rspamd-outbound`; `sign_networks` cannot narrow it because Rspamd matches it against the client address the milter peer itself reports), `try_fallback = false`, `use_esld = false`. All `actions` are disabled (no reject, no add_header): it only signs. Only RSA keys are published (one selector per domain, the domain's `active` `rsa_2048` key); Ed25519 dual signing is out of scope (§10).
- **Key distribution**: the **api** (the only holder of `DATA_ENCRYPTION_KEY`) runs a `DkimSigningPublisher` that reconciles every `DKIM_SIGNING_SYNC_INTERVAL_SECONDS` (default 30; one replica per tick via the existing KV lock pattern) and on demand (`pnpm --filter @email-gateway/api dkim:sync`, one-shot CLI used by tests and operators). Desired state: for every domain with `status = active`, `outbound_enabled = true`, organization `active`, its `active` `rsa_2048` key with a ciphertext → decrypt with `SecretBox` (AAD `dkim:<publicId>:<selector>`). Redis layout (two hashes): `dkim_selectors` field `<domain>` → `<selector>`; `dkim_keys` field `<selector>.<domain>` → PKCS#8 PEM. Changes are applied in `MULTI/EXEC`: write the key before the selector; remove the selector before the key; prune `dkim_keys` fields no longer referenced. PEMs are never logged. Implementers verify the exact Rspamd option names (`selector_prefix`, `key_prefix`) for 3.12 and adapt names, not the layout.
- **redis-dkim**: Redis 7.4, `--save '' --appendonly no` (keys never touch disk outside MySQL ciphertext), `--maxmemory 64mb --maxmemory-policy noeviction`, ACL file rendered at start from env (tmpfs, mode 0600): `default` off; `dkim-writer` (api): `~dkim_selectors ~dkim_keys +ping +hget +hgetall +hkeys +hset +hdel +hexists +multi +exec +del`; `dkim-reader` (rspamd-outbound): `~dkim_selectors ~dkim_keys +ping +hget +select` (+ anything Rspamd provably needs, documented); `dkim-probe` (smtp-adapter): `%R~dkim_selectors +ping +hexists +hget` (selectors are public data; it can never read keys). After a redis-dkim restart the keys are back within one sync interval; until then 10027 defers (fail closed).
- **Trade-off** (ADR-0020): plaintext signing keys live in the memory of three processes (api transiently, redis-dkim, rspamd-outbound). Mitigations: dedicated instance, ACLs per role, no persistence, internal network only (production: security groups so only api, adapter and rspamd-outbound reach it), keys only for active outbound-enabled domains, crypto-shredding in MySQL unchanged.

### D13. Bounce processing and reputation

- `postfix-outbound`: `notify_classes = bounce, delay`; `bounce_notice_recipient = delay_notice_recipient = 2bounce_notice_recipient = bounce-notices@${POSTFIX_BOUNCE_DOMAIN}` (default `bounces.gateway.internal`, a reserved, unroutable name); static transport `bounces.gateway.internal lmtp:inet:${SMTP_ADAPTER_HOST}:10052`; `delay_warning_time = ${POSTFIX_DELAY_WARNING_TIME}` (default 4h). Postfix sends the original sender its normal DSN (diagram 7: the sender is an authenticated tenant user) and the bounce handler a **postmaster copy** (multipart/report with `message/delivery-status` and the original headers only).
- Bounce LMTP (`:10052`, same LMTP wrapper, accepts only `bounce-notices@<bounce domain>` recipients, `BOUNCE_MAX_MESSAGE_BYTES` = 2 MiB, buffered — the size cap makes buffering safe). Parsed with `mailparser`; from the `message/delivery-status` part: per-message `Reporting-MTA`, `X-Postfix-Queue-ID`, `X-Postfix-Sender`, `Arrival-Date`; per recipient `Final-Recipient`, `Original-Recipient`, `Action`, `Status`, `Remote-MTA`, `Diagnostic-Code`. _Review change (§12.7):_ the LMTP envelope sender must be Postfix's bounce daemon (`<>` or `double-bounce@${POSTFIX_OUTBOUND_MYHOSTNAME}`, else `550 5.7.1` at MAIL), and the policy refuses the bounce-notice domain (and subdomains) as a recipient in every context (`REJECT 5.7.1 Relay access denied`), so no client can reach the handler through a listener and reinjection.
- Organization = owner of the `X-Postfix-Sender` domain (`resolveDomainOwner`). No owner (e.g. failures of reinject-inbound deliveries to tenant servers, whose sender is external) → ignored, counted `smtp_bounce_notices_total{outcome="ignored"}` (inbound delivery tracking is step 2.3). _Review change (§12.7):_ the notice is recorded only when the undelivered message's headers (`text/rfc822-headers`) carry a valid **outbound** `X-Gateway-Trace` of that organization (D14), i.e. the gateway reinjected the message on 10027 for delivery. Postmaster copies of ingestion-hop failures on postfix-outbound (content filter LMTP 10051: From check, loop, an adapter/S3/DB outage longer than `delay_warning_time`) carry none and are `ignored`; a notice naming another tenant's sender domain cannot carry that tenant's valid trace.
- Per failed/delayed recipient, one writer transaction: `bounce_events` (`occurred_at` = `Arrival-Date` parsed, else the notice's `Date`, deterministic for dedupe; `bounce_type` `hard` for `Action: failed`, `soft` for `delayed`; `smtp_code` from the diagnostic code; `enhanced_status`; `diagnostic` ≤ 1024; `reporting_mta`; `dedupe_key` = hex SHA-256 of `{queueId}|{finalRecipient}|{action}|{status}`; insert-if-absent on the unique `(organization_id, dedupe_key, occurred_at)`), and for hard bounces whose status is an address failure (`5.1.1`, `5.1.2`, `5.1.3`, `5.1.6`, `5.1.10`, `5.2.1`) an upsert of `delivery_suppressions` (`reason = hard_bounce`, `source = 'bounce'`, `expires_at = now + SUPPRESSION_HARD_BOUNCE_DAYS`; never shortens or replaces a `manual` or `complaint` suppression). `message_id` stays `NULL` (linking via `email_deliveries.outbound_queue_id` is step 2.3).
- Replies: committed or ignored → `250`; DB error → `451 4.3.0` (Postfix retries the notice); unparseable → `250` + `smtp_bounce_notices_total{outcome="unparseable"}` + warn log (a postmaster copy, not customer mail).
- **Reputation counters** (`ReputationRecorder`, WP1): Redis hash `rep:{orgId}:{yyyymmdd}` (`HINCRBY`, TTL 40 days) and the Prometheus counter `smtp_tenant_mail_events_total{organization_id, event}` with events `submitted`, `relayed`, `suppressed`, `rate_limited`, `bounced_hard`, `bounced_soft`, `delayed`. Recording never fails the mail path (errors are logged and counted). Documented PromQL for the bounce ratio (`bounced_hard / relayed`) and alert thresholds; automatic throttling of a tenant is out of scope (§10). Cardinality: one series per organization and event (bounded by tenants with outbound mail).

### D14. Loop prevention

- Postfix `hopcount_limit = 30` on both instances (in-session `554 5.4.0`).
- **Gateway trace header**, produced by whatever reinjects mail (delivery-worker, steps 3.x/5.x; the helper ships now in `@email-gateway/common`):
  `X-Gateway-Trace: v=1; g=<GATEWAY_TRACE_ID>; d=<in|out>; t=<unix seconds>; s=<sig>` where `sig` = base64url (no padding) of the first 16 bytes of HMAC-SHA256(`GATEWAY_TRACE_SECRET`, `v1|<g>|<d>|<t>|<organizationId>`). It reveals neither the tenant nor internal hosts (organization-neutral); `Received:` headers use `mx.gateway.local` / `out.gateway.local`-style host names only.
- Ingestion counts, per organization of the message, the valid traces (same `g`, same `d` as the listener's direction, signature verifies for that organization; constant-time compare). Count ≥ `SMTP_LOOP_MAX_PASSES` (default 1: the message already passed this gateway for that tenant and direction) → that organization's recipients get `554 5.4.6 Routing loop detected`. Forged traces cannot trigger it (HMAC); traces of other tenants or the other direction do not count (legitimate cross-tenant forwarding and outbound-then-inbound between two tenants keep working).
- The transport map never routes to the gateway's own hosts (D11), and Postfix's own "mail for X loops back to myself" check remains.

### D15. Connection limits, TLS, size

Inbound `master.cf`: `smtp inet n - n - 1 postscreen`, `smtpd pass - - n - - smtpd`, `dnsblog`, `tlsproxy`. postscreen with `postscreen_access_list = permit_mynetworks`, `postscreen_greet_action = ${POSTFIX_POSTSCREEN_GREET_ACTION}` (local `ignore`, production `enforce`), `postscreen_dnsbl_sites = ${POSTFIX_POSTSCREEN_DNSBL_SITES}` (empty locally), deep protocol tests off (they defer first contacts), `postscreen_client_connection_count_limit = $smtpd_client_connection_count_limit`. anvil (both instances, env-tunable): `smtpd_client_connection_count_limit` (50), `smtpd_client_connection_rate_limit` (300/min), `smtpd_client_message_rate_limit` (2000/min), `smtpd_client_recipient_rate_limit` (5000/min), `smtpd_client_new_tls_session_rate_limit` (300/min), `smtpd_client_auth_rate_limit` (outbound, 30/min), `anvil_rate_time_unit = 60s`; smtpd process limit `${POSTFIX_SMTPD_PROCESS_LIMIT}` (100). `smtpd_client_event_limit_exceptions` stays `$mynetworks` (loopback only on inbound).

TLS: `smtpd_tls_cert_file`/`smtpd_tls_key_file` from `POSTFIX_TLS_CERT_PATH`/`POSTFIX_TLS_KEY_PATH` (and `POSTFIX_OUTBOUND_TLS_*`; renamed from `*_FILE` by WP6, §12 fix 1), default the image's snakeoil pair; production mounts the certificate chain (runbook `smtp-tls-cert-rotation.md`: replace files, `postfix reload`). `smtpd_tls_protocols = >=TLSv1.2`, `smtpd_tls_mandatory_protocols = >=TLSv1.2`, `smtpd_tls_mandatory_ciphers = high`, `tls_preempt_cipherlist = yes`, session cache, `smtpd_tls_received_header = yes`, `smtpd_tls_loglevel = 1`. Outbound client: `smtp_tls_security_level = may` (per-destination policy from D11), `smtp_tls_loglevel = 1`; MTA-STS/DANE are out of scope (§10). `smtpd_tls_fingerprint_digest = sha256` on `postfix-outbound`.

Size: `message_size_limit = ${POSTFIX_MESSAGE_SIZE_LIMIT}` (50 MiB) on both instances (advertised `SIZE`, enforced by Postfix); per-tenant limits by policy (D4, D11). _Review change (§12.7):_ the outbound 587 and 25 listeners now also run the policy at END-OF-MESSAGE (`smtpd_end_of_data_restrictions`, contexts `submission` / `relay`); before, a client that left out `SIZE=` could exceed the tenant limit up to `message_size_limit`.

### D17. Compose topology, images and ports

See §6. Images are built **sequentially** (8 GB VM). `postfix-outbound`, `rspamd-outbound` and `redis-dkim` join the default (infrastructure) set; `mail-sink`, `dns-sink`, `smtp-tools` are profile `smtp-test`. `postfix-outbound` uses Docker's embedded DNS with `dns: [172.31.250.53]` (dns-sink) as upstream on a dedicated network `mailtest` (fixed subnet `172.31.250.0/24`; `dns-sink` `.53`, `mail-sink` `.25`), so locally **the outbound MTA can never reach the Internet**: CoreDNS is authoritative for `sink.test` and answers nothing else. Postfix containers get `extra_hosts: ["host.docker.internal:host-gateway"]` so `SMTP_ADAPTER_HOST=host.docker.internal` works when the adapter runs on the host (local default in this repository's `.env`; `.env.example` default `smtp-adapter` for the apps profile and CI).

### D18. Kubernetes and EC2

Kubernetes manifests are not changed (out of scope). `docs/deployment/smtp-gateway.md` documents the production model: inbound and outbound Postfix on separate EC2 Auto Scaling Groups (NLB on 25 for inbound; outbound with static Elastic IPs, PTR records and per-IP reputation), EBS-backed spool per instance, lifecycle hook that stops accepting (`postfix stop` of smtpd via `master.cf` disable / NLB deregistration), drains (`postqueue -f`, wait for an empty active queue) and never terminates an instance with a non-empty queue (the spool is moved or the instance is kept), smtp-adapter as an internal service reachable only from the Postfix ASGs, certificate distribution (ACM cannot export: use an S3 or Secrets Manager copy pulled at boot), security groups per port of D9, and capacity notes.

### D19. postfix-notify

Kept unchanged. Decision: it stays separate. Platform transactional mail (invitations, password resets) must not depend on tenant outbound health, tenant reputation, DKIM keys of customer domains, or the post-queue pipeline; it relays to its own upstream. A later step may move it onto `postfix-outbound` with a platform DKIM domain and a dedicated reputation pool; documented in the deployment doc, not done here.

### D20. Local adapter on the host

Integration tests run Postfix in Compose and smtp-adapter either as the `apps` profile container (CI) or on the host (`pnpm --filter @email-gateway/smtp-adapter dev`, local). All adapter listeners bind `MAIL_LISTEN_HOST`/`POLICY_HOST` (default `0.0.0.0`) and refuse peers outside `SMTP_INTERNAL_CLIENT_NETWORKS` (default loopback + RFC 1918), so host-mode is reachable from Docker but not from other networks.

/// Outbound relay connector of an organization (step 2.2 D10). Exactly one auth method.
model SmtpConnector {
  id                    BigInt                @id @default(autoincrement()) @db.UnsignedBigInt
  publicId              String                @unique @default(uuid(7)) @map("public_id") @db.Char(36)
  organizationId        BigInt                @map("organization_id") @db.UnsignedBigInt
  name                  String                @db.VarChar(128)

  status                SmtpConnectorStatus   @default(active)

  secretHash            String?               @map("secret_hash") @db.VarChar(255)
  secretSetAt           DateTime?             @map("secret_set_at") @db.DateTime(3)
  /// client_certificate only; lower-case hex SHA-256 of the DER certificate, no colons.
  certFingerprintSha256 String?               @unique @map("cert_fingerprint_sha256") @db.Char(64)
  /// Refuse sessions without TLS (source_ip; implied for sasl and client_certificate).
  requireTls            Boolean               @default(true) @map("require_tls")
  createdByUserId       BigInt?               @map("created_by_user_id") @db.UnsignedBigInt
  createdAt             DateTime              @default(now()) @map("created_at") @db.DateTime(3)
  updatedAt             DateTime              @updatedAt @map("updated_at") @db.DateTime(3)

  organization Organization           @relation(fields: [organizationId], references: [id], onDelete: Restrict)
  createdBy    User?                  @relation(fields: [createdByUserId], references: [id], onDelete: SetNull)
  networks     SmtpConnectorNetwork[]

  @@unique([organizationId, name])
  @@index([organizationId, status])
  @@map("smtp_connectors")
}

/// Allowed client network of a connector. Ranges never overlap across all connectors (api-enforced).
model SmtpConnectorNetwork {
  id             BigInt   @id @default(autoincrement()) @db.UnsignedBigInt
  organizationId BigInt   @map("organization_id") @db.UnsignedBigInt
  connectorId    BigInt   @map("connector_id") @db.UnsignedBigInt

  cidr           String   @db.VarChar(49)

  rangeStart     Bytes    @map("range_start") @db.VarBinary(16)
  rangeEnd       Bytes    @map("range_end") @db.VarBinary(16)
  createdAt      DateTime @default(now()) @map("created_at") @db.DateTime(3)

  organization Organization  @relation(fields: [organizationId], references: [id], onDelete: Restrict)
  connector    SmtpConnector @relation(fields: [connectorId], references: [id], onDelete: Cascade)

  @@unique([connectorId, cidr])
  @@index([ipVersion, rangeStart])
  @@map("smtp_connector_networks")
}

## 7. Alternatives considered

| Topic                   | Chosen                                                                                | Rejected and why                                                                                                                                                                                                                                                                                                                                                                 |
| ----------------------- | ------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Dynamic Postfix lookups | `socketmap` served by smtp-adapter                                                    | `mysql:` tables with a read-only account: puts DB credentials and SQL in the edge container (security boundary Z2), duplicates tenant-resolution rules in SQL, no cache shared with the policy; `tcp_table`: no reply escaping, weaker protocol; generated `hash:` files: reload lag and a sync job                                                                              |
| SASL                    | Dovecot auth protocol served by smtp-adapter                                          | Dovecot SASL + SQL passdb: battle-tested, but needs `dovecot-mysql` and DB credentials inside the Postfix container, a table-level GRANT that must be ordered after migrations, and duplicates connector-status rules; Cyrus `saslauthd`: no Argon2id, awkward multi-tenant mapping                                                                                              |
| DKIM signer             | Dedicated Rspamd `dkim_signing` + isolated Redis fed by the api                       | OpenDKIM with a KeyTable synced from MySQL: files with plaintext keys on disk and `DATA_ENCRYPTION_KEY` in a sync sidecar, OpenDKIM is barely maintained; signing in a Node after-queue filter: reimplements an SMTP hop and buffers messages; signing in the shared inbound Rspamd: widens key exposure to the scanner of untrusted mail and risks signing spoofed inbound mail |
| Outbound path in 2.2    | Submission → ingestion (LMTP, `direction = outbound`); delivery only via reinjection  | Direct submission → Internet with signing: faster to demo, but sends unscanned mail and creates a bypass that later steps must remove                                                                                                                                                                                                                                            |
| Multi-tenant split      | One S3 upload + `CopyObject` per extra organization; one transaction per organization | One transaction for all organizations: a failure of one tenant would defer the others; one object shared by several tenants: breaks per-tenant key prefixes and retention                                                                                                                                                                                                        |
| Ingestion dedupe        | `ingest_key` = MTA id + queue id + direction + content hash                           | Registry row reserved before the upload (two transactions, orphan registry rows); content hash alone (identical messages from different senders would merge)                                                                                                                                                                                                                     |
| Loop detection          | HMAC-signed, organization-neutral trace header checked at ingestion                   | Plain marker header (forgeable; would let anyone suppress delivery); header_checks in-session (cannot see the tenant)                                                                                                                                                                                                                                                            |
| Connection limits       | anvil + postscreen (greet/DNSBL off locally, on in production)                        | postscreen deep protocol tests (defer every first contact; breaks tests and first-time senders' latency)                                                                                                                                                                                                                                                                         |
| Cache invalidation      | Outbox tail + TTL                                                                     | api deleting adapter keys after commit (couples the api to the adapter's key layout, lost on crash); RabbitMQ (no relay until 3.2)                                                                                                                                                                                                                                               |
| Metrics                 | prom-client `/metrics` scraped directly                                               | OTel metrics SDK via the Collector: no metrics pipeline exists yet in the services, more moving parts for the same counters                                                                                                                                                                                                                                                      |

### 12.4 Fixes made by WP6 (bugs found by the stack tests)

1. **`POSTFIX_*TLS_*_FILE` → `POSTFIX_*TLS_*_PATH`** (`.env.example`, local `.env` keys renamed with unchanged values, `docker-compose.yml`, both Postfix entrypoints and `main.cf` comments, deployment doc, TLS runbook, §5/D15 here). Every Node service resolves `<KEY>_FILE` as a secret file (`packages/config`), so the api crashed on the host (`ENOENT /etc/ssl/certs/ssl-cert-snakeoil.pem`, e.g. `dkim:sync`). The adapter had worked around it with a key filter (comment updated).
2. **`postfix-outbound` `lmtp_host_lookup = native`** (was `dns, native`). Its resolver is dns-sink, which REFUSES names outside `sink.test`; Postfix treats that as a temporary error and never falls back to `/etc/hosts`, so with the adapter on the host every outbound ingestion and bounce notice stayed deferred (`Host not found, try again`). LMTP next hops are always internal hosts.
3. **Socketmap `transport` accepts the full recipient address** (`socketmap-lookup.service.ts` + unit and adapter-integration tests). Postfix sends socketmap transport tables one lookup with `user@domain` (socketmap is not an indexed table), never the bare domain, so the map answered `NOTFOUND` and reinject-inbound mail went to an MX lookup of the tenant domain instead of its destination. A bare domain key is still answered; `.parent`, `*`, `@x`, `a@b@x` stay `NOTFOUND`. (`relay_domain` is unaffected: `relay_domains` matching does query the domain.)
4. **SASL temporary failures close the connection** instead of `FAIL <id> temp` (`sasl-server.service.ts`, unit and integration tests), and **`-o max_use=1` on the 587 listener**. Postfix 3.7 answers `535 5.7.8` (permanent) for every `FAIL` line, so Redis/DB errors and throttling looked like wrong credentials. Only a lost auth connection maps to `454 4.7.0`; but Postfix's Dovecot client keeps one connection per `smtpd` process and never reconnects, so after any close (also a plain **adapter restart**, verified: three `454 … Connection lost to authentication server` in a row) every AUTH of that process failed until it exited. One session per process fixes both; verified by restarting the adapter (AUTH works at once) and by the Redis-down test (`235` after recovery).
5. `smtp-tools` gets `extra_hosts: host.docker.internal:host-gateway` (test-only, for the raw LMTP client on Linux hosts); `.prettierignore` gains `infrastructure/rspamd-outbound/**` (Rspamd UCL, like `infrastructure/rspamd/**`).
6. Test plumbing: `seed.test.ts` uses `DEMO.domain` instead of `POSTFIX_RELAY_DOMAINS`; `services.test.ts` gates on the `api` container (an adapter on the host is not "the apps profile"); the integration-tests package script is now `test:integration` (root `test:integration` updated), so `pnpm test` (turbo) no longer runs the stack suites alongside the unit tests (it failed without a stack and overloaded the machine with one).

None of these weakens a fail-closed rule or a relay restriction.
