# Schema reference

All 91 tables, by module. The source of truth is `packages/database/prisma/schema.prisma` and the migrations. The design is section 3 of [the step 1.1 design](../plan/steps/01-database.md#3-data-model); steps 1.2 + 1.3 added two identity tables and the identity/tenancy columns ([D10](../plan/steps/02-tenants-auth-rbac.md#d10-data-model-changes-one-forward-migration-wp1), migration `20261102061337_identity_tenancy`); step 2.1 added the domain lifecycle, DNS-check and DKIM key-custody columns ([§3](../plan/steps/03-domain-onboarding.md#3-data-model-one-forward-migration-wp1), migration `20261102091717_domain_onboarding`, plus the data-only `20261102110046_domain_check_backfill` that schedules pre-2.1 domains for their first check); step 2.2 added the recipient allow-list and the outbound SMTP connector tables ([§3](../plan/steps/04-smtp-gateway.md#3-data-model-one-forward-migration-wp1), migration `20261102120936_smtp_gateway`); step 2.3 added the destination provider presets, the reinjection groups, the delivery status audit trail, stream cursors and the per-recipient delivery tracking columns ([§3](../plan/steps/05-routing.md#3-data-model-one-forward-migration-mail_routing-wp1), migration `20261103090000_mail_routing`); step 3.1 added the MIME parse stage table and the attachment metadata columns ([§3](../plan/steps/06-mime-ingestion.md#3-data-model-one-forward-migration-mime_ingestion-wp1), migration `20261103200000_mime_ingestion`); step 3.2 added the outbox reconciliation columns (migration `20261104000000_event_relay`) and, in its review round 1, `message_consumer_progress` and the outbox index `(event_id)` (migration `20261104120000_consumer_progress`); step 3.3 replaced `MessageStatus` by the fifteen lifecycle states, added the lifecycle columns of `email_messages` and `email_message_status_history` and the api's `api_idempotency_keys` (migration `20261104130000_message_lifecycle`), and made the five Postfix queue-id columns case-sensitive (migration `20261104130100_queue_id_case_sensitive`); see [Step 3.3 changes](#step-33-changes-message-lifecycle); step 4.1 added the scan round and engine attempt columns, `email_messages.client_name`, the partitioned `email_auth_results` and `scan_engine_settings` (migration `20261105090000_scan_pipeline`); see [Step 4.1 changes](#step-41-changes-scan-pipeline); step 4.2 evolved `malware_signatures` into the known-threat hash catalog and added `attachment_scan_results`, `sandbox_submissions` (both partitioned), `attachment_rescan_jobs` and `scan_signature_versions` (migration `20261105103406_attachment_scanning`); see [Step 4.2 changes](#step-42-changes-attachment-scanning); step 4.3 evolved `threat_indicators` into the platform URL feed and added the five partitioned URL tables `message_urls`, `url_scan_results`, `url_rewrites`, `url_dynamic_inspections` and `url_click_events` (migration `20261105214341_url_protection`); see [Step 4.3 changes](#step-43-changes-url-protection); step 4.4 added the partitioned `bec_scan_results` and the six BEC tenant tables (migration `20261106171051_bec_detection`); see [Step 4.4 changes](#step-44-changes-phishing-and-bec). Diagrams are in [er-diagram.md](er-diagram.md), and index rationale in [indexing.md](indexing.md).

Legend:

- Every table has `id BIGINT UNSIGNED AUTO_INCREMENT` unless stated, and `created_at` (plus `updated_at` on mutable rows).
- **org** = `organization_id BIGINT UNSIGNED NOT NULL` with a foreign key to `organizations` (none on partitioned tables). **org?** = nullable (NULL means platform-level).
- **P** = partitioned (column, granularity); see [partitioning.md](partitioning.md). Retention tiers are in [retention.md](retention.md).
- **Owner** = the deployable that writes the table ([data ownership](../architecture/data-ownership.md)). Every service writes `message_idempotency` (through `processOnce`) and `message_outbox`.

## Step 3.3 changes (message lifecycle)

Design: [step 3.3 §3](../plan/steps/08-message-lifecycle.md#3-data-model), [ADR-0025](../architecture/adr/0025-message-lifecycle-state-machine.md).

**`MessageStatus` (the one-time enum replacement).** `email_messages.status` and `email_message_status_history.from_status` / `to_status` hold exactly `received`, `persisted`, `scanning`, `scanned`, `scan_failed`, `policy_evaluated`, `approved`, `quarantined`, `held_for_review`, `rejected`, `delivery_pending`, `delivery_retry`, `delivered`, `archived`, `expired` (default `received`). The migration widened the enum, mapped the old values (`received → persisted` with `version + 1` and a `received → persisted` history row, `delivery_queued → delivery_pending` with `status_reason = delivery_planned`, `delivered` gets `delivery_complete`, `partially_delivered → delivered` with `delivery_partial`, `failed → rejected` with `delivery_failed`, `discarded → rejected` with `discarded`; history rows renamed with the same mapping), added a version-0 `NULL → received` history row (`lifecycle_backfill`, `changed_at = received_at`) to every message without one, and then narrowed it. From now on the enum is append-only again.

**New columns.** `email_messages.lifecycle_round SMALLINT UNSIGNED NOT NULL DEFAULT 0` (+1 on rescan and release) and `status_reason VARCHAR(64) NULL` (reason code of the last applied transition). `email_message_status_history`: `lifecycle_round`, `actor_role VARCHAR(32) NOT NULL DEFAULT 'legacy'`, `actor_service VARCHAR(64) NOT NULL DEFAULT 'legacy'`, `actor_type ENUM('system','user','api_key') NOT NULL DEFAULT 'system'`, `actor_id VARCHAR(64) NULL` (operator public id), `correlation_id VARCHAR(128) NULL`, `transition_key CHAR(64) NULL` (hex SHA-256 of the transition idempotency key, [L5.3](../plan/steps/08-message-lifecycle.md#l53-transition-keys-idempotency)), `state_event_id CHAR(36) NULL` (the `mail.message.state_changed.v1` event id), `occurred_at DATETIME(3) NULL` (producer time: recorded, never compared). The unique key `(message_id, transition_key, received_at)` makes a transition idempotent per message; its name is `email_message_status_history_message_id_transition_key_recei_key` (Prisma's default, truncated to MySQL's 64-character identifier limit). Legacy rows have `NULL` keys, which never collide.

**`api_idempotency_keys`** (not partitioned, no foreign keys, owned by the api): see [Platform operations](#platform-operations-10). Purged by `db:partitions` one day after `expires_at` ([retention.md](retention.md)).

**Collations.** Five columns are `VARCHAR(32) CHARACTER SET utf8mb4 COLLATE utf8mb4_bin` (collation `utf8mb4_bin`, case-sensitive Postfix queue ids, step 3.3, [L15](../plan/steps/08-message-lifecycle.md#l15-case-sensitive-postfix-queue-ids-fix-found-in-step-32)): `email_messages.mta_queue_id`, `email_deliveries.outbound_queue_id`, `email_deliveries.dsn_queue_id`, `delivery_reinjections.queue_id`, `delivery_status_events.queue_id`; and `api_idempotency_keys.idempotency_key` is `VARCHAR(128) … utf8mb4_bin`. Every other text column keeps the table collation `utf8mb4_unicode_ci`. The character set is unchanged, so no data was converted. Prisma does not model column collation: `schema.prisma` documents it in the field comments, and `prisma migrate diff` reports no drift (checked against the main schema, a clean schema and the migration history with the shadow database).

**ALTER algorithms (MySQL 8.4.13).** Every statement names its algorithm, so MySQL refuses instead of silently choosing a slower one; the choices were tried on a throwaway schema (`email_gateway_verify`) before the migration ran:

| Migration                 | Statement                                                                                       | Algorithm              | Why                                                                               |
| ------------------------- | ----------------------------------------------------------------------------------------------- | ---------------------- | --------------------------------------------------------------------------------- |
| `message_lifecycle`       | Widen `email_messages.status` (append nine values)                                              | `INSTANT`              | Appending ENUM members that keep the 1-byte storage is a metadata change          |
| `message_lifecycle`       | Widen the history `from_status` / `to_status`                                                   | `INSTANT`              | Same                                                                              |
| `message_lifecycle`       | Add the nine history columns                                                                    | `INSTANT`              | Appended columns, constant defaults or nullable                                   |
| `message_lifecycle`       | Add `email_messages.lifecycle_round`, `status_reason`                                           | `INSTANT`              | Same                                                                              |
| `message_lifecycle`       | Backfill (two `INSERT … SELECT`, six `UPDATE` of `email_messages`, two `UPDATE` of the history) | DML                    | Every partition (no `received_at` bound); one-time                                |
| `message_lifecycle`       | Narrow and reorder `email_messages.status`                                                      | `COPY`                 | MySQL cannot remove or reorder ENUM members in place (`INPLACE` refused, ER 1846) |
| `message_lifecycle`       | Narrow and reorder the history `from_status` / `to_status`                                      | `COPY`                 | Same                                                                              |
| `message_lifecycle`       | Unique index `(message_id, transition_key, received_at)`                                        | `INPLACE`, `LOCK=NONE` | Online secondary index build, a local index per partition                         |
| `message_lifecycle`       | `CREATE TABLE api_idempotency_keys`                                                             | n/a                    | New, empty                                                                        |
| `queue_id_case_sensitive` | `email_messages.mta_queue_id` → `utf8mb4_bin`                                                   | `INPLACE`              | Not indexed, same character set                                                   |
| `queue_id_case_sensitive` | `email_deliveries.outbound_queue_id` + `dsn_queue_id` → `utf8mb4_bin` (one statement)           | `COPY`                 | `outbound_queue_id` is indexed: changing an indexed column's collation copies     |
| `queue_id_case_sensitive` | `delivery_reinjections.queue_id` → `utf8mb4_bin`                                                | `COPY`                 | Indexed (`(queue_id)`)                                                            |
| `queue_id_case_sensitive` | `delivery_status_events.queue_id` → `utf8mb4_bin`                                               | `INPLACE`              | Not indexed                                                                       |

Partitioning is preserved by every statement (`ALTER TABLE … MODIFY` rewrites each partition and keeps the `PARTITION BY` clause): `information_schema.PARTITIONS` listed the same five partitions of each of the five tables before and after on the main schema. The `COPY` statements rebuild the table and block writes for their duration, which is acceptable for the local and pre-production data of this step (ADR-0025); the same kind of change on production data would need online schema-change tooling (design §10).

Counts on the main local schema (2026-11-04): before, `email_messages` 1 `received` (version 0) and 8 `delivery_queued` (version 1), history 8 rows `received → delivery_queued`; after, 1 `persisted` (`lifecycle_backfill`, version 1) and 8 `delivery_pending` (`delivery_planned`, version 1), history 18 rows (9 `NULL → received` version 0, 1 `received → persisted`, 8 `received → delivery_pending`); every message has a version-0 row and `MAX(history.version) = email_messages.version`.
