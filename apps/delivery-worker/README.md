# delivery-worker

Per-recipient delivery of approved mail (step 2.3, [design](../../docs/plan/steps/05-routing.md), [ADR-0021](../../docs/architecture/adr/0021-mail-routing-and-delivery-status.md), operations: [mail-routing.md](../../docs/deployment/mail-routing.md)). The worker plans approved recipients into reinjection groups, hands each group to postfix-outbound (`10026` inbound/internal, `10027` outbound), and turns postfix-outbound's delivery log into per-recipient status. Postfix owns every remote retry (ADR-0006); the worker retries only its own hop. Data plane: the MySQL **writer** only (ADR-0014), Redis (rate limits), S3 (EML stream, never buffered whole), `GET /metrics`, `GET /health/{live,ready}` (mysql, rabbitmq, redis, s3) on port 3040.

## Configuration

`src/config.ts` validates every key it reads (design §5, `.env.example` section "Mail routing and delivery (step 2.3)"): `DELIVERY_*`, `ROUTING_MAX_RECEIVED_HEADERS`, `ROUTING_MAX_GATEWAY_PASSES`, `GATEWAY_TRACE_SECRET` (≥ 32), `GATEWAY_TRACE_ID`, `POSTFIX_OUTBOUND_MYHOSTNAME`, `INGEST_HEADER_MAX_BYTES`, `REDIS_URL`, `S3_*`, `DATABASE_URL`, `RABBITMQ_*`, the base keys and `HTTP_PORT` (3040). Startup refuses `DELIVERY_DEV_PASSTHROUGH_ENABLED=true` unless `APP_ENV` is `local` or `ci`.

## Running on the host

```sh
docker compose --profile smtp-test up -d --wait     # infra + reinject-forwarder (127.0.0.1:2626/2627)
pnpm --filter @email-gateway/smtp-adapter dev        # LMTP ingestion, socketmap and policy for Postfix
pnpm --filter @email-gateway/delivery-worker dev     # reads ../../.env; cwd apps/delivery-worker
```

The local `.env` points the worker at `127.0.0.1:2626/2627` and at `../../.local/postfix-outbound-log/maillog` (relative to `apps/delivery-worker`). Built output: `node --env-file=../../.env dist/main.js` from `apps/delivery-worker`.

## Cursors (operations and stack tests)

| Cursor (`stream_cursors.name`)                                                          | Reset (worker stopped)                                                                                                                                                                                           |
| --------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `postfix-log:<DELIVERY_STATUS_LOG_SOURCE_ID>` (`postfix-log:out.gateway.local` locally) | `DELETE FROM stream_cursors WHERE name = 'postfix-log:out.gateway.local';` → the next start re-reads the current `maillog` from offset 0 (idempotent: no second transition, no second `email_events`/outbox row) |
| `outbox:delivery-worker.planner`                                                        | deleting it restarts at the oldest retained outbox row (already planned approvals are skipped by the `processOnce` ledger)                                                                                       |
| `outbox:delivery-worker.dev-passthrough`                                                | deleting it restarts at `MAX(id)` (never replays old mail)                                                                                                                                                       |

## Tests

- `pnpm --filter @email-gateway/delivery-worker test`: unit tests (`src/**/*.test.ts`).
- `pnpm --filter @email-gateway/delivery-worker run test:integration`: against the real MySQL writer, Redis and MinIO from `.env`, with an in-process fake reinjection listener (`smtp-server`); fixtures in `it-*` organizations, cleaned up afterwards. Claims and reconciler scans are scoped to the fixture organizations.
