# @email-gateway/webhook-worker

The Webhook Service of step 6.2 ([design](../../docs/plan/steps/19-webhooks-notifications.md) W1–W13, N2; ADR-0054, ADR-0055, ADR-0056). HTTP port 3075 serves probes (`/health/live`, `/health/ready`) and `/metrics` only. Deployment: [docs/deployment/webhooks.md](../../docs/deployment/webhooks.md). Runbook: [docs/runbooks/webhooks.md](../../docs/runbooks/webhooks.md).

## Roles (`WEBHOOK_WORKER_ROLES`, default `fanout,delivery`)

| Role       | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Dependencies (readiness)                           |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| `fanout`   | Consumes `email.webhooks` (topology v11, broker user `eg-webhook`, `QueueConsumer`, prefetch `WEBHOOK_FANOUT_PREFETCH`). Projects each of the eight bound internal events into public events by the W3 rules (`src/fanout/projection.ts`), pre-filters them against the per-organization subscription index and the tenant alert settings (cached `WEBHOOK_SUBSCRIPTION_CACHE_SECONDS`), and acks a no-op **without a transaction or ledger row**. Otherwise one writer transaction under the ledger `webhook-worker.fanout` (`processOnce`, `WEBHOOK_FANOUT_TX_TIMEOUT_MS`): echo-checked reads, `buildEnvelope` (payload guard), `webhook_events` and `webhook_deliveries` (insert-ignore), alert windows and `notification.alert_requested.v1` outbox rows.                                                                                                                                                                                     | mysql, rabbitmq (`email.events`, `email.webhooks`) |
| `delivery` | The database-driven loop (`src/delivery`): due organizations (at most 200 per tick through a rotating `organization_id` cursor, shuffled), a short `FOR UPDATE SKIP LOCKED` claim per organization (nothing is sent for an organization that is not `active` or lacks the `webhooks` feature: its due rows are `cancelled`; rows of a paused subscription are parked with `next_attempt_at = NULL`) with Redis in-flight/rate caps and a lease, the send outside any transaction (stored envelope, current + unexpired previous secret, `EG-Signature`, §4.2 headers, `GuardedPoster`), the CAS-recorded attempt, retries (`Retry-After` honored), dead letters, auto-disable with audit and alert, range replays (batches of 500, resumable) and the maintenance (`GET_LOCK('eg:webhook-maintenance')`: cancel pending deliveries of disabled/deleted subscriptions, purge deleted subscriptions, old replays and alert windows, backlog gauges). | mysql, redis                                       |

## Guarantees

- **Tenant isolation**: the organization comes from the source envelope (set by the producer from trusted context); every row read is echo-checked against it; only subscriptions of that organization are ever matched; the envelope carries the organization's **public** id.
- **Metadata only**: public payloads carry public ids, the tenant's own domain names, recipient and sender **domains**, codes, counts and times; never a subject, body, local part, URL from mail, S3 key or secret (`assertWebhookPayloadSafe`; a violation dead-letters the source event with `webhook_payload_unsafe`). A sender-controlled Message-ID that the guard would refuse is dropped (`internetMessageId: null`).
- **At least once, idempotent**: deterministic public event ids, insert-ignore on the unique keys, the fanout ledger, CAS on every attempt record; receivers dedupe on `EG-Event-Id` / `Idempotency-Key`.
- **Outbound HTTP only through the SSRF guard**: every resolved address checked (one blocked answer blocks), the validated IP dialed, the connected address re-checked, TLS ≥ 1.2 with host verification, POST only, no redirects, bounded time and size, https and `WEBHOOK_ALLOWED_PORTS` only; blocked attempts make no connection and fail at once (`blocked:<reason>`).
- **Secrets**: decrypted with `WEBHOOK_SECRET_ENCRYPTION_KEY` (and `_PREVIOUS`), cached ≤ 60 s by `(subscription, secret_version)`, never logged or stored; a decryption failure is the attempt outcome `secret_unavailable` (retried, not counted against the endpoint).
- **Fail closed** without Redis: the loop sends nothing (`webhook_rate_limit_store_errors_total`).
- **Tenant lifecycle**: a suspended, pending-deletion or deleted organization, or one whose `webhooks` plan feature is off, gets no new deliveries (fanout), no attempts (the claimer cancels its due rows with `organization_inactive` / `webhooks_not_enabled`; they can be replayed once the organization is back) and no range replays (`failed` with the same codes).
- **Pause**: the api parks a paused subscription's pending deliveries (`next_attempt_at = NULL`) in the PATCH transaction and makes them due again on resume; the claimer parks any due row of a paused subscription it meets, and the maintenance pass un-parks leftovers of active subscriptions. A paused backlog therefore never hides the organization's other subscriptions and never counts in `webhook_due_backlog` / `webhook_oldest_due_age_seconds`.
- **In-flight slots** are one Redis sorted-set member per reservation (`wh:slots:org:<id>`, `wh:slots:sub:<id>`, score = lease expiry): the slots of a killed process expire after one lease even while the keys stay busy.

`webhook_fanout_events_total{source_type,result}`, `webhook_events_created_total{type}`, `webhook_deliveries_created_total{type,trigger}`, `webhook_delivery_attempts_total{outcome}`, `webhook_delivery_duration_seconds{outcome}`, `webhook_deliveries_dead_total`, `webhook_deliveries_cancelled_total{reason}`, `webhook_subscriptions_disabled_total{reason}`, `webhook_due_backlog`, `webhook_oldest_due_age_seconds`, `webhook_ssrf_blocked_total{reason}`, `webhook_rate_limited_total{scope}`, `webhook_rate_limit_store_errors_total`, `webhook_replays_total{result}`, `webhook_replay_events_skipped_total{reason}`, `webhook_alert_requests_total{kind,result}`, `webhook_inconsistent_reads_total{read}`, `webhook_maintenance_leader`, `webhook_maintenance_last_success_timestamp_seconds`, plus the shared `amqp_*` consumer series. No label carries a tenant, subscription, URL or event id. Alerts: `infrastructure/monitoring/rules/webhooks.rules.yml`.

## Development and tests

```bash
pnpm --filter @email-gateway/webhook-worker dev               # reads ../../.env
pnpm --filter @email-gateway/webhook-worker test              # unit tests (fakes only)
pnpm --filter @email-gateway/webhook-worker test:integration  # real MySQL, Redis, RabbitMQ
```

The integration suite (`integration/webhooks.test.ts`) creates and deletes its own `it-wh-*` organizations, a throwaway vhost with the full topology, runs the fanout as the Nest app and drives the delivery role tick by tick against an in-process HTTPS receiver reached through `WEBHOOK_TEST_DIAL_MAP` (stub DNS: `hooks.receiver.test` → 203.0.113.20). It covers fanout to rows, signatures verified by the receiver, retries with backoff, `Retry-After`, dead letters, single and range replays, auto-disable with audit and alert rows, two-organization isolation, SSRF targets never connected, per-organization fairness and the EXPLAIN of the due and claim queries. The TEST-ONLY Compose receiver is `infrastructure/webhook-receiver/server.mjs` (smtp-test profile).
