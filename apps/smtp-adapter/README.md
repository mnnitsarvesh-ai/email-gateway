# @email-gateway/smtp-adapter

The Node side of the Postfix SMTP gateway (step 2.2, [design](../../docs/plan/steps/04-smtp-gateway.md), operations: [smtp-gateway.md](../../docs/deployment/smtp-gateway.md)): policy service 10040, socketmap 10041, SASL 10042, durable LMTP ingestion 10050 (inbound) / 10051 (outbound), bounce notices 10052, HTTP 3010 (`/health/*`, `/metrics`). Data plane: the MySQL **writer** (ADR-0014), Redis, S3.

## Message lifecycle (step 3.3)

[Design](../../docs/plan/steps/08-message-lifecycle.md) L5.2, L8.1, L9, L15, [ADR-0025](../../docs/architecture/adr/0025-message-lifecycle-state-machine.md). The adapter writes the lifecycle only through `@email-gateway/message-lifecycle` (one-door rule):

- **SMTP commit** (`src/ingestion/ingestion.repository.ts`, edges E1 and E2). `IngestionRepository.commit` builds `initialLifecycle({ messageId, receivedAt, organizationId, causationEventId: <received event id>, correlationId: 'lmtp:<queueId>', service: 'smtp-adapter', at: receivedAt })`, spreads its `messageFields` into `emailMessage.create` (the message is born `persisted`, version 1, round 0, reason `committed`) and writes the two history rows with `writeInitialHistory` (`NULL → received` version 0 `smtp_accepted`, `received → persisted` version 1 `committed`; actor `ingestion` / `smtp-adapter` / `system`, `event_id` = the `mail.message.received.v1` event id, transition keys `ingest:<messageId>:received|persisted`). That is the only change to the hot path: one `createMany` in the same transaction, no lock, no read. No `email_events` row (the `received` row is the timeline entry) and no `mail.message.state_changed.v1` row (`mail.message.received.v1` notifies `persisted`).
- **Bounce notices** (`src/bounces/bounce-notice.service.ts`). Each `bounce_notice` signal goes through the shared recorder of `@email-gateway/mail-routing`, which also derives the message state (L9: e.g. the last recipient bouncing moves `delivery_pending → rejected/delivery_failed`, a delay warning `→ delivery_retry`). The recorder context carries this adapter's `LifecycleMetrics` (`src/shared/lifecycle-metrics.ts`).
- **Case-sensitive queue ids** (L15). The queue-id columns are `utf8mb4_bin`, so `BouncesRepository.findReinjection` and the recorder's queue-id match never confuse two Postfix queue ids that differ only in letter case.

Metrics added (`GET /metrics`, same names and labels in every deployable): `lifecycle_transitions_total{from,to,result}`, `lifecycle_transitions_ignored_total{reason}`, `lifecycle_version_conflicts_total`, `lifecycle_derived_skipped_total{state}` (transitions derived from bounce notices; the commit's creation rows are not counted).

## Account takeover telemetry and enforcement (step 8.4)

[Design](../../docs/plan/steps/24-account-takeover-core.md) D4, D14, D19, [ADR-0073](../../docs/architecture/adr/0073-ato-enforcement-smtp-and-policy-facts.md); operations: [smtp-ato-enforcement.md](../../docs/runbooks/smtp-ato-enforcement.md). Code: `src/ato/` (`AtoModule`: `AtoTelemetryRecorder`, `AtoRestrictionService`).

- **Telemetry (D4).** The SASL server records every AUTH decision (`ok`, `fail`, `throttled`, `blocked`; never `temp`) **after** its reply line is written; the policy service records every message it passed (`DUNNO`) at END-OF-MESSAGE in the `submission` and `relay` contexts after its answer (connector, queue id, client IP, HELO, TLS protocol, lower-cased envelope sender, recipient count, size; null senders are not entries). Both are synchronous pushes into one bounded in-process buffer (`SMTP_ATO_TELEMETRY_BUFFER_MAX`, a full buffer drops the newest entry). A flusher every `SMTP_ATO_TELEMETRY_FLUSH_MS` groups entries by (organization, kind) into batches of at most `SMTP_ATO_TELEMETRY_BATCH_MAX` (≤ 200, the contract bound) and writes one `message_outbox` row per batch in one multi-row insert on the writer (`smtp.auth.recorded.v1` / `smtp.submission.recorded.v1`, aggregate `smtp_telemetry`, `aggregate_id` = organization id, `producer.instance` = host and pid). On a database error the entries stay buffered and are retried until `SMTP_ATO_TELEMETRY_MAX_AGE_MS`, then dropped (`expired`); shutdown flushes once with a 5 s bound. **Loss model:** at most once between the adapter and the outbox (a crash loses at most one flush interval), at least once afterwards; durable ATO facts never depend on it. Usernames that did not resolve to a connector are never kept: they become the first 16 hex characters of HMAC-SHA256(`SMTP_ATO_USERNAME_HASH_KEY`, username) and go into batches of the platform organization (`organizations.kind = 'platform'`; without one those entries are dropped and counted). The adapter never looks up the `ato_detection` feature: the ato-worker drops events of organizations without ATO.
- **Sending restriction (D14).** `PolicyDecisionService.connectorRecipient` (contexts `submission` and `relay`, at RCPT, after the sender checks and before suppression and rate limits) answers `REJECT 5.7.1 Sending temporarily restricted by security policy` (mode `reject`, the default) or `DEFER_IF_PERMIT 4.7.1 Sending temporarily restricted by security policy, try again later` (mode `defer`) when an active `send_block` matches the connector or SHA-256 of the lower-cased envelope sender. Inbound, reinjection and bounce paths are never checked.
- **Authentication block (D14).** `ConnectorAuthService.authenticate` checks an active `auth_block` (scope `connector`, or `connector_ip` with the client IP inside the stored IPv4/IPv6 range) after the connector lookup and **before** the secret is verified: the answer is the same `FAIL` as wrong credentials (after the usual failure delay), the secret is not verified, the per-IP failure counter is not incremented, and telemetry records `blocked` (`failureReason: ato_blocked`).
- **Lookup and cache.** One Redis entry per organization, `sa:ato:r:{organizationId}` (versioned JSON of the active rows, at most 500), loaded from the writer with TTL `SMTP_ATO_RESTRICTION_CACHE_SECONDS`; rows past `expires_at` are ignored at read time. The outbox tail (`DomainCacheInvalidator`, `SMTP_CACHE_INVALIDATION_POLL_MS`) deletes the key on `ato.restriction.changed.v1`. **Fail closed:** a Redis or database error tempfails the recipient (`450 4.3.5`, existing behaviour) and closes the SASL auth connection (`454 4.7.0`).
- **Kill switch.** `SMTP_ATO_ENFORCEMENT_ENABLED=false` stops enforcing every send and auth block without any lookup (an emergency control for a false-positive storm; telemetry continues). See the runbook.

Configuration (`src/config.ts`, `.env.example` SMTP section; Compose and `infrastructure/kubernetes/base/smtp-adapter.yaml` pass them): `SMTP_ATO_TELEMETRY_ENABLED` (true), `SMTP_ATO_TELEMETRY_FLUSH_MS` (1000, 100–10 000), `SMTP_ATO_TELEMETRY_BATCH_MAX` (200, 10–200), `SMTP_ATO_TELEMETRY_BUFFER_MAX` (10 000, 1 000–100 000), `SMTP_ATO_TELEMETRY_MAX_AGE_MS` (60 000), `SMTP_ATO_USERNAME_HASH_KEY` (secret, ≥ 32 characters, required while telemetry is enabled), `SMTP_ATO_RESTRICTION_CACHE_SECONDS` (15, 1–60), `SMTP_ATO_ENFORCEMENT_ENABLED` (true).

Metrics: `smtp_ato_telemetry_total{kind,result}` (`recorded`, `flushed`, `dropped`, `expired`, `error`), `smtp_ato_telemetry_buffer_entries`, `smtp_ato_restriction_lookups_total{result}` (`hit`, `miss`, `error`), `smtp_ato_restrictions_enforced_total{kind,mode}`, `smtp_sasl_auth_total{result="blocked"}`. No tenant, address or IP labels.

## Tests

- `pnpm --filter @email-gateway/smtp-adapter test`: unit tests (`src/**/*.test.ts`), including the commit's statement order and lifecycle fields (`ingestion.repository.test.ts`) and the lifecycle metrics adapter.
- `pnpm --filter @email-gateway/smtp-adapter test:integration`: in-process listeners against the real MySQL writer, Redis and MinIO from `.env` (fixtures in `it-*` organizations, cleaned up afterwards). The ingestion suite asserts a committed message is `persisted`, version 1, round 0, with exactly the two creation history rows and no `state_changed` row. The bounce suite asserts the derived `rejected/delivery_failed` (history, `state_changed` outbox row, metrics) and that notices for queue ids differing only in case (`4jKFxV5fmHz12JnW…` / `4jKFxV5fMHz12Jnw…`) never match each other's delivery. Fixture messages of reinjected mail are inserted `delivery_pending` with matching history rows (L8.6). A vitest globalSetup (`integration/support/live-workers.ts`) pauses a running `event-relay`, `email-worker` and `delivery-worker` (containers, or host processes on their ports) for the duration and resumes them afterwards, so they cannot publish or advance the suites' fresh messages.
- `integration/ato.test.ts` (step 8.4): telemetry batches per organization after the reply (unknown usernames hashed into the platform organization), the END-OF-MESSAGE submission entry, `send_block` per mailbox and connector in both modes with expiry and other tenants unaffected, invalidation through the outbox tail, the kill switch, `auth_block` per connector and per range (right secret refused, no per-IP count, `blocked` telemetry) and fail-closed behaviour. Restriction rows are inserted directly for synthetic organizations, as the ATO store writes them.
