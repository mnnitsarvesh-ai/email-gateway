# @email-gateway/smtp-adapter

The Node side of the Postfix SMTP gateway (step 2.2, [design](../../docs/plan/steps/04-smtp-gateway.md), operations: [smtp-gateway.md](../../docs/deployment/smtp-gateway.md)): policy service 10040, socketmap 10041, SASL 10042, durable LMTP ingestion 10050 (inbound) / 10051 (outbound), bounce notices 10052, HTTP 3010 (`/health/*`, `/metrics`). Data plane: the MySQL **writer** (ADR-0014), Redis, S3.

## Message lifecycle (step 3.3)

[Design](../../docs/plan/steps/08-message-lifecycle.md) L5.2, L8.1, L9, L15, [ADR-0025](../../docs/architecture/adr/0025-message-lifecycle-state-machine.md). The adapter writes the lifecycle only through `@email-gateway/message-lifecycle` (one-door rule):

- **SMTP commit** (`src/ingestion/ingestion.repository.ts`, edges E1 and E2). `IngestionRepository.commit` builds `initialLifecycle({ messageId, receivedAt, organizationId, causationEventId: <received event id>, correlationId: 'lmtp:<queueId>', service: 'smtp-adapter', at: receivedAt })`, spreads its `messageFields` into `emailMessage.create` (the message is born `persisted`, version 1, round 0, reason `committed`) and writes the two history rows with `writeInitialHistory` (`NULL → received` version 0 `smtp_accepted`, `received → persisted` version 1 `committed`; actor `ingestion` / `smtp-adapter` / `system`, `event_id` = the `mail.message.received.v1` event id, transition keys `ingest:<messageId>:received|persisted`). That is the only change to the hot path: one `createMany` in the same transaction, no lock, no read. No `email_events` row (the `received` row is the timeline entry) and no `mail.message.state_changed.v1` row (`mail.message.received.v1` notifies `persisted`).
- **Bounce notices** (`src/bounces/bounce-notice.service.ts`). Each `bounce_notice` signal goes through the shared recorder of `@email-gateway/mail-routing`, which also derives the message state (L9: e.g. the last recipient bouncing moves `delivery_pending → rejected/delivery_failed`, a delay warning `→ delivery_retry`). The recorder context carries this adapter's `LifecycleMetrics` (`src/shared/lifecycle-metrics.ts`).
- **Case-sensitive queue ids** (L15). The queue-id columns are `utf8mb4_bin`, so `BouncesRepository.findReinjection` and the recorder's queue-id match never confuse two Postfix queue ids that differ only in letter case.

Metrics added (`GET /metrics`, same names and labels in every deployable): `lifecycle_transitions_total{from,to,result}`, `lifecycle_transitions_ignored_total{reason}`, `lifecycle_version_conflicts_total`, `lifecycle_derived_skipped_total{state}` (transitions derived from bounce notices; the commit's creation rows are not counted).

## Tests

- `pnpm --filter @email-gateway/smtp-adapter test`: unit tests (`src/**/*.test.ts`), including the commit's statement order and lifecycle fields (`ingestion.repository.test.ts`) and the lifecycle metrics adapter.
- `pnpm --filter @email-gateway/smtp-adapter test:integration`: in-process listeners against the real MySQL writer, Redis and MinIO from `.env` (fixtures in `it-*` organizations, cleaned up afterwards). The ingestion suite asserts a committed message is `persisted`, version 1, round 0, with exactly the two creation history rows and no `state_changed` row. The bounce suite asserts the derived `rejected/delivery_failed` (history, `state_changed` outbox row, metrics) and that notices for queue ids differing only in case (`4jKFxV5fmHz12JnW…` / `4jKFxV5fMHz12Jnw…`) never match each other's delivery. Fixture messages of reinjected mail are inserted `delivery_pending` with matching history rows (L8.6). A vitest globalSetup (`integration/support/live-workers.ts`) pauses a running `event-relay`, `email-worker` and `delivery-worker` (containers, or host processes on their ports) for the duration and resumes them afterwards, so they cannot publish or advance the suites' fresh messages.
