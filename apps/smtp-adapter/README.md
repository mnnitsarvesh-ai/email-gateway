# @email-gateway/smtp-adapter

The Node side of the Postfix SMTP gateway (step 2.2, [design](../../docs/plan/steps/04-smtp-gateway.md), operations: [smtp-gateway.md](../../docs/deployment/smtp-gateway.md)): policy service 10040, socketmap 10041, SASL 10042, durable LMTP ingestion 10050 (inbound) / 10051 (outbound), bounce notices 10052, journal intake LMTP 10053 (step 8.6, only while `JOURNAL_INTAKE_DOMAIN` is set), HTTP 3010 (`/health/*`, `/metrics`). Data plane: the MySQL **writer** (ADR-0014), Redis, S3.

## Message lifecycle (step 3.3)

[Design](../../docs/plan/steps/08-message-lifecycle.md) L5.2, L8.1, L9, L15, [ADR-0025](../../docs/architecture/adr/0025-message-lifecycle-state-machine.md). The adapter writes the lifecycle only through `@email-gateway/message-lifecycle` (one-door rule):

- **SMTP commit** (`src/ingestion/ingestion.repository.ts`, edges E1 and E2). `IngestionRepository.commit` builds `initialLifecycle({ messageId, receivedAt, organizationId, causationEventId: <received event id>, correlationId: 'lmtp:<queueId>', service: 'smtp-adapter', at: receivedAt })`, spreads its `messageFields` into `emailMessage.create` (the message is born `persisted`, version 1, round 0, reason `committed`) and writes the two history rows with `writeInitialHistory` (`NULL → received` version 0 `smtp_accepted`, `received → persisted` version 1 `committed`; actor `ingestion` / `smtp-adapter` / `system`, `event_id` = the `mail.message.received.v1` event id, transition keys `ingest:<messageId>:received|persisted`). That is the only change to the hot path: one `createMany` in the same transaction, no lock, no read. No `email_events` row (the `received` row is the timeline entry) and no `mail.message.state_changed.v1` row (`mail.message.received.v1` notifies `persisted`).
- **Bounce notices** (`src/bounces/bounce-notice.service.ts`). Each `bounce_notice` signal goes through the shared recorder of `@email-gateway/mail-routing`, which also derives the message state (L9: e.g. the last recipient bouncing moves `delivery_pending → rejected/delivery_failed`, a delay warning `→ delivery_retry`). The recorder context carries this adapter's `LifecycleMetrics` (`src/shared/lifecycle-metrics.ts`).
- **Case-sensitive queue ids** (L15). The queue-id columns are `utf8mb4_bin`, so `BouncesRepository.findReinjection` and the recorder's queue-id match never confuse two Postfix queue ids that differ only in letter case.

Metrics added (`GET /metrics`, same names and labels in every deployable): `lifecycle_transitions_total{from,to,result}`, `lifecycle_transitions_ignored_total{reason}`, `lifecycle_version_conflicts_total`, `lifecycle_derived_skipped_total{state}` (transitions derived from bounce notices; the commit's creation rows are not counted).

## Account takeover telemetry and enforcement (step 8.4)

[Design](../../docs/plan/steps/24-account-takeover-core.md) D4, D14, D19, [ADR-0073](../../docs/architecture/adr/0073-ato-enforcement-smtp-and-policy-facts.md); operations: [smtp-ato-enforcement.md](../../docs/runbooks/smtp-ato-enforcement.md). Code: `src/ato/` (`AtoModule`: `AtoTelemetryRecorder`, `AtoRestrictionService`).

- **Telemetry (D4).** The SASL server records every AUTH decision (`ok`, `fail`, `throttled`, `blocked`; never `temp`) **after** its reply line is written; the policy service records every message it passed (`DUNNO`) at END-OF-MESSAGE in the `submission` and `relay` contexts after its answer (connector, queue id, client IP, HELO, TLS protocol, lower-cased envelope sender, recipient count, size; null senders are not entries). Both are synchronous pushes into one bounded in-process buffer (`SMTP_ATO_TELEMETRY_BUFFER_MAX`, a full buffer drops the newest entry). A flusher every `SMTP_ATO_TELEMETRY_FLUSH_MS` groups entries by (organization, kind) into batches of at most `SMTP_ATO_TELEMETRY_BATCH_MAX` (≤ 200, the contract bound) and writes one `message_outbox` row per batch in one multi-row insert on the writer (`smtp.auth.recorded.v1` / `smtp.submission.recorded.v1`, aggregate `smtp_telemetry`, `aggregate_id` = organization id, `producer.instance` = host and pid). On a database error the entries stay buffered and are retried until `SMTP_ATO_TELEMETRY_MAX_AGE_MS`, then dropped (`expired`); shutdown flushes once with a 5 s bound. **Loss model:** at most once between the adapter and the outbox (a crash loses at most one flush interval), at least once afterwards; durable ATO facts never depend on it. Usernames that did not resolve to a connector are never kept: they become the first 16 hex characters of HMAC-SHA256(`SMTP_ATO_USERNAME_HASH_KEY`, username) and go into batches of the platform organization (`organizations.kind = 'platform'`; without one those entries are dropped and counted). The adapter never looks up the `ato_detection` feature: the ato-worker drops events of organizations without ATO.
- **Sending restriction (D14).** `PolicyDecisionService.connectorRecipient` (contexts `submission` and `relay`, at RCPT, after the sender checks and before suppression and rate limits) answers `REJECT 5.7.1 Sending temporarily restricted by security policy` (mode `reject`, the default) or `DEFER_IF_PERMIT 4.7.1 Sending temporarily restricted by security policy, try again later` (mode `defer`) when an active `send_block` matches the connector or SHA-256 of the lower-cased envelope sender. Inbound, reinjection and bounce paths are never checked.
- **Authentication block (D14).** `ConnectorAuthService.authenticate` checks an active `auth_block` (scope `connector`, or `connector_ip` with the client IP inside the stored IPv4/IPv6 range) after the connector lookup and **before** the secret is verified: the answer is the same `FAIL` as wrong credentials (after the usual failure delay), the secret is not verified, the per-IP failure counter is not incremented, and telemetry records `blocked` (`failureReason: ato_blocked`).
- **Lookup and cache.** One Redis entry per organization, `sa:ato:r:{organizationId}` (versioned JSON of the active rows, at most 500), loaded from the writer with TTL `SMTP_ATO_RESTRICTION_CACHE_SECONDS`; rows past `expires_at` are ignored at read time. The outbox tail (`DomainCacheInvalidator`, `SMTP_CACHE_INVALIDATION_POLL_MS`) deletes the key on `ato.restriction.changed.v1`. **Fail closed:** a Redis or database error tempfails the recipient (`450 4.3.5`, existing behaviour) and closes the SASL auth connection (`454 4.7.0`).
- **Kill switch.** `SMTP_ATO_ENFORCEMENT_ENABLED=false` stops enforcing every send and auth block without any lookup (an emergency control for a false-positive storm; telemetry continues). See the runbook.

Configuration (`src/config.ts`, `.env.example` SMTP section; Compose and `infrastructure/kubernetes/base/smtp-adapter.yaml` pass them): `SMTP_ATO_TELEMETRY_ENABLED` (true), `SMTP_ATO_TELEMETRY_FLUSH_MS` (1000, 100–10 000), `SMTP_ATO_TELEMETRY_BATCH_MAX` (200, 10–200), `SMTP_ATO_TELEMETRY_BUFFER_MAX` (10 000, 1 000–100 000), `SMTP_ATO_TELEMETRY_MAX_AGE_MS` (60 000), `SMTP_ATO_USERNAME_HASH_KEY` (secret, ≥ 32 characters, required while telemetry is enabled), `SMTP_ATO_RESTRICTION_CACHE_SECONDS` (15, 1–60), `SMTP_ATO_ENFORCEMENT_ENABLED` (true).

Metrics: `smtp_ato_telemetry_total{kind,result}` (`recorded`, `flushed`, `dropped`, `expired`, `error`), `smtp_ato_telemetry_buffer_entries`, `smtp_ato_restriction_lookups_total{result}` (`hit`, `miss`, `error`), `smtp_ato_restrictions_enforced_total{kind,mode}`, `smtp_sasl_auth_total{result="blocked"}`. No tenant, address or IP labels.

## Provider relay (step 8.2)

[Design](../../docs/plan/steps/25-m365-google-connectors.md) D7, D8, D10, D18; [ADR-0078](../../docs/architecture/adr/0078-provider-relay-tenant-attribution.md), [ADR-0079](../../docs/architecture/adr/0079-connector-validation-probes-and-health.md). Microsoft 365 and Google Workspace outbound and internal mail arrives from shared provider infrastructure on the existing relay listener. Everything lives in `src/provider-relay/**` (`ProviderRelayModule`); the step 2.2 files carry only small hooks and behave exactly as before without a marker.

- **Egress ranges** (`egress-index.service.ts`): the `active` `provider_egress_range_sets` of each provider, loaded from the writer at start and every `PROVIDER_EGRESS_CACHE_SECONDS`, plus `PROVIDER_EGRESS_EXTRA_RANGES` (local/ci only). A failed refresh keeps the last set; before the first load, provider decisions tempfail.
- **Resolution at RCPT** (`provider-relay-resolver.service.ts`, `provider-relay-policy.service.ts`): after certificate and source-IP connectors, a client in a provider's ranges with a non-empty sender whose active, outbound-enabled domain is linked to an `active` connection of that provider (outbound `probe_only`, `active` or `suspended`) with an active `provider_relay` connector. TLS is always required; `probe_only` answers `451 4.7.1 … not active yet …` for non-probe recipients, `suspended` `451 4.7.1 … suspended`; null senders from provider ranges get `550 5.7.1 Null-sender mail is not accepted on the provider relay`; probe addresses (`eg-probe-<token>@PROVIDER_PROBE_DOMAIN`) are refused in every other context. Cached 30 s under `sa:prelay:conn:{provider}:{domain}`. A client in a provider's ranges is shared infrastructure (one certificate and address pool for every customer): a certificate or legacy source-IP connector matched there serves only senders of its own organization; every other sender from those ranges is resolved by the provider relay, so no organization can capture another one's provider traffic by registering the provider's certificate fingerprint.
- **Marker** (`relay-marker.store.ts`): END-OF-MESSAGE writes `sa:prelay:{queueId}` (v1) before `DUNNO`, with TTL `PROVIDER_RELAY_MARKER_TTL_SECONDS` but never less than Postfix's `maximal_queue_lifetime` (5 d), so a queue file whose first LMTP delivery is late (smtp-adapter down or backlogged) or whose recipients are delivered in several batches still finds it; markers are not deleted after ingestion (Redis runs with `noeviction`). A Redis error answers `DEFER_IF_PERMIT 4.3.5`. A provider-egress client that no longer resolves to any connector at END-OF-MESSAGE (connection, connector or link changed after RCPT) gets `DEFER_IF_PERMIT 4.7.1 Provider relay authorization changed, try again later` (`smtp_provider_relay_total{result="state_changed"}`), never a marker-less relay.
- **Proof at LMTP ingestion** (`provider-relay-ingestion.service.ts`, `proof-verifier.ts`): every outbound transaction reads the marker (Redis error → `451`). With a marker the bytes are teed into `mailauth` DKIM verification (keys through `PROVIDER_RELAY_DNS_SERVERS`), then `evaluateProviderProof` of `@email-gateway/mail-routing` decides before anything is committed: `pass` → normal ingestion with `details.providerRelay` on the `received` event; `fail` → `550 5.7.26 Sender not authenticated by the linked provider tenant` for every recipient and the upload discarded; `temperror` → `451 4.3.0` (the marker is kept for 5 days so a late retry is never ingested without proof). Google signatures are counted per queue file in `sa:prelay:dkim:{sha256(b=)}`.
- **Probes** (`probe-recorder.repository.ts`): probe recipients are intercepted: one `provider_probe_observations` row per (token, queue id), linked to the validation run awaiting that token; nothing goes to S3 or `email_messages`.
- **Counters** (`relay-counters.service.ts`): hourly `provider_relay_counters` upserts every `PROVIDER_RELAY_COUNTER_FLUSH_SECONDS` and `provider_connections.last_relay_accepted_at`.

Metrics: `smtp_provider_relay_total{provider,result}`, `smtp_provider_proof_total{provider,rule,result}`, `smtp_provider_probe_observations_total{provider,result}`, `smtp_provider_egress_ranges{provider}`, `smtp_provider_egress_load_errors_total`, `smtp_provider_relay_counter_flush_errors_total`, `smtp_provider_relay_marker_errors_total{operation}`.

## Journal-only intake (step 8.6)

[Design](../../docs/plan/steps/27-journal-intake-and-archive-split.md) D1–D3, D9; [ADR-0087](../../docs/architecture/adr/0087-journal-intake-path.md); operations: [journal-intake.md](../../docs/runbooks/journal-intake.md), [smtp-gateway.md](../../docs/deployment/smtp-gateway.md#journal-intake-step-86). Customers that only journal send Microsoft 365 / on-premises Exchange journal reports, Google Workspace "Also deliver to" copies or `always_bcc` copies to a per-source address `journal-<26 base32>@JOURNAL_INTAKE_DOMAIN`. Everything lives in `src/journal-intake/**` (`JournalIntakeModule`, imported only while `JOURNAL_INTAKE_ENABLED` and `JOURNAL_INTAKE_DOMAIN` are set); the step 2.2 files carry small optional hooks.

- **Never a tenant domain.** `DomainPolicyService.get` answers `null` for the intake domain and its subdomains (policy, socketmap `relay_domain` / `transport`), whatever the database holds. Postfix lists the intake domain itself in `relay_domains` and routes it with `transport_maps` to `:10053`.
- **RCPT policy** (`journal-intake-policy.service.ts`, `admission.ts`, `policy_context=inbound`, recipient domain = the intake domain): (1) local part `journal-<token>` → `sha256` = `address_hash` (or an unexpired `previous_address_hash`), source not `disabled` — else `550 5.1.1`; (2) organization `active`, effective feature `journal_intake` (the organization row, else the plan's `default_features`) and either effective `archiving` with archive settings enabled (8.6) or **API mode active** (step API-1 D6: effective `api_mode_protection` and at least one non-deleted domain whose `COALESCE(domains.protection_mode, organizations.protection_mode)` is `api`/`hybrid`; the snapshot's `organization.apiDetect`), source not `paused` — else `450 4.7.1 Journal intake temporarily unavailable`; (3) provider kinds: the bound (`active_tenant_key` + `external_tenant_id`), non-disabled connection of the same organization and provider and the client in that provider's egress set; on-premises kinds: the client in the source's `intake-networks/1` and in **no** provider egress set; the client certificate (`ccert_fingerprint` / `ccert_pubkey_fingerprint`) when fingerprints are configured — else `550 5.7.1 Journal intake sender not authorized`; an egress index not loaded yet tempfails; (4) `require_tls` without TLS → `MUST_STARTTLS`; (5) one destination kind per transaction: `sa:jintake:inst:<instance>` (Lua claim, 1 h) holds `src:<sourceId>` or `tenant` (tenant recipients record it too while intake is on) → `452 4.5.3 Error: too many recipients` on mixing, both orders; (6) `FixedWindowLimiter` scopes `jintake_src` (`JOURNAL_INTAKE_RATE_PER_SOURCE_PER_MINUTE`) and `jintake_org` (plan `journal_intake_messages_per_minute`; missing = 0) → `RATE_LIMITED`; (7) declared size above `min(source, plan journal_intake_max_message_bytes, JOURNAL_INTAKE_MAX_MESSAGE_BYTES)` → `TOO_BIG_FOR_RECIPIENT`, else the limit goes to `InstanceSizeStore` for END-OF-MESSAGE; (8) `DUNNO`. Sources are read through `sa:jintake:src:<addressHash>` (`JOURNAL_INTAKE_SOURCE_CACHE_SECONDS`, negative entries too).
- **END-OF-MESSAGE marker** (`intake-state.store.ts`): an intake transaction writes `sa:jintake:q:<queueId>` (v1: source id, TLS flag and protocol, presented certificate fingerprints, client address; TTL 5 days like the 8.2 relay marker) before `DUNNO`; a Redis error tempfails. XFORWARD carries no TLS facts, so the LMTP re-check needs it.
- **Journal LMTP** (`journal-intake.service.ts`, `journal-intake.listener.ts`, health `lmtp-journal`): answers only `250` or `451`. RCPT: one intake recipient per transaction; the source is re-read on the writer and admitted again with the XFORWARD address and the marker's TLS / certificate facts (any failure, or no marker, `451`). DATA, streaming: raw bytes → `JournalReportSplitter` (report kinds; WP2) → `HeaderFieldStripper(['X-EG-Journal-Token'])` → SHA-256, header scan and the S3 upload `org/<org>/eml/<yyyy>/<mm>/<dd>/<objectRef>.eml` (`objectRef` over `{mtaId}|{queueId}|journal|{org}`); the raw bytes are teed into the 8.2 DKIM verifier for Microsoft 365 (evidence only). Proof (`evaluateIntakeProof` of `@email-gateway/mail-routing`, outer headers): `fail` → the upload is aborted, nothing stored, `250 2.0.0 Ok: dropped`, counter `dropped_proof`, `last_refusal_code = proof_<rule>`; `temperror` → `451`; `pass` → envelope (`parseJournalEnvelope`, or `buildCopyEnvelope` for copies and unparsed reports; intake-domain addresses removed; capped at `JOURNAL_INTAKE_MAX_RECIPIENTS`, `truncated`), parties (`classifyIntakeParties`, `domain_id` = the org-side party's domain, else the lowest-id verified domain), duplicate pre-check, then `JournalIntakeRepository.commit`.
- **Commit** (`journal-intake.repository.ts`, one writer transaction): `message_identities` (ingest key `v2:` over `{mtaId}|{queueId}|journal|{sha256 of the received bytes}|{intake address}`), `email_messages` (`ingest_source = journal_intake`, born `persisted` with history E1/E2, header metadata and size/SHA-256 of the **stored** message), `email_recipients` (status `journaled`, direction nullable), `journal_intake_messages` (envelope, proof, format, report SHA-256/size, `scan_requested` = `archive-settings/1` `intake.scanEnabled` read in the transaction **or** API mode active in the LMTP's writer snapshot (detect-mode scanning, step API-1 D6)), the `received` event with `details.intake = { sourceId, kind, format }` (public id, codes) and `mail.message.received.v1` with `ingestSource: 'journal_intake'` (`recipientCount` at least 1). A committed ingest key (redelivery) is `250`.
- **Counters** (`journal-intake-counters.service.ts`): Redis hashes `sa:jintake:cnt:<sourceId>:<yyyymmdd>` (TTL 3 days, dirty set `sa:jintake:cnt:dirty`), one Lua script per event (never awaited by a reply). Every `JOURNAL_INTAKE_COUNTER_FLUSH_SECONDS` each hash is taken atomically and added to `journal_intake_counters` (`INSERT … SELECT` from the source row, so the organization comes from the source) and the source's `last_accepted_at` / `last_refused_at` / `last_refusal_code`; the first accepted message sets `verified_at` and moves `pending_verification` → `active` (bumping `row_version`). Failed writes put the counts back (dropped after 3 failures). Refusals before a source matched (unknown address) count only in metrics.

Metrics (no organization or source labels): `journal_intake_messages_total{kind,outcome}` (`accepted`, `duplicate`, `dropped`, `tempfail`), `journal_intake_bytes_total{kind}`, `journal_intake_refusals_total{stage,code}` (stages `rcpt`, `eom`, `lmtp`), `journal_intake_unwrap_total{format,result}`, `journal_intake_lmtp_seconds{kind}`, `journal_intake_proof_total{kind,rule,result}`, `journal_intake_counter_flush_errors_total`. Alerts: `infrastructure/monitoring/rules/journal-intake.rules.yml`. Logs carry the source public id, codes and sizes only, never addresses, tokens or subjects.

TEST-ONLY fixture builders (synthetic M365 / on-premises reports, Google copies, BCC copies, intake credentials from a random secret, snapshots and egress ranges) are in `src/journal-intake/testing/` (excluded from the build).

## Tests

- `pnpm --filter @email-gateway/smtp-adapter test`: unit tests (`src/**/*.test.ts`), including the commit's statement order and lifecycle fields (`ingestion.repository.test.ts`) and the lifecycle metrics adapter.
- `pnpm --filter @email-gateway/smtp-adapter test:integration`: in-process listeners against the real MySQL writer, Redis and MinIO from `.env` (fixtures in `it-*` organizations, cleaned up afterwards). The ingestion suite asserts a committed message is `persisted`, version 1, round 0, with exactly the two creation history rows and no `state_changed` row. The bounce suite asserts the derived `rejected/delivery_failed` (history, `state_changed` outbox row, metrics) and that notices for queue ids differing only in case (`4jKFxV5fmHz12JnW…` / `4jKFxV5fMHz12Jnw…`) never match each other's delivery. Fixture messages of reinjected mail are inserted `delivery_pending` with matching history rows (L8.6). A vitest globalSetup (`integration/support/live-workers.ts`) pauses a running `event-relay`, `email-worker` and `delivery-worker` (containers, or host processes on their ports) for the duration and resumes them afterwards, so they cannot publish or advance the suites' fresh messages.
- `integration/ato.test.ts` (step 8.4): telemetry batches per organization after the reply (unknown usernames hashed into the platform organization), the END-OF-MESSAGE submission entry, `send_block` per mailbox and connector in both modes with expiry and other tenants unaffected, invalidation through the outbox tail, the kill switch, `auth_block` per connector and per range (right secret refused, no per-IP count, `blocked` telemetry) and fail-closed behaviour. Restriction rows are inserted directly for synthetic organizations, as the ATO store writes them.
- `integration/provider-relay.test.ts` (step 8.2): policy → marker → LMTP ingestion with DKIM keys generated at runtime, published by the in-process DNS stub `integration/provider-relay-support/dns-stub.ts` (never the Internet); the EML store is an in-memory double. Microsoft 365 pass, forged tenant header and unsigned `550 5.7.26`, DNS failure `451` with the marker kept, null sender and relay denials, `probe_only`, probe interception (evidence row, idempotent, nothing stored), the Google replay limit (sixth use refused) and the hourly counters.
- `integration/journal-intake.test.ts` (step 8.6): policy → END-OF-MESSAGE marker → journal LMTP → MinIO and the writer for synthetic `it-jrnl-*` organizations: a Microsoft 365 report (base64 embedded message) committed with the BCC recipient, `journaled` recipients, `journal_intake_messages`, history, event and outbox; redelivery of the same queue file as a duplicate; a wrong tenant header dropped with nothing stored; in-session refusals (non-egress client, plaintext, unknown address, mixed transactions in both orders); `451` without a marker; a Google copy whose token never reaches the stored object; an on-premises report from its networks and refused from a provider range; the counter flush (counts, `verified_at`, `pending_verification` → `active`).
