# @email-gateway/security-contracts

The contracts of the security scan pipeline (step 4.1 S4, S6–S9, [design](../../docs/plan/steps/09-rspamd.md), [ADR-0026](../../docs/architecture/adr/0026-security-scan-pipeline.md), which supersedes ADR-0007's engine contract; [contracts §7](../../docs/architecture/contracts.md#7-security-engine-contract)): standardized verdicts and reason codes, the engine catalog, normalized engine and authentication results, and the Rspamd platform and tenant settings with their pure resolver. Used by the email-worker scan role (mapping, aggregation, settings at use) and by the api (scans read API, settings API). Engines classify, policy decides: nothing here rejects, quarantines or delivers. The adapter interface lives with the adapters (`apps/email-worker/src/scanning/engine.ts`). Dependencies: `zod` and `@email-gateway/shared-types`; no I/O.

| Module            | Design | Exports                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ----------------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/verdicts.ts` | S7     | `SCAN_VERDICTS` (`clean`, `spam`, `suspicious`, `malicious`, `unknown`, `timeout`, `error`), `ENGINE_OUTCOMES` (adds `skipped`), `DEFINITE_VERDICTS`, `FAILURE_OUTCOMES`, `VERDICT_SEVERITY` (`clean < unknown < suspicious < spam < malicious`), `isDefiniteVerdict`, `isFailureOutcome`, `mostSevere()` (returns `null` when no definite verdict exists, so every caller states its own fallback and nothing invents `clean`), `REASON_CODE_PATTERN`, `reasonCodeSchema`, `reasonCodesSchema` (≤ 32, unique)                                                                                                              |
| `src/engines.ts`  | S4     | `SECURITY_STAGES`, `ENGINE_NAMES`, `ENGINE_NAME_PATTERN`, `ENGINE_CATALOG` (data; step 4.1: `rspamd`, stage `antispam`, queue `scan.spam`, required by default, not disableable by a tenant), `engineCatalogEntry`, `parseEnabledEngines(SCAN_ENGINES)` (refuses an empty list, duplicates and unregistered names), `requiredEngines(enabled, tenantDisabled)` (the snapshot in `email_scans.required_engines`, catalog order)                                                                                                                                                                                              |
| `src/results.ts`  | S6, S9 | `AUTH_OUTCOMES`, `DMARC_POLICIES`, `authResultsSchema` (SPF, DKIM with ≤ 10 signatures, DMARC with policy, ARC), `engineSignalSchema` (≤ 5 options of ≤ 200 characters), `normalizedEngineResultSchema` (strict; `outcome` admits only the five definite verdicts: failures are attempts, never results; ≤ 200 signals)                                                                                                                                                                                                                                                                                                     |
| `src/settings.ts` | S8     | `rspamdPlatformSettingsSchema`, `RSPAMD_PLATFORM_DEFAULTS`, `RSPAMD_PLATFORM_ENV_KEYS` + `rspamdPlatformSettingsFromEnv(env)` (the `SCAN_RSPAMD_*` keys, read identically by the api and the email-worker), `rspamdTenantSettingsSchema` (strict), `rspamdSettingsBounds(platform)` (the `bounds` of the settings API), `resolveRspamdSettings(platform, override)` (scores inside the bounds and ordered, at most two decimals, severities only raised; violations `invalid`, `unknown_key`, `out_of_bounds`, `threshold_order`, `severity_lowered`), `settingsVersion()` = `<mapping>;p=<12 hex>;t=<row version \| none>` |

`mail.message.scanned.v1` itself is defined in `@email-gateway/event-contracts` (which does not depend on this package); the email-worker tests that its verdict lists equal `SCAN_VERDICTS` / `ENGINE_OUTCOMES`.

## Tests

- `pnpm --filter @email-gateway/security-contracts test`: unit tests of the verdict order and `mostSevere`, reason-code limits, the catalog and `parseEnabledEngines` / `requiredEngines`, the result schemas, and the settings resolver (bounds, order, lowered severities, unknown keys, version format).
