# @email-gateway/security-contracts

The contracts of the security scan pipeline (step 4.1 S4, S6–S9, [design](../../docs/plan/steps/09-rspamd.md), [ADR-0026](../../docs/architecture/adr/0026-security-scan-pipeline.md), which supersedes ADR-0007's engine contract; step 4.2 §4, [design](../../docs/plan/steps/10-attachment-scanning.md), [ADR-0028](../../docs/architecture/adr/0028-attachment-scanning-engine.md); [contracts §7](../../docs/architecture/contracts.md#7-security-engine-contract)): standardized verdicts and reason codes, the engine catalog, normalized engine and authentication results, the Rspamd platform and tenant settings with their pure resolver, and the attachment engine's file-type vocabulary, verdicts, reason codes, settings and per-attachment result. Used by the email-worker scan role (mapping, aggregation, settings at use) and by the api (scans read API, settings API). Engines classify, policy decides: nothing here rejects, quarantines or delivers. The adapter interface lives with the adapters (`apps/email-worker/src/scanning/engine.ts`). Dependencies: `zod` and `@email-gateway/shared-types`; no I/O.

## Tests

- `pnpm --filter @email-gateway/security-contracts test`: unit tests of the verdict order and `mostSevere`, reason-code limits, the catalog and `parseEnabledEngines` / `requiredEngines`, the result schemas, and the settings resolver (bounds, order, lowered severities, unknown keys, version format); step 4.2: the file-type vocabulary (every A5 id, unique extensions and MIME types, lookups), the attachment reason codes (every A6 code, pattern), the attachment platform settings (defaults, env, refusals), `resolveAttachmentSettings` (add-only deny list, allow list without denied types, raise-only verdicts, tighten-only size, unknown keys) and `attachmentResultSchema` (strictness, no filename or entry names, the clean rule, list bounds).
