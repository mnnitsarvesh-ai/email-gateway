# @email-gateway/message-lifecycle

The message lifecycle of step 3.3 ([design](../../docs/plan/steps/08-message-lifecycle.md), [ADR-0025](../../docs/architecture/adr/0025-message-lifecycle-state-machine.md), [runbook](../../docs/runbooks/message-lifecycle.md)): the fifteen states, the transition table as data, the pure ordering rule, the derived delivery state, and the transition service that is the **only** writer of `email_messages.status`, `status_changed_at`, `version`, `lifecycle_round`, `status_reason` and `email_message_status_history` (one-door rule, enforced by `src/one-door.test.ts`). Writer only (ADR-0014).

| Module               | Design | Exports                                                                                                                                                                                                                                                                           |
| -------------------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/states.ts`      | L2     | `MESSAGE_STATES`, `MessageState`, `ACTOR_ROLES`, `ActorRole` (defined once in `@email-gateway/event-contracts`), `STATE_RANK`, `FINAL_STATES`, `EXPIRABLE_STATES`, `isMessageState`, `isActorRole`                                                                                |
| `src/transitions.ts` | L3     | `TRANSITIONS` (edges E1–E27; step 4.1 adds E27 and retires E4; step 4.2 A13 gives E19 the roles `operator`, `scanner` and the reasons `admin_rescan`, `signature_rescan`, paired by `reasonRoles`), `TransitionEdge`, `LIFECYCLE_REASON_CODES`, `LifecycleReasonCode`, `findEdge` |
| `src/decide.ts`      | L4     | `decideTransition(current, request, table?)` → `apply` / `duplicate` / `stale` / `invalid` (a reason the edge's `reasonRoles` reserves for another role → `invalid/reason_not_allowed`: E19 `scanner` only with `signature_rescan`, `operator` only with `admin_rescan`)          |
| `src/derive.ts`      | L9     | `deriveDeliveryState(counts)`                                                                                                                                                                                                                                                     |
| `src/initial.ts`     | L5.2   | `initialLifecycle(input)` (SMTP commit: `messageFields` + two history rows), `writeInitialHistory(tx, init)`                                                                                                                                                                      |
| `src/service.ts`     | L5, L9 | `lockLifecycle(tx, message)`, `transitionMessage(tx, request, deps?)`, `transitionMessageWithRetry(prisma, request, { timeoutMs, maxAttempts? }, deps?)`, `applyDerivedDeliveryState(tx, message, ctx, deps?)`, `retryDelayMs`                                                    |
| `src/keys.ts`        | L5.3   | `transitionKeyHash(key)` (SHA-256 hex; 1–512 characters)                                                                                                                                                                                                                          |
| `src/errors.ts`      | L5.7   | `LifecycleVersionConflictError`, `LifecycleContractError`, `isRetryableLifecycleError`, `isTransitionKeyViolation`                                                                                                                                                                |
| `src/metrics.ts`     | L5.5   | `LifecycleMetrics` (`transition`, `ignored`, `versionConflict`, `derivedSkipped`), `noopLifecycleMetrics`                                                                                                                                                                         |
| `src/events.ts`      | L7     | `toStateChangedPayload` (`mail.message.state_changed.v1`)                                                                                                                                                                                                                         |

`transitionMessage` runs inside the caller's writer transaction: `SELECT … FOR UPDATE` on the message (tenant must match, else `not_found`), the transition-key check, `decideTransition`, a compare-and-set `UPDATE … WHERE version = ?`, the history row, an `email_events` `lifecycle.<to>` row and the `mail.message.state_changed.v1` outbox row; stale/invalid requests write one `lifecycle.ignored` event unless `recordIgnored: false`. It never retries inside a caller's transaction; `transitionMessageWithRetry` opens its own and retries deadlocks, lock waits, `P2034`, CAS conflicts and a P2002 on the transition key (equal jitter 20–500 ms, default 5 attempts).

## Tests

- Unit (`pnpm --filter @email-gateway/message-lifecycle test`): exhaustive decision over (creation + 15) × 15 × roles, wrong reasons, table invariants (the L3 table verbatim, reachability, final states), ordering tables and `fast-check` properties (shuffled and duplicated scripts with a rescan and a release round), every recipient-count combination 0..2, the creation rows, request validation and retry classification, the Prisma enum equality, the one-door scan.
- Integration (`pnpm --filter @email-gateway/message-lifecycle test:integration`, real MySQL writer from `.env`, it-ml-\* organizations, every row removed afterwards): the applied row set, ignored rows, tenant mismatch, derived states; concurrency (64 parallel writers with distinct and with equal keys, a 16-worker chain race, two CAS transactions with the same version, 200 messages × 8 writers); recovery (crash inside `processOnceHandler`, writer cut through a TCP proxy after the row lock, P2002 on the transition key in a REPEATABLE READ caller).
