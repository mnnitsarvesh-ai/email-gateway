# @email-gateway/ato-detection

The account takeover (ATO) detection core of step 8.4 ([design](../../docs/plan/steps/24-account-takeover-core.md) §4.4, D7–D15; [ADR-0070](../../docs/architecture/adr/0070-ato-account-and-event-model.md) … [ADR-0075](../../docs/architecture/adr/0075-security-incident-model-shared-ato-atp.md)): rules, correlation, scoring, baselines, explanations, responses and their safeguards, short-term windows in Redis, the transactional store of the ATO tables, GeoIP enrichment and the identity-provider port. Used by the `ato-worker` (detection, responses, maintenance, provider polling) and by the api (`/ato`, `/incidents`) so both write identical rows. Deterministic integer arithmetic, no learned model; no message content, password, token or recipient address is ever stored.

Two entry points: `@email-gateway/ato-detection` (runtime) and `@email-gateway/ato-detection/testing` (test kit, loads only under Vitest). Runtime code never imports the test kit or Vitest (`src/boundary.test.ts`). Runtime code is pure TypeScript except `windows/` (a minimal Redis interface), `store/` (a Prisma transaction client) and `geoip/` (files).

## GeoIP

Production reads operator-provided MaxMind databases (City, ASN, optional Anonymous IP) with the official reader `@maxmind/geoip2-node` (Apache-2.0); `maxmind` (MIT, its own dependency) is used only to read a file's metadata (database type, build epoch) before the reader is swapped in. Nothing is downloaded and no database ships with the package. Without the City database every geographic rule is `unavailable`; locations are never guessed.

`test-fixtures/geoip/synthetic-{city,asn,anonymous}.mmdb` are synthetic databases over documentation ranges only (RFC 5737, RFC 3849, RFC 5398 ASNs), generated from `synthetic-geoip.json`:

```sh
pnpm --filter @email-gateway/ato-detection geoip:synthetic
```

The output is byte-identical on every run (asserted by `src/geoip.test.ts`, which also reads the files with the production reader).

## Tests

- Unit (`pnpm --filter @email-gateway/ato-detection test`, no I/O except fixtures): every rule (fires, boundary, dedupe, learning and immature behaviour, capability unavailable), correlation X1–X5, scoring (decay table, groups, caps, gates, overrides, bands, determinism, every worked example of D11), baselines, settings schema and bounds, explanations for every code and the evidence guard, the incident handler, the response state machine, recommendations and every automation guard, windows over `InMemoryRedis`, geo math, IP classification, devices, keys, the synthetic MMDB generator, the provider contract kit against the fake adapter, the runtime/test-kit boundary.
- Integration (`pnpm --filter @email-gateway/ato-detection test:integration`, real MySQL writer and Redis from `.env`, synthetic `it-ato-*` organizations created and removed by the suites): the store (settings, accounts, auth events, activity, signals, scoring and incidents, responses and approvals, restrictions, provider actions, overrides, false positives, manual incidents, trusted contexts, protection, automation guards, sweeps, notifications) and the Lua window scripts (parity with the in-memory model, TTL on every key, no tenant identifier in platform IP keys).
