# @email-gateway/quarantine

The pure rules of the quarantine store of step 5.3 ([design](../../docs/plan/steps/17-quarantine.md) Q1, Q3, Q6, Q9, Q10, Q12–Q20, Q24, Q26; [ADR-0046](../../docs/architecture/adr/0046-quarantine-store-and-per-recipient-decisions.md), [ADR-0047](../../docs/architecture/adr/0047-quarantine-release-revalidation-and-approvals.md), [ADR-0048](../../docs/architecture/adr/0048-quarantine-preview-and-download-controls.md)). The policy-engine (entry writer, release executor, sweeper, digest scheduler), the api (routes, release pre-check, approvals, downloads) and the notification-worker call the same functions, so a rule is decided once.

## Invariants

- **Pure.** No Prisma, S3, network, clock, randomness or logger: `now`, keys and every fact are parameters; enums are string unions mirroring the Prisma enums of the 5.3 migration (pinned by tests).
- **The state machine is data.** `ENTRY_TRANSITIONS` is the Q3 table; anything else is `409 quarantine_state_conflict`. Expiry never releases.
- **No release weakens the floor without a second person.** `decideRelease` turns floor reasons, a current REJECT, review entries and stale verdicts into approval reasons; `checkApprover` refuses the requester, the recipient, API keys and principals without `quarantine:approve`; `release.allowHardBlocks = false` refuses hard blocks in every mode.
- **Fail-safe retention.** `decideObjectDisposal` treats legal-hold criteria it cannot parse as matching everything and keeps shared or archive-pending objects.
- **Downloads prove what was granted.** `qdl1` tokens are HMAC-SHA256 with domain separation, verified in constant time before the payload is parsed, bound to organization, user, entry, object and part, with an injected clock; single use is the api's atomic grant consume.

The cron evaluator accepts exactly the grammar of the api's organization settings validator (a unit test compares both on a corpus and 20 000 random expressions) and resolves wall-clock times like `Temporal`'s `compatible` disambiguation (a time in a spring-forward gap fires after the gap; a repeated time fires once).

## Tests

`pnpm --filter @email-gateway/quarantine test` (no infrastructure): every allowed and refused transition; the reason and engine tables on real `policy-dsl` evaluations; settings defaults, bounds, fallback and the platform-bound validation; expiry clamps; approval reasons for every floor reason; staleness; `decideRelease` for every mode × reasons × staleness × message state × `allowHardBlocks`, approved-reason subsets and new reasons after an approval; separation of duties; self-service; disposal (legal hold match/no match/unparseable, retention, archive pending, shared object); bulk limits; token tamper, wrong key, expiry and binding; malware gating; cron grammar, time zones, DST gaps and overlaps, coalescing and the per-day cap; DTO schemas; search cursors.
