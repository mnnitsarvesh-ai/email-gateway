# @email-gateway/dlp

Data loss prevention library of step 4.5 ([design](../../docs/plan/steps/13-dlp.md),
[ADR-0036](../../docs/architecture/adr/0036-dlp-engine-and-extraction.md),
[ADR-0037](../../docs/architecture/adr/0037-dlp-policy-actions-and-lifecycle-binding.md),
[ADR-0038](../../docs/architecture/adr/0038-dlp-evidence-masking-and-aadhaar-gating.md)). CommonJS,
no Nest, no Prisma, no I/O except the packaged `data/` files: the email-worker's `dlp` engine and
the api load and echo-check every row, read the S3 parts and pass plain inputs in. The shared lists
(detector ids and codes, categories, actions, coverage codes, …) are imported from
`@email-gateway/security-contracts`, never duplicated.

| Module          | Contents                                                                                                                                                                                                                                                                                                                                     |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `validators/`   | Luhn, Verhoeff, ISO 13616 length table + mod 97 (bec `ibanChecksumValid`), GSTIN mod-36, MRZ 7-3-1, IIN brands (`data/iin-ranges.json`), IFSC, ISO 3166 (`data/iso3166.txt`), packaged test cards (`data/test-cards.txt`, 59), trivial-run exclusion.                                                                                        |
| `detectors/`    | The built-in detectors of `dlp-map/1` (D5): linear digit-run and token scanners, anchored checks on single tokens ≤ 128 code units only; PEM/GCP keys, MRZ, dates, source code, currency amounts.                                                                                                                                            |
| `context/`      | The DLP phrase trie on the bec normalization (`normalizeForMatching` + `wordTokens`) and the D7 scoring (window, table columns, bulk, code penalty, negatives, disclaimers, clamping, thresholds).                                                                                                                                           |
| `dictionaries/` | Built-in dictionaries (`data/dictionaries/{labels,business,financial,context,negative}.json`, en / hi / hi-Latn, SHA-256 versioned) and tenant dictionaries compiled into one trie per organization snapshot (D8).                                                                                                                           |
| `custom/`       | `compileCustomPattern` (D9 steps 1–7 on `re2js` 2.9.0, probe corpus `data/probe-corpus.txt` generated by `scripts/probe-corpus.ts`), `loadTenantPatterns`, `findPatternMatches`, `testCustomPattern` (api test endpoint).                                                                                                                    |
| `classify/`     | Findings (distinct values, ≤ 5 sources, ≤ 3 masked samples, match cap), category aggregates, coverage composition, verdict (D10), reason codes.                                                                                                                                                                                              |
| `policy/`       | `evaluateDlpPolicy` (D11, D12; pure, deterministic, default policy `dlp-default/1`, monitor mode, exceptions, truncated recipient lists) and `dlpPolicyVersion` (`pol/1;h=<12 hex>`).                                                                                                                                                        |
| `mask/`         | D15 masks.                                                                                                                                                                                                                                                                                                                                   |
| `evidence/`     | `buildEvidence` (D16 bounds and context redaction) and the `dlp-evidence/1` envelope `sealEvidence` / `openEvidence` (AES-256-GCM data key wrapped under `DLP_EVIDENCE_KEY`, SecretBox format).                                                                                                                                              |
| `extract/`      | Attachment text extraction (D4), also exposed as `@email-gateway/dlp/extract` (root `extract.js` / `extract.d.ts`): `ExtractionSession` (the shared walker's entry visitor + `finish`), text decoding, CSV/TSV tables, XML tokenizer (no DTD), OOXML/ODF parts, pdfjs-dist 4.10.38. Imports no bec, url-security, AI SDK or `child_process`. |
| `detect.ts`     | `detect()`: the whole text pipeline over segments (chunks of `DLP_SCAN_CHUNK_CHARS` with a 512 overlap, yields, `Deadline`, HTML through bec `htmlToText`).                                                                                                                                                                                  |
| `versions.ts`   | `dlpEngineVersion()` (`dlp/1;dict=<8hex>;data=<8hex>;ext=dlp-extract/1`), `DLP_EXTRACTOR_VERSION`, `DLP_TEXT_DERIVATION_VERSION`.                                                                                                                                                                                                            |
| `corpus/`       | Synthetic fixture builders (seeded PRNG + manifest): text, HTML, CSV, PDF (hand-written writer: Flate, image-only, RC4 password), DOCX, XLSX, PPTX, ODT, ODS, ZIP and nested ZIP (yazl 3.3.1); the false-positive and not-extracted sets.                                                                                                    |

## Usage (worker side)

```ts
import { ExtractionSession } from '@email-gateway/dlp/extract'; // extractor child
// child: const session = new ExtractionSession({ declaredContentType, filenameExt }, limits);
//        const result = await inspectBytes(bytes, inspectLimits, NOOP_YARA_ENGINE, { onEntry: session.visitor });
//        return session.finish(bytes, result.detectedType, walkSummaryOf(result));

import {
  classifyDetection,
  composeCoverage,
  detect,
  evaluateDlpPolicy,
  policyFindings,
} from '@email-gateway/dlp';
const detection = await detect({
  segments,
  settings,
  aadhaarEnabled,
  dictionaries,
  customPatterns,
  now,
  deadline,
});
const classification = classifyDetection(detection);
const decision = evaluateDlpPolicy({
  ...snapshot,
  findings: policyFindings(classification.findings),
});
```

`pnpm --filter @email-gateway/dlp test` runs every unit suite (validators, detectors, context,
dictionaries, custom-pattern safety, policy incl. the 10 000-case permutation property test,
masking, evidence and its encryption, extraction, the extractor import graph and the whole corpus
through `detect()`); `test:integration` has no infrastructure suite.
