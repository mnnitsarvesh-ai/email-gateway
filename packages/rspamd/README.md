# @email-gateway/rspamd

Transport and normalization of Rspamd's own protocol (step 4.1 S9, [design](../../docs/plan/steps/09-rspamd.md), [deployment](../../docs/deployment/rspamd.md)). Used by the email-worker's scan role (`/checkv2`, version) and the api's platform training route (Bayes, fuzzy). It decides **no** platform verdict: the S7 mapping lives in the email-worker. Dependencies: `zod` only (Node's global `fetch`).

## API

- `new RspamdClient({ baseUrl, controllerUrl?, controllerPassword?, controllerEnablePassword?, timeoutMs, maxInFlight? = 8, maxReplyBytes? = 4 MiB })`
  - `check({ body, sizeBytes, envelope, logTag, settingsId? }, signal?)` → `{ reply, serverVersion, rcptTruncated, omittedHeaders, durationMs }`: `POST /checkv2`; a `Readable` body is **streamed** (`duplex: 'half'`, `Content-Length = sizeBytes`), bytes are sent as is. The `soft reject` action throws `RspamdSoftRejectError`. `serverVersion` comes from the `Server: rspamd/<version>` reply header (Rspamd 3.12 sends it).
  - `learn('spam' | 'ham', body, sizeBytes, signal?)` → `'learned' | 'already_learned'` (controller `/learnspam` / `/learnham`, enable password; 208 and 204 are `already_learned`).
  - `fuzzy('add' | 'delete', flag, weight, body, sizeBytes, signal?)` → `{ result: 'added' | 'deleted', hashes }` (controller `/fuzzyadd` / `/fuzzydel`, `Flag`, `Weight` on add; flags 11 `EG_FUZZY_SPAM`, 12 `EG_FUZZY_PHISH`).
  - `version(signal?)` → controller `GET /stat` (read password).
  - Every call is bounded by `timeoutMs` (including the wait for an in-flight slot) and by the `InFlightLimiter` (`maxInFlight`).
- `buildRequestHeaders(envelope, { logTag, settingsId? })`: `IP`, `Helo`, `Hostname`, `From` (`<>` for the null sender), at most 100 `Rcpt` (`RSPAMD_MAX_RCPT_HEADERS`; `rcptTruncated`), `Queue-Id`, `User: org-<id>` for outbound/internal only, `Settings-Id` (`eg_inbound` / `eg_outbound`), `Log-Tag`. Unsafe optional values (CR/LF, control characters, too long) are left out and named in `omitted`; an unusable sender, log tag, settings id or organization id throws `RspamdRequestError`. UTF-8 values are sent as UTF-8 bytes.
- `rspamdCheckReplySchema` (permissive for unknown fields) and `normalizeReply(reply, { envelopeFrom?, helo? })` → `{ score, requiredScore, action, skipped, passthroughModule, symbols, symbolsTruncated, auth }`: symbols sorted by |score| then name (≤ 200, ≤ 5 options of ≤ 200 characters, control characters stripped) and SPF/DKIM/DMARC/ARC outcomes from the symbol tables `SPF_SYMBOLS`, `DKIM_SYMBOLS` (+ `DKIM_TRACE` per signature, selectors from `R_DKIM_*` options), `DMARC_SYMBOLS`, `ARC_SYMBOLS`. `auth` has the shape of `AuthResults` in `@email-gateway/security-contracts`. GTUBE (`is_skipped` with `passthrough_module`) is **not** `skipped`; any pre-filter reply carries its `passthroughModule`, and the email-worker's mapping treats one that raised no verdict as `unknown` (`engine.skipped`), never `clean` (close-out CR1).
- Errors (`RspamdError` subclasses, `kind`, `retryable`, `operation`): `RspamdTimeoutError`, `RspamdUnavailableError` (`causeCode`: `ECONNREFUSED`, `UND_ERR_SOCKET`, …), `RspamdHttpError` (`status`), `RspamdProtocolError` (`reason`: `invalid_json`, `schema_mismatch`, `reply_too_large`, `unexpected_reply`; `issuePaths` names only), `RspamdSoftRejectError`, `RspamdRequestError` (not retryable; `field`). No message ever carries a body, a header value, a reply text or a password. An error of the caller's body stream (S3) is rethrown unchanged; a caller abort that is not a timeout rethrows the abort reason.

## Tests

- `pnpm --filter @email-gateway/rspamd test`: unit tests (header builder, reply schema, normalizer with every auth symbol, client against a local HTTP server: streaming and Content-Length, errors, timeouts, refused/reset connections, soft reject, limiter, controller calls).
- `pnpm --filter @email-gateway/rspamd test:integration`: every fixture of `tests/fixtures/scan-corpus` through the real inbound rspamd (required/absent symbols, auth outcomes, score inside the verdict-preserving range), outbound settings, the Rcpt cap, Bayes learning (per-run random vocabularies) and fuzzy add/delete for both flags. Needs `docker compose up -d --wait rspamd`, `docker compose --profile smtp-test up -d dns-sink` and the test values in `.env` (`RSPAMD_DNS_SERVERS=172.31.250.53`, `RSPAMD_RBL_PROFILE=test`, `RSPAMD_BAYES_MIN_LEARNS=10`); the suite fails with these instructions otherwise. Part of the root `pnpm test:integration`.
